2.1 数据可视化流程（Card · Mackinlay · van Wijk）

三套经典模型描述同一件事的三个侧面：一条管道、一套自动决策、一个反馈环。

1 你的原案例

本章从头到尾只用一份数据：中国石油大学（华东）2025 级新生名册 newstudent.csv，含 80 条记录、8 列（序号 / 姓名 / 性别 / 生日 / 年龄 / 班级 / 籍贯 / 民族）。

原站的 2.1 给出的是一张「3 个可视化流程模型」的概念图。本节课我们把它重画成一张可交互的数据流管道图：点击任意一段，就能看到它在三套模型里分别对应什么。

三套模型：同一件事的三个侧面
模型作者 / 年份回答的问题
Card 数据流模型Card, Mackinlay & Shneiderman, 1999「先做什么、后做什么」—— 给出管道的顺序
Mackinlay 自动化准则Mackinlay, 1986「映射这一步怎么自动决策」—— 选哪条通道
van Wijk 反馈模型van Wijk, 2005「视图之后怎么把用户操作喂回去」—— 反馈环
2 嵌入理论

Card 数据流模型（1999）：可视化的「管道」

把可视化拆成四段：原始数据（Raw Data）→ 数据表（Data Tables）→ 视觉结构（Visual Structure）→ 视图（Views）。段与段之间是嵌套变换 D → T → V → C/L/S：数据变换（D→T）、视觉映射（T→V）、视图变换（V→C/L/S，即 Camera / Light / Screen）。

Mackinlay 自动化准则（1986）：映射怎么自动决策

对每一种数据类型，自动挑「量化误差最小」的视觉通道：数值型 → 位置（最准）、有序型 → 长度 / 密度、类别型 → 色调 / 形状。它解决的是管道里「数据表 → 视觉结构」这一步的选型问题。

van Wijk 反馈模型（2005）：把交互画成一个环

经典管道是单向的，van Wijk 强调交互反馈循环：View ⇆ Filter ⇆ Param ⇆ Other Views。用户看图 → 改变筛选 / 参数 → 触发新视图，视图和用户之间是一个闭环，而不是一次性渲染。

核心教学要点：三个模型是叠加关系，不是冲突关系。Card 告诉你「transform 之后该 mapping，mapping 之后该 view」；Mackinlay 告诉你「mapping 这一步怎么自动决策」；van Wijk 告诉你「view 之后还要把用户操作 feed 回去」。

3 ⭐ 关键代码
① SVG 箭头：<marker> + marker-end 
// 1. 在 <defs> 里定义箭头形状，用 id 命名
svg.append("defs").append("marker")
   .attr("id", "arrowhead")
   .attr("viewBox", "0 -5 10 10")
   .attr("refX", 8)            // 箭头位置校准：让尖端贴住节点边缘
   .attr("orient", "auto")      // 跟随线段方向自动旋转
   .append("path").attr("d", "M0,-5L10,0L0,5");

// 2. 用 marker-end="url(#arrowhead)" 把箭头「装」到线段末端
svg.append("line")
   .attr("marker-end", "url(#arrowhead)")
   .attr("x1", x1).attr("y1", y).attr("x2", x2).attr("y2", y);

marker-end="url(#arrowhead)" 是 SVG 的引用机制 —— 用 URL 把 <defs> 里定义的形状复用到线段末端。refX 决定箭尖相对线段终点的偏移，orient="auto" 让箭头自动转向。一条 marker 可以服务所有线，不必为每根箭头各画一个三角。

② classed：一次切换所有节点的状态 
// 单选：把所有节点的 selected 状态一次刷新
svg.selectAll(".node")
   .classed("selected", n => n.id === d.id);   // 接收布尔函数

classed(name, predicate) 接收一个布尔函数，一次性切换全部节点的类名，比自己写 forEach + classList.toggle 简洁得多。它只负责改 class，真正的外观（高亮、描边）交给 CSS —— 这正是 D3 分离「状态」与「样式」的典型做法。

③ 数据驱动的管道：把 stage 数组绑成 SVG 节点 
const STAGES = ["原始数据", "数据表", "视觉结构", "视图"];

svg.selectAll(".stage").data(STAGES).join("g")
   .attr("class", "stage")
   .attr("transform", (d, i) => `translate(${i * 160}, 0)`);

管道的每一段都是「数据 → 图元」的一次绑定。把 STAGES 换成别的数组，整张图随之改变 —— 这就是 D3 的核心思想：document 由 data 驱动。本章后面的树、列表、聚合图，用的都是同一套 join 模式。

本节小结

  • Card 1999 把可视化拆成四段管道：原始数据 → 数据表 → 视觉结构 → 视图，段间是嵌套变换 D→T→V→C/L/S。
  • Mackinlay 1986 负责「映射」这一步的自动决策（数值→位置、类别→色调）；van Wijk 2005 补上「视图 ⇆ 用户」的反馈环。

自测 · 1 题

在 Card 数据流模型里，「给年龄这个属性选出最合适的视觉通道（位置）」属于哪一段箭头？

「把属性映射到通道」正是视觉映射（数据表 → 视觉结构），也正是 Mackinlay 自动化准则发挥作用的那一段。数据变换（D）只管整理表格，视图渲染（V）只管把已定好的图元画到屏幕上。

2.2 数据变换：原数据 → 数据表

把「按班级分」升级成「按维度组合分」—— 这是管道的第一段箭头，也是可视化的「第一公里」。

1 你的原案例

接上节的管道，本节的 2.2 处理的正是第一段箭头「原始数据 → 数据表」，也就是 数据变换（Data Transformation）。

原案例用新生数据按「班级 / 专业」做 rollup 分桶聚合，核心是 d3.rollup 的链式调用 —— 一个函数完成多维度分组。本节课把它做成一段可单步的折叠动画：80 条明细 → 按班级分组计数 → 再按性别嵌套聚合。

2 嵌入理论

数据变换的四大操作（Card 1999 · D 层）

从「原始数据」到「数据表」，D 层做四类操作。原文 2.2 只讲了「分桶聚合」，这里把它放进完整的框架里 —— 你会看到聚合只是其中一行。

操作做什么D3 实现
清洗 / 过滤去缺失、去异常，筛选满足条件的行.filter()、d3.csv(url, row) 回调
聚合 / 汇总按 key 分组，把同组归约为一个值d3.rollup()、d3.group()
连接 / 关联按键把两张表拼起来（学生表 join 班级表）d3.map + 手动索引
派生 / 衍生由已有列算出新列（从「班级」切出「专业」）row 回调里算一个新字段

本节演示的 rollup 聚合，属于「聚合」这一行。读懂这张表，你才知道数据变换是整个流水线的「第一公里」—— 数据表没整理好，后面的映射与渲染全都白搭。

d3.rollup = 「按 key 分桶、再 reduce 一次」的函数式组合

d3.rollup(data, reducer, ...keys) 返回的是 Map（不是数组、也不是普通对象），所以遍历要用 for ([k, v] of m) 或 m.entries()；嵌套 rollup 得到的是嵌套 Map。
与 d3.group 的区别一句话：rollup 把组内数据归约成一个值，group 保留原数组。

OLAP 切片 / 切块 / 钻取（Codd 1993）

OLAP 操作实际对应
切片 Slice固定一个维度（只看 2025 级）→ .filter() 后再 rollup
切块 Dice按两个维度分组 → 双 key rollup
钻取 Drill层层下钻 → 嵌套 rollup + 递归展开

可视化系统的「下钻交互」，背后通常就是 rollup + hierarchy 的组合。

3 ⭐ 关键代码
① 双层 rollup：返回嵌套 Map 
// 外层 key = 班级，内层 key = 性别，reducer = 计数
const nested = d3.rollup(
  students,
  v => v.length,          // 把同组归约为一个值（数人数）
  d => d.class,           // 外层 key
  d => d.gender           // 内层 key（rest 参数，可继续加）
);

// 遍历嵌套 Map：
for (const [cls, inner] of nested) {
  for (const [gender, count] of inner) {
    console.log(cls, gender, count);   // 软件工程1班 男 12
  }
}

d3.rollup 的 key 参数是rest 参数（...keys）：传 1 个 → 单层 Map，传 2 个 → 嵌套 Map，传 3 个 → 三层嵌套。返回的是 Map，所以遍历用 for...of 或 .entries()，不是 Object.keys。

② 用正则从「班级」切出「专业」 
const data = await d3.csv("./data/newstudent.csv", d => {
  const cls = d["班级"].trim();
  const m = cls.match(/^(.+?)(\d+班)$/);  // 中间非贪婪 + 末尾「数字+班」
  return {
    id:     +d["序号"],
    name:   d["姓名"].trim(),
    class:  cls,
    gender: d["性别"].trim(),
    major:  m ? m[1] : cls,   // "软件工程1班" → "软件工程"
  };
});

正则里 .+? 是非贪婪匹配：让中间尽可能短，把 \d+班 留给末尾。若写成贪婪的 .+，它会把整串都匹配走，m[1] 就是 undefined。这类正则坑学生常踩，必须掌握。

③ group 与 rollup 的一句话区别 
// group：分组「保留」——每个 key 下是完整的元素数组
const byClass = d3.group(students, d => d.class);

// rollup：分组「聚合」——每个 key 下只有一个归约值
const countByClass = d3.rollup(students, v => v.length, d => d.class);

一句话记住：group 是分组保留，rollup 是分组聚合。如果「人数」和「名单」都要（后面还要下钻），用 group；只要汇总数字，用 rollup 更紧凑。本节演示的折叠动画，两级都用 rollup。

点「下一步」看 80 条明细如何逐层折叠成嵌套 Map；也可以「上一步」回退或「重放」。左侧会同步打印 d3.rollup 的输出。

本节小结

  • 数据变换是管道的「第一公里」，含清洗 / 聚合 / 连接 / 派生四类操作，rollup 只是其中的「聚合」。
  • d3.rollup(data, reducer, ...keys) 返回 Map（嵌套则返回嵌套 Map），keys 是 rest 参数 —— 加一层 key 就多一级分组。
  • group 保留每组原数组，rollup 只留聚合值；正则 /^(.+?)(\d+班)$/ 里的 .+? 非贪婪是切出「专业」的关键。
自测 · 第 1 题

执行 d3.rollup(students, v => v.length, d => d.class)，返回值是什么？

rollup 返回 Map；因为给了 reducer v => v.length，每组只保留一个聚合值（人数），所以不是保留原数组（那才是 group 的行为）。

自测 · 第 2 题

正则 /^(.+?)(\d+班)$/ 里的 .+? 若改成贪婪的 .+，对 "数据科学2班" 会怎样？

贪婪的 .+ 会先尽量「吃」掉尽可能多的字符，导致留给 \d+班 的部分几乎为空，第 1 个捕获组拿不到「专业」。非贪婪 .+? 让它尽量少吃，把「数字+班」留给后面 —— 这才是正确切分的关键。

2.3 视觉映射：数据表 → 视觉结构

拿到层级数据后，怎么把节点摆到屏幕上不打架？—— Reingold–Tilford 算法，本质是一次「位置通道」的视觉映射。

1 你的原案例

接上节，我们有了「数据表」。本节的 2.3 是第二段箭头「数据表 → 视觉结构」，也就是 视觉映射（Visual Mapping）。它回答一个核心问题：数据里每个属性，该用哪个视觉通道来表达？

原案例提到「树形结构可视化」。本节课展开树布局算法原理 —— 用「班级 / 性别」分组得到一棵层级树，然后把它稳稳地摆到屏幕上。

2 嵌入理论

视觉通道与 Mackinlay 排名（1986）

视觉通道是「把数据编码到视觉元素上」的载体：位置、长度、面积、角度、颜色、形状、纹理……Mackinlay 1986 给出经典排名：对不同数据类型，各通道的量化精确度不一样。

数据类型通道精确度排序（高 → 低）
定量 Quantitative位置 → 长度 → 角度 → 斜率 → 面积
有序 Ordinal位置 → 密度 → 饱和度 → 亮度 → 体积
名义 Nominal位置 → 色调 → 纹理 → 连接 → 形状

位置（Position）永远第一 —— 三种数据类型都最准，人眼对位置最敏感。

两类通道：幅度 vs 标识

按「能不能表达量的多少」，通道分两类：幅度通道（Magnitude）表达有序 / 定量属性（共用尺度位置最准，长度 / 倾斜 / 面积次之，亮度 / 饱和度 / 体积最弱）；标识通道（Identity）表达类别属性（空间区域、色调、运动、形状 —— 能区分「不同类」，但分不出「谁多谁少」）。选错类别 = 误导读者。

Reingold–Tilford 算法：树布局的核心（1981）

至今仍是 d3.tree() 的实现核心，核心思路分三遍遍历：

  1. 第一遍（自底向上）：对每个父节点，计算其左右子树「占用多少横向空间」。
  2. 第二遍（自顶向下）：给每个节点分配绝对 x 坐标（保证兄弟节点紧贴父节点中线且不重叠）。
  3. 第三遍：处理「线程 (threads)」—— 修复子节点跨父中线时的对齐。

复杂度 O(n)。整个算法做的就是「用位置通道把层级关系编码成父上子下的树」—— 所以树布局本质上就是一次视觉映射。

d3-hierarchy 模块全家桶

API用途
hierarchy(data)把嵌套 data 转成 hierarchy（补 parent / children / depth）
tree().size([h, w])Reingold–Tilford 算法，左右布局（本节的演示用的就是它）
cluster().size([h, w])所有叶子对齐到同一深度
treemap().tile(...)面积布局（slice-and-dice / squarified）
pack().radius(...) / partition()圆环打包 / icicle·sunburst 布局
3 ⭐ 关键代码
① hierarchy + tree：树布局三步走 
// 1. hierarchy：嵌套数据 → 补上 parent / children / depth
const root = d3.hierarchy(rootData);

// 2. tree 布局（Reingold–Tilford）：算 x / y 坐标
const treeData = d3.tree().size([360, 720])(root);

// 3. links：父—子连线；注意 x=d.y、y=d.x 的「交换」
g.selectAll(".link").data(treeData.links()).join("path")
  .attr("d", d3.linkHorizontal().x(d => d.y).y(d => d.x));

// 4. nodes：每个节点 translate 到 (y, x)
const ng = g.selectAll(".node").data(treeData.descendants()).join("g")
  .attr("transform", d => `translate(${d.y}, ${d.x})`);

treeData.x 是深度方向（垂直），treeData.y 是水平方向（同层不同节点）。所以横向树里 linkHorizontal 必须写 x = d.y, y = d.x 这样交换，直接把 d.x 当横坐标会把连线连错。这种「x 轴走 y、y 轴走 x」的 swap 是横向树特有的。

② separation：控制兄弟节点间距 
const treeLayout = d3.tree()
  .size([360, 720])
  .separation((a, b) => (a.parent === b.parent ? 1 : 2));
//                              ↑ 兄弟紧贴        ↑ 不同父至少隔 2 倍

separation 接收一个函数，返回两个节点之间的「间隔倍数」。默认兄弟 1、非兄弟 2；调小到 0.5 全部挤在一起，调大到 2.0 树变宽。本质上就是给「位置通道」再加一条约束 —— 兄弟之间要留够间距。

③ 从 rollup 的 Map 搭出 hierarchy 树 
// 把嵌套 Map 递归转成 { name, children } 的普通对象树
function toTree(node, label) {
  if (node instanceof Map) {
    const children = [];
    for (const [k, v] of node) children.push(toTree(v, k));
    return { name: label, children };
  }
  return { name: `${label} (${node.length})` };   // 叶子
}

const root = d3.hierarchy(toTree(nested, "2025 级新生"));

上节的 rollup 产出嵌套 Map，本节的 hierarchy 要的是 { name, children }。中间这一步「递归转换」是把数据变换接到视觉映射的桥 —— 这一步做完，树的形状就定死了，剩下的只是把位置算出来。

4 可运行演示

点「下一步」逐步求解：先看未布局时节点全部重叠，再走 Reingold–Tilford 的三遍 —— 自底向上量宽度 → 自顶向下定坐标 → 对齐收尾。

本节小结

  • 视觉映射 = 给每个数据属性挑通道；Mackinlay 1986 排名里「位置」对三种数据类型都最准，所以树布局优先用位置。
  • 通道分两类：幅度通道（有序/定量，如位置、长度）与标识通道（类别，如色调、形状），选错类别就会误导读者。
  • Reingold–Tilford 三遍遍历（自底向上量宽度 → 自顶向下定 x → 处理 threads）复杂度 O(n)，是 d3.tree() 的核心。
自测 · 第 1 题

横向树（d3.tree().size([360, 720])）里，linkHorizontal().x(d => d.y).y(d => d.x) 为什么要交换 x、y？

d3.tree 输出的 x 是深度方向（默认垂直）、y 是水平方向（同一深度的不同节点）。要做成横向树，就得把水平方向交给 x、深度方向交给 y —— 所以 linkHorizontal 里写成 x = d.y, y = d.x。不做这个交换，连线会把父子连到错误的方向上。

自测 · 第 2 题

把「专业」（软件工程 / 数据科学，无顺序）映射到色相、把「年龄」映射到位置，这两种做法分别用到了哪类通道？

专业是类别属性 → 用标识通道（色相）区分「不同类」；年龄是定量属性 → 用幅度通道（位置）表达「多与少」。两者都挑对了：如果反过来把年龄塞进色相，读者就无法判断谁大谁小。

2.4 视图渲染与用户交互

把树画成可折叠的 HTML 列表 —— 一路踩过点击、冒泡、委托三个坑，最后用动画补上「时间维」。

1 你的原案例

接上节，我们有了「视觉结构」。本节 2.4 是最后两段箭头：「视觉结构 → 视图」（渲染）和「视图 ↔ 用户」（交互反馈）。Card 模型的 V 层，加上 van Wijk 的反馈环，都落在这里。

原文档用了 classed 控制节点样式、用 stopPropagation 阻止冒泡，重点是把 D3 树布局的输出变成可交互的 HTML 列表。本节课把「事件冒泡」做成一段可点、可看的示踪动画。

2 嵌入理论

DOM 事件三阶段

浏览器的事件流分三阶段（DOM 规范）：

  1. 捕获（capturing）：window → document → … → 目标元素（从外到内）
  2. 目标（target）：目标元素本身
  3. 冒泡（bubbling）：目标元素 → … → document → window（从内到外）

默认监听的是冒泡阶段。你可以在监听器里 e.stopPropagation() 截断冒泡，让上层的监听器不再触发。

事件委托（Event Delegation）

问题：列表里有 1000 个 li，给每个 li 都绑 click 监听器 → 慢、内存大、新增元素还要重新绑。
解法：只给父元素（ul）绑 1 个 click 监听器，靠冒泡统一收口；用 e.target.closest('.label') 找到「实际被点的子元素」。
优势：1 个监听器代替 N 个，未来新增的元素自动支持。

动画：视图渲染的「时间维」

动画（transition）不是「花哨」，而是视图渲染在时间维上的展开。D3 用 .transition().duration(ms) 让属性从旧值平滑过渡到新值。教学价值集中在 duration 这一个参数：

  • duration = 0：瞬间跳变，看不出「变化过程」；
  • duration = 500：0.5 秒过渡，能看清展开 / 收缩 / 位移的流畅过程；
  • duration > 1500：太慢，学生开始走神。
3 ⭐ 关键代码
① 事件委托：父级绑一次，子级全受益 
// 只在父级 ul 上绑一次 click（事件委托）
ul.addEventListener("click", (e) => {
  const li = e.target.closest("li");   // 找到「实际被点的行」
  if (!li || !ul.contains(li)) return;
  pick(li);                            // 统一处理选中
});

1000 个 li 各绑 1 个监听器 → 慢且费内存；改成父级绑 1 次，靠冒泡统一收口。e.target.closest("li") 负责从「真正被点的元素」回溯到「我们关心的行」，即使点击落在行内的图标或文字上也能正确命中。

② toggle 与 select 的冲突：stopPropagation 
// 折叠箭头：阻止冒泡，别触发父级的「选中」
label.addEventListener("click", (e) => {
  e.stopPropagation();       // ⭐ 截断冒泡
  node._collapsed = !node._collapsed;
  render();
});

// 行选中：只会被「非 toggle」的点击触发
li.addEventListener("click", () => pick(li));

不 stopPropagation 的话，点折叠箭头会同时触发「切换折叠」和「选中节点」，用户看着会困惑。这是 DOM 事件机制的核心教学点：一个点击，两个监听器，用截断冒泡来分工。

③ transition + duration：给渲染补上时间维 
svg.selectAll(".node")
  .transition()                          // 进入过渡状态
  .duration(DURATION)                  // 时长（ms），由滑块控制
  .attr("transform", d => `translate(${d.y}, ${d.x})`)
  .attr("opacity", 1);

// 新节点：先设 opacity=0，再过渡到 1 → 淡入效果
ng.attr("opacity", 0)
  .transition().duration(DURATION).attr("opacity", 1);

duration = 0 是瞬间跳变、看不出过程；500 能看清展开 / 收缩；超过 1500 就太慢会走神。动画把「视图渲染」从一帧变成一段时间里的连续过程，也是 van Wijk 反馈环最直观的体现。

4 可运行演示

点最里层的子元素，看事件如何沿 DOM 树向上冒泡到父级监听器；勾上「在 li 层截断冒泡」再点一次，对比路径的差别。右侧还有「逐个绑定 vs 事件委托」的监听器数量对比。

本节小结

  • DOM 事件三阶段：捕获（自外向内）→ 目标 → 冒泡（自内向外）；默认监听的是冒泡阶段。
  • 事件委托 = 父级绑 1 个监听器 + e.target.closest() 定位子元素，用 1 个监听器代替 N 个，新增元素自动生效。
  • toggle 与 select 分工靠 stopPropagation() 截断冒泡；动画的 duration 则是视图渲染的「时间维」。
自测 · 1 题

一个列表有 1000 个 li，且会不断新增。用事件委托相比「给每个 li 各绑一个 click」，最本质的好处是？

事件委托把监听器数量从 N 降到 1，并且新插入的 li 会沿着冒泡自然触发父级监听器，无需逐个重新绑定。它并不自动阻止冒泡，判断「点了哪一行」仍然要靠 e.target.closest("li")。
