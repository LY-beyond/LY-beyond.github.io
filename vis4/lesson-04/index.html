4.1 数据转换

宽格式给人看，长格式给程序用 —— 一次 flatMap 完成转换。

1 原案例

本章从头到尾只用一份数据：1985 年美国 50 州犯罪统计 crime.csv。它含 50 行 × 12 列，每行一个州、每列一个指标 —— 这是典型的宽格式。

crime.csv 字段清单：1 列标识 + 1 列人口 + 10 列犯罪指标
列名含义类型
state州名（唯一标识）String
population1985 年人口Number（53 万 ~ 2700 万，跨 50 倍）
population_growth人口增长率（%）Number（有正有负）
robbery / aggravated_assault抢劫 / 加重伤害Number（案件数）
burglary / larceny_theft / motor_vehicle_theft入室盗窃 / 普通盗窃 / 车辆盗窃Number（案件数）
murder / arson / rape1 / rape2谋杀 / 纵火 / 强奸两版口径Number（案件数）
2 嵌入理论

宽格式（wide）与长格式（long）

宽格式：一行一个实体（州），列是指标（murder、robbery…）。人眼读得懂、一目了然，但「哪个指标」这个信息藏在列名里，程序拿不到。

长格式：一行一个观测，列固定为 {state, metric, value}。「指标」被降级成一列数据，于是 filter / group / data-join 都能直接按它切分。

转换：对每个州，遍历要保留的指标列表，把 (州, 指标, 值) 三元组展开 —— 也就是 flatMap。这一步是 ES2019 的语法，等价于 map() 再 flat()。

怎么选：给人看、给人填的表格用宽格式；给程序算、给 D3 绑的中间数据用长格式。同一份数据在流水线里往往「一进一出各一种格式」，转换点就在 flatMap 这一行。

3 ⭐ 关键代码
① d3.autoType：加载即完成类型推断 
// 第二参直接传 d3.autoType，省掉逐列 +d.field
const raw = await d3.csv('./data/crime.csv', d3.autoType);

// 验证类型确实转换了：
console.log(raw[0].population);        // 3979000（Number，不是 "3979000"）
console.log(typeof raw[0].state);      // "string"

autoType 内部就是遍历每一列，试探 Number() / Date() / 布尔字面量：能识别的就转，识别不了的保持字符串。所以它很省事、但也很保守 —— 像 "1,234" 这种带千分位的数字它不会自动转，仍要自己清洗。

② flatMap：宽格式 → 长格式的一行写法 
// 宽格式：一行一个州，列 = 指标
// 长格式：一行一个观测 {state, metric, value}
const METRICS = ['murder', 'robbery', 'burglary'];

const long = raw.flatMap(d =>
  METRICS.map(metric => ({
    state: d.state,
    metric,
    value: d[metric],
  }))
);
// 50 行 × 3 个指标 = 150 行
const byMetric = d3.group(long, d => d.metric);   // 分组、过滤、join 都顺了

flatMap = 「map 之后把结果压低一层」。写成 map(...).flat() 结果一样，但 flatMap 语义更清楚，也不会出现中间那份嵌套数组。注意：行数会从 50 涨到 150 —— 长格式是用行数换可操作性。

③ 平行坐标前的逐轴归一化 
// 平行坐标：每根轴各自 min-max，映射到 [0, 1]
const norm = (values) => {
  const lo = Math.min(...values), hi = Math.max(...values);
  const span = hi - lo || 1;          // 全部相等时避免除以 0
  return (v) => (v - lo) / span;
};
const yOfMurder = norm(raw.map(d => d.murder));

平行坐标最大的陷阱：每根轴的刻度不一样。归一化后跨轴比较的是「相对位置」，不是绝对数值 —— 所以只能说「这个州在谋杀轴上偏上、在盗窃轴上偏下」，不能说「谋杀 350 = 盗窃 350」。散点矩阵没有这个问题：两两对比时两轴都是真实刻度。

4 可运行演示

演示 A · 宽 → 长：运行时真实加载 crime.csv，勾选要保留的指标，看 flatMap 如何把「50 行 × 12 列」展开成「150 行 × 3 列」—— 原表中高亮的列正是被展开成一行行观测的来源。

演示 B · 多变量投影：先用平行坐标看 50 个州在 5 个指标上的「轮廓」，再用散点矩阵做两两对比。选一根轴、拖两个滑块刷选（brush）—— 被选中的州会在两个图里同步高亮，这就是联动刷选。

本节小结

  • 宽格式一行一个实体（人眼友好），长格式一行一个观测（程序友好）；flatMap 一行完成宽 → 长。
  • d3.autoType 加载时就逐列推断类型，但它只做「能猜出来的」转换，脏数据仍要自己清洗。
  • 平行坐标必须逐轴归一化（跨轴只读相对位置）；散点矩阵用真实刻度做两两对比 —— 这就是多变量投影的两条不同策略。
自测 · 第 1 题

crime.csv 里「一行一个州、每列一个犯罪指标」，这种布局属于？

宽格式 = 一行一个实体（州），列是指标（murder、robbery…）。改成一行一个 (州, 指标, 值) 的三元组，才是长格式 —— 那是给 filter / group / data-join 用的形状。

自测 · 第 2 题

把 50 行宽格式的 crime.csv，用 ['murder', 'robbery', 'burglary'] 三个指标 flatMap 成长格式，会得到多少行？

每个州被展开成 3 行观测：50 × 3 = 150 行。长格式是用行数换可操作性 —— 数据变大，但 filter / group / 绑定 join 都变简单了。

4.2 坐标轴变换

数据空间 → 归一化空间 → 屏幕像素空间，三层职责分明，错了就乱套。

1 原案例

原 5.1.2 节用散点图展示 crime.csv 的 谋杀（murder）vs 抢劫（robbery）。麻烦在于：谋杀数从 32（Vermont）到 3082（California），抢劫数从 489（Wyoming）到 254707（California）—— 如果直接把原始数值当像素用，画布根本装不下。

层坐标含义本例数值谁负责
① 数据空间原始数值（真实单位）murder = 3082数据本身
② 归一化空间压缩到 0..innerW 的标准化坐标x' = 0.98scaleLinear / scaleLog / scaleSqrt
③ 屏幕像素空间加上 margin 偏移后的最终像素位置X = 48 + 0.98×560 ≈ 597 px第二层 scale 或 d3.axisBottom
2 嵌入理论

为什么必须分三层

把「值 → 坐标」和「坐标 → 像素」拆开，好处是解耦：归一化结果只和数据有关，屏幕像素只和画布尺寸有关。于是换一个画布大小（响应式布局、导出不同尺寸的图）只需要重算第三层，第一层的归一化结果原地复用。

如果偷懒写成「一个 scale 同时管 domain=数据、range=[margin, margin+innerW]」，那么每次改 margin 都要回到数据层改一遍 —— 而且元素之间共享的坐标（比如一条参考线的位置）就没法复用了。

常见错位：把「数据域 → 像素域」写进同一个 scale（domain=[0, maxMurder]、range=[margin, margin+innerW]）。当时看不出问题，直到需要改 margin、做响应式或叠加一条共享参考线 —— 才发现每个 scale 都得改两处。

3 ⭐ 关键代码
① 两层 scale：数据 → 归一化 → 像素 
const M = { t: 20, r: 20, b: 36, l: 48 };   // 边距
const innerW = W - M.l - M.r, innerH = H - M.t - M.b;

// 第一层：数据空间 → 归一化空间（只跟数据有关）
const xData = d3.scaleLinear().domain([0, maxMurder]).range([0, innerW]);

// 第二层：归一化空间 → 屏幕像素空间（只跟画布有关）
const xScreen = d3.scaleLinear().domain([0, innerW]).range([M.l, M.l + innerW]);

// 渲染时层层套用：数据 → 归一化 → 像素
.attr('cx', d => xScreen(xData(d.murder)))

domain() 是输入、range() 是输出。两层分开后，xData 可以被多张图共享（同一份数据的迷你图们），xScreen 只在渲染时用一次。口诀：里层管数据，外层管画布。

② 第一层里选哪个 scale：linear / log / sqrt 
// 均匀分布：最常用，直接线性映射
const xLin  = d3.scaleLinear().domain([0, maxMurder]).range([0, innerW]);

// 跨数量级（人口 53 万 ~ 2700 万）：log 让等比变成等距
const xLog  = d3.scaleLog().domain([1, maxMurder]).range([0, innerW]);

// 面积感知：半径平方映射到值（气泡图的正确做法）
const xSqrt = d3.scaleSqrt().domain([0, maxMurder]).range([0, innerW]);
// 类别轴用 scaleBand（柱状图），别拿 scaleLinear 去排类别

换 scale 只改第一层，第二层完全不动 —— 这正是分层的价值。数据的分布决定了第一层用哪个 scale：线性分布用 linear、跨数量级用 log、映射到面积（而非长度）用 sqrt。

4 可运行演示

点「下一步」逐层推进，看同一组州在每一层的坐标怎么变；上方切 linear / log / sqrt 会同时改变第 ② 层的归一化，右侧表格给出每个点的三套坐标与当前公式。

本节小结

  • 三层职责：数据空间（真实值）→ 归一化空间（0..innerW）→ 屏幕像素空间（加 margin），层与层之间的桥梁是 scale。
  • 分层带来解耦：归一化结果与画布尺寸无关，改尺寸只重算最外层，共享元素（参考线、网格）不用重算。
  • 第一层选 scale 由数据分布决定：linear 均匀、log 跨数量级、sqrt 用于面积、band 用于类别。
自测 · 1 题

把「数据空间 → 归一化空间 → 屏幕像素空间」拆成两层 scale，最主要的好处是？

第二层只依赖画布尺寸，第一层只依赖数据。改画布时第一层的归一化结果原样复用 —— 而且共享元素（网格线、参考线、其他迷你图）都能复用同一套坐标。d3 也不强制要求两层。

4.3 曲线拟合

同一组散点，换一种模型就是另一条趋势线 —— 靠什么判断哪种更贴合？

1 原案例

原 5.1.3 节用「折线 + 散点」展示 50 个州的趋势，代码里写的是 curveCatmullRom，但没讲为什么 —— 结果就是曲线过拟合地把每个州的抖动都画了出来。

2 嵌入理论

插值（interpolation）vs 拟合（fitting）

插值：曲线经过每一个数据点（Catmull-Rom、Natural、monotoneX）。保住了全部信息，但也把噪声一起画了进去。

拟合：曲线不要求经过数据点，只反映趋势（线性回归、幂函数、LOESS）。它主动「丢掉」点对点的细节，换来看清整体走向。

怎么选：点数少（< 10）→ 插值，信息本来就不多，别浪费；点数多（> 30）→ 拟合，抖动多半是噪声；数据本身有顺序且要保单调 → monotoneX（不会出现伪震荡）。

别忘了 colormap。本节演示的散点用色也遵循第 3 章的规则：同一类别用同一色相，不用彩虹色阶 —— 颜色只区分「是否被选中」，不编码数值。

3 ⭐ 关键代码
① d3.line().curve()：换一行就换风格 
const line = d3.line()
  .x(d => x(d.population))
  .y(d => y(d.murder))
  .curve(d3.curveMonotoneX);   // ← 只改这一行，换曲线风格

svg.append('path')
  .datum(data)                 // 整个数组当一份数据交给 path
  .attr('d', line)
  .attr('fill', 'none');

datum() 是把数组整体绑给一个元素（不是逐元素绑）。常用 curve：linear 直连、monotoneX 保单调、catmullRom 平滑过点、step 阶梯。判断口诀：有序数据用 monotoneX、抖动大用平滑样条、离散状态用 step。

② 最小二乘拟合：把幂函数变成直线来解 
// 幂函数 y = a · x^b → 两边取对数变成直线：ln y = ln a + b · ln x
const pts = data.filter(d => d.population > 0 && d.murder > 0);
const lx = pts.map(d => Math.log(d.population));
const ly = pts.map(d => Math.log(d.murder));

const { slope, intercept } = ols(lx, ly);   // 一元线性回归
const a = Math.exp(intercept), b = slope;   // 幂函数的两参数

「线性化」是拟合的万能钥匙：指数、幂、反比、平方根都能通过换元变成直线，然后调用同一个 ols()。注意：在线性化空间里最小化误差，不等于在原始空间里最小化误差 —— 所以取完对数再算的 R² 要回到原空间评估。

③ R²：贴合程度的统一标尺 
// R² = 1 − SSres / SStot：越接近 1 越贴合
const mean  = ys.reduce((s, v) => s + v, 0) / ys.length;
const ssTot = ys.reduce((s, v) => s + (v - mean) ** 2, 0);
const ssRes = ys.reduce((s, v, i) => s + (v - fit[i]) ** 2, 0);
const r2 = 1 - ssRes / ssTot;   // 可以为负：比「直接用平均值」还差

R² 不是越高越好。它衡量的是「相对均值基线的改进」：直线对 50 个州能到 0.6 就很不错了，而三次多项式总能再挤出 0.02 —— 那 0.02 往往只是把噪声拟合了一遍。比较 R² 时，参数量要一并看。

4 可运行演示

下方点按钮切换 10 种拟合模型：同一组成对的散点（人口 → 谋杀数）不动，曲线、拟合方程与 R² 同步更新；右侧排序条按 R² 从高到低排，一眼看出谁最贴合。

本节小结

  • 插值过所有点（保信息、也保噪声），拟合只反映趋势（丢细节、看得清）；点数多少是主要判断依据。
  • d3.line().curve() 换一行就换风格：有序数据选 monotoneX，抖动大选平滑样条，离散状态选 step。
  • 拟合靠「线性化」统一成最小二乘；用 R² 比较贴合度时，必须同时看模型复杂度，否则会挑上过拟合的那个。
自测 · 第 1 题

只有 8 个数据点的折线图，要保持原序列单调、不出现伪震荡，应该选哪种 curve？

Catmull-Rom 这类张力样条在点间可能「甩」出一个并不存在的鼓包（伪震荡）。monotoneX 约束了每段的三次项，保证「数据上升就不下弯」，是时间序列与有序数据最稳的默认选择。

自测 · 第 2 题

关于拟合优度 R²，下面哪种说法是正确的？

R² = 1 − SSres/SStot，基线是「全部用平均值预测」。它可以为负（比均值还差，说明模型完全不合适）；它只对同一份数据可比，跨数据集没有意义；而复杂度越高越容易虚高 —— 所以要看参数量（或调整后 R²）。

4.4 倾角感知（45° 黄金角）

人眼对斜率的估计不是线性的 —— 45° 是视觉上的「中点」。

1 原案例

原 5.1.4 节提到「平均倾斜度最优为 45°」，但没有解释原因。而对 crime.csv 这种跨 50 倍的数据，画在线性轴上时，多数州挤成一团、趋势线的倾角接近水平（< 20°），读者几乎读不出斜率。

2 嵌入理论

Cleveland 1984 的斜率估计实验

让被试估计直线的斜率，并报告感知值与真实值的偏差，结果是一条 U 型曲线：

  • 斜率接近 0° 或 90° 时，估计误差最大（几乎没法判断「这点差别算不算更陡」）。
  • 斜率接近 45° 时，估计最准 —— 这就是「黄金角」。

Stevens 幂律给出了原因：感知斜率 ≈ 真实斜率1.0~1.3，即人眼把「陡度」整体夸张了约 30%。只有在 45° 附近，「被夸张」与「被压缩」误差互相抵消，感知与真实最接近。

设计原则：① 关键数据的斜率落在 30°–60°；② 对比增长曲线时，用 log 轴把陡度拉回 45° 左右；③ 避免在 5° 以下或 85° 以上做趋势对比 —— 那里的感知误差足以让人得出错误结论。

3 ⭐ 关键代码
① 角度 → 屏幕坐标（注意 SVG 的 y 轴朝下） 
// SVG 的 y 轴向下（与数学坐标相反），所以 sin 项要取负
function lineAt(deg, len = 240, o = { x: 100, y: 240 }) {
  const r = deg * Math.PI / 180;
  return {
    x1: o.x, y1: o.y,
    x2: o.x + len * Math.cos(r),
    y2: o.y - len * Math.sin(r),
  };
}

这是画角度图形的第一个坑：SVG 原点在左上角、y 向下增长，所以 sin 项要取负，否则 30° 会画成「向右下 30°」。第二个坑：角度必须换算成弧度再喂给 Math.cos / Math.sin。

② U 型误差模型 + 滑块驱动 
// Cleveland 的 U 型误差：|ln(tan θ)| 在 45° 取 0，向两端发散
const err = (deg) => {
  if (deg <= 0 || deg >= 90) return 1;
  const r = deg * Math.PI / 180;
  return 1 - Math.exp(-Math.abs(Math.log(Math.tan(r))));
};

slider.addEventListener('input', e => draw(+e.target.value));

把抽象理论变成可调参数，学生才能「感觉到」它：拖动滑块时同时更新「直线倾角」与「误差曲线上的游标」，两条信息一对应，U 型的含义就立住了。

③ 用 log 轴把趋势斜率拉回 45° 
// 指数增长在线性轴上是「前缓后陡」：斜率 5° → 85°，两端都失真
// 换 log 轴：等比增长变成等距，整条趋势的倾角落回 45° 附近
const xLog = d3.scaleLog()
  .domain(d3.extent(data, d => d.population))   // [53 万, 2700 万]
  .range([0, innerW]);

// 检验：把散点回归到「归一化后的平方画布」上，量一下角度是否进了 30°–60°
const angle = Math.atan(ols(normX, normY).slope) * 180 / Math.PI;

这就是 4.2 的 scale 选型与本节的设计原则接上的地方：换第一层的 scale，就能改变屏幕上那条趋势线的倾角。下面演示里切线性 / log，可以看到同一个回归系数算出的角度从 < 20° 跳进黄金区间。

④ 原创 · 夸大倍数：把谎言算成一个数（图表谎言放大镜） 
// y 轴起点滑块：f ∈ [0, 0.92]，y0 = 截断位置
const y0 = Bv.rate * (+baseEl.value / 100);
lieEl.innerHTML    = barSvg(A, Bv, y0, Math.round(190 * stretch)); // 画面版随滑块变形
honestEl.innerHTML = barSvg(A, Bv, 0, 190);                   // 诚实版永远从零起

// 夸大倍数 = 画面高度比 ÷ 真实高度比
const trueRatio = A.rate / Bv.rate;                // 从零起，例：1.04
const seenRatio = (A.rate - y0) / (Bv.rate - y0);  // 截断后，例：1.27
const factor = seenRatio / trueRatio;              // → 1.2×，越截越大

对应演示：图表谎言放大镜（双图对照 + 实时读数）。截断轴的谎不是「感觉」，是可计算的：y0 逼近较矮那根柱的值时 seenRatio → ∞；再叠加 stretch 倍纵横比拉伸，面积感被二次扭曲。注意折线图不受此约束 —— 它的契约是位置而非长度，本规则只约束条形图。

4 可运行演示

拖滑块改变视倾角：左图是直线本身（含 45° 参考虚线），中图是 Cleveland 的 U 型误差曲线与游标，右下角用 crime.csv 的真实回归算出「当前轴下的趋势倾角」—— 切 linear / log 看它怎么跑进 30°–60°。

原创演示 · 图表谎言放大镜：同一份真实数据画两张条形图 —— 左边随「y 轴起点」和「纵横比拉伸」两个滑块变形，右边永远从零画起，中间实时读出「差异被夸大几倍」。练出对截断轴的条件反射。

理论透视 · 条形图的隐含契约：条形长度从零起编码数量——这是读者与图形的无声约定，截断 y 轴等于撕毁契约：4% 的真实差距被画成 27% 的视觉悬崖。Cleveland & McGill 的感知实验为此给出理论依据：位置比较最准、长度次之、面积最差——截断轴把本该是「位置/长度」的比较悄悄降级成「面积」比较，而纵横比拉伸会进一步放大面积感（同一份数据，拉一拉高宽比就能讲出另一个故事）。夸大倍数 = 画面比例 ÷ 真实比例，本演示把它实时算出来。防御性读图三问：y 轴从哪起？纵横比是多少？绝对差到底是多少？——三问问完，大多数谎言不攻自破。注意折线图不受此约束：它的契约是「位置」而非「长度」，适度截断反而合理。

本节小结

  • Cleveland 1984：斜率估计误差呈 U 型，0° / 90° 最差、45° 最好；稳定区间取 30°–60°。
  • Stevens 幂律（感知 ≈ 真实1.0~1.3）解释了原因：人眼把陡度夸张了约 30%，45° 附近恰好抵消。
  • 设计动作：把关键斜率赶进 30°–60°；增长曲线用 log 轴压缩陡度 —— 换 scale 就能换倾角。
自测 · 1 题

用滑块把视倾角从 45° 拖到 85°，Cleveland 的 U 型误差曲线会怎么变？

U 型曲线的两侧都是单调上升的：从 45° 出发，无论往 0° 还是往 90° 走，误差都在变大。85° 与 5° 都在「危险区」，在这样的倾角上比较趋势，感知误差会直接盖过真实差别。

4.5 等值线（Marching Squares）

给定标量场 + 阈值，把「值 = 阈值」的那条曲线追踪出来。

1 原案例

原 5.2.2 节用 Marching Squares 从 crime.csv 里提取等值线，但原始代码是一张截图占位 —— 这节课我们把它补成真能跑的算法，并把每一步摊开来看。

思路：先把 50 个州的两个指标（如谋杀、抢劫）当成 2D 平面上的散点，用核密度估计（KDE）铺出一张标量场，再对这个连续场取等值线 —— 等值线包围的就是「密度相仿」的区域。

2 嵌入理论

原理：用「格子四角的大小关系」判断线段怎么走

把标量场离散化成网格。对每个 cell，看它的4 个角是不是大于阈值 —— 4 个布尔量组成 case 编号 0~15（2⁴ = 16 种）。每种 case 对应 0 / 1 / 2 条线段，正好把「超过阈值」和「未超过阈值」两片区域分开。

位编码：bit0 = BL、bit1 = BR、bit2 = TR、bit3 = TL（左下→右下→右上→左上，顺时针）。

每条线段的端点落在 cell 的边上，位置由线性插值求出：t = (阈值 − a) / (b − a)，其中 a、b 是该边两端格点的值。

唯一需要动脑的情形：case 5 与 case 10 是鞍点（对角两两大于阈值），此时线段有两种连法，必须借助 cell 的中心值才能决定该往哪边连。

推广到 3D：每个立方体 8 个角 → 2⁸ = 256 种 case，就是 Marching Cubes（Lorensen & Cline 1987），医学 MRI / CT 的等值面提取标配。

3 ⭐ 关键代码
① EDGE_TABLE：16 种 case 的核心数据结构 
// 边编号：0 = 左中, 1 = 下中, 2 = 右中, 3 = 上中
const EDGE_TABLE = [
  [],                  // 0000 全小于阈值 → 无线段
  [[3, 0]],            // 0001 仅 BL 大
  [[0, 1]],            // 0010 仅 BR 大
  [[3, 1]],            // 0011 BL + BR
  [[1, 2]],            // 0100 仅 TR 大
  [[3, 0], [1, 2]],    // 0101 鞍点（需看格心）
  [[0, 2]],            // 0110 BR + TR
  [[3, 2]],            // 0111 只有 TL 小
  [[2, 3]],            // 1000 仅 TL 大
  [[2, 0]],            // 1001 TL + BL
  [[0, 1], [2, 3]],    // 1010 鞍点（需看格心）
  [[2, 1]],            // 1011 只有 BR 小
  [[1, 3]],            // 1100 TR + TL
  [[1, 0]],            // 1101 只有 TR 小
  [[0, 3]],            // 1110 只有 BL 小
  [],                  // 1111 全大于阈值
];

这张表就是 Marching Squares 的全部算法逻辑 —— 剩下的都是查表 + 插值。case 0 与 15 无交点（整格同侧），case 5 与 10 各有 2 条线段且方向有歧义。

② 位运算拼出 case 编号 
// 4 个角「是否大于阈值」→ 4 位二进制 → case 编号 0~15
let code = 0;
if (bl > threshold) code |= 1;   // bit 0
if (br > threshold) code |= 2;   // bit 1
if (tr > threshold) code |= 4;   // bit 2
if (tl > threshold) code |= 8;   // bit 3

const segs = EDGE_TABLE[code];    // 查表得到 0 / 1 / 2 条线段

用|= 累加「2 的幂」是位运算的经典写法：4 个布尔恰好拼出 0~15 的编号。顺序很关键 —— 表里的 0/1/2/3 边编号与这里 bit 的排列必须一一对应，否则线段会连错位置。

③ 在边上线性插值求交点（含鞍点判方向） 
// 边 (a→b) 上与阈值等值点的位置 t ∈ [0,1]
const t = (threshold - a) / (b - a);
const px = ax + t * (bx - ax);
const py = ay + t * (by - ay);

// 鞍点：比较格心与阈值，决定两条线段各自该连哪一对边
const center = (tl + tr + bl + br) / 4;
// code 5: 格心 > 阈值 → 连 [3,0]；否则连 [1,2]
// code 10: 格心 > 阈值 → 连 [2,3]；否则连 [0,1]

为什么必须插值：如果偷懒取边中点，等值线会变成锯齿状的折线，网格越粗越难看。线性插值让交点在边上按数值比例滑动，网格很粗时也能得到平滑的曲线。

4 可运行演示

点「下一步」逐步走完算法：格点取值 → 标记大于阈值的格点 → 在边上插值求交点 → 连成折线；也可以「播放」自动走完，拖阈值滑块看等值线如何变形、有时会分裂成两圈。

本节小结

  • Marching Squares = 用格子四角的「是否大于阈值」拼出 case 编号（0~15），查表得到 0/1/2 条线段，把两侧区域分开。
  • 线段端点由边上线性插值给出（t = (阈值 − a)/(b − a)），这是等值线平滑的关键。
  • 只有鞍点（case 5 / 10）有歧义，必须借助格心值判方向；推广到 3D 就是 2⁸ = 256 种 case 的 Marching Cubes。
自测 · 1 题

Marching Squares 里 case 5 与 case 10 为什么需要特殊处理？

全大（15）与全小（0）才没有线段。case 5 / 10 是对角两角大于阈值，两条线段既可以「围住两个大角」也可以「围住两个小角」，几何上有歧义 —— 算法惯例是比较格心值与阈值来定夺。
