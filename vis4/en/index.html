CHART CHEAT SHEET

Chart cheat sheet: ask about the task first, then pick the mark

The right-hand column marks the most commonly misused spots. The first step in choosing a chart is not “which one looks nice” but “which visual channels my data type allows”.

Quick-reference matrix: look up charts by “what you want to express” (the full version — 20 rows, an interactive decision tree, right-vs-wrong comparisons and a 6-question quiz — lives in the Chart Selection Guide topic page)
You want to show Recommended chart Main visual channel Use with care / common mistakes
Compare sizes across a few categories Bar chart Length (position) Don't encode size as area / volume; sort by value when there are many categories
See the distribution shape of one variable Histogram / density plot Length (binned counts) Bin width decides the shape — change the width and you change the story
See the relationship between two variables Scatter plot Position (x, y) Set transparency when points overlap, or switch to hexagonal binning
See the trend over time Line chart Position + slope The time axis must be evenly spaced and continuous; never draw lines across unordered categories
See composition and shares Stacked bar chart Length (totals stay comparable) A pie with more than 5 slices cannot be read; sort slices by size
See 2-D density / strength of correlation Heatmap Color lightness (sequential colormap) Never use a rainbow scale; a color legend is mandatory
Compare several distributions and find outliers Box plot / violin plot Position + length (statistics) Don't box-plot very small samples — draw the points directly
See the overall structure across many variables Scatterplot matrix / parallel coordinates Position (multiple axes) Beyond 8 dimensions, switch to dimensionality reduction (PCA) or faceting

ABOUT

About this course

📖 Theory sources

Chen Wei, “Introduction to Visualization”; Mackinlay 1986 (ranking of visual channels); Stevens 1946 (scales of measurement); Cleveland 1984 (graphical perception); Card 1999 (data-flow model); Bostock's official D3 documentation.

🎯 Design principles

Case-centered, not theory-centered. Every concept is embedded in a practical case, with ⭐ key-point notes, runnable demos and instant self-tests.

🧭 How to study

① Each chapter opens with learning goals; ② read on section by section — demos render in place; ③ use the “code only” switch for quick review; ④ finish each section's self-test before moving to the next.

🛠️ Tech stack and constraints

Zero build: plain HTML + CSS + ES Modules + a locally bundled D3 module, no videos at all. Every principle diagram is drawn with inline SVG, keeping the site compact and fully offline-capable.

🗂️ Appendix · Original Specimens

The appendix collects the course's original standalone demos plus the Chapter 4 lecture PDF: vanilla D3 kept as-is — read the chapters first, then come here to compare with the source.
