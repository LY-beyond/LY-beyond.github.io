5.1 时间属性

动手画时序图之前，先回答一个问题：我手上这条「时间」，到底是时刻、间隔，还是周期？

1 你的原案例

原 6.1 节把时间属性列成了一张「名词解释表」，读完还是不知道该怎么用。本节把它们搬上一个环形轮盘：点某个属性，旁边立刻显示它的定义、一个生活例子，以及它最典型的可视化方式。

轮盘上放的是 5 个可以直接落到坐标轴上的属性：时刻（instant）、间隔（interval）、跨度（span）、频率（frequency）、周期（cycle）。它们不是互相排斥的 5 类数据，而是「同一列时间」可以被提问的 5 个角度 —— 电话号码表要问时刻，心率曲线要问间隔，销售额月报要问周期。

2 嵌入理论

陈为教材：时间是有结构的量纲

教材强调时间不是普通的数值轴，它自带 5 个性质：有序性（任意两个事件可比较先后，与因果紧密相连）、连续性（两个时刻之间永远还有时刻）、周期性（自然过程常有循环，如昼夜与季节，可用循环时间域表达）、独立于空间（时间与空间紧相关，但科学过程大多把二者分开处理）、结构性（年 / 月 / 日 / 时 / 分 / 秒 的层级切分，既有自然的昼夜，也有人为约定的 60 秒）。

  • 把「时刻」当作点 → 散点图、事件标记；把「间隔」当作长度 → 甘特图、时间线括号。
  • 把「跨度」当作区间 → 面积图、时间轴范围高亮。
  • 忽略「周期性」→ 季节趋势会被线性时间轴「抹平」，只剩一条看不出规律的锯齿线。

把这 5 个属性想清楚，能挡掉四类常见错误：有序性缺失（散点图错位成噪声）、连续性混淆（离散事件却硬连成线）、周期性忽略（季节趋势被抹平）、结构性不匹配（工作日 / 周末、闰年统统计错）。

  { key: 'cycle',     name: '周期', icon: '⟳', token: '--c-success',

为什么用对象数组：轮盘、详情、图例三处都要读同一批属性。写成一份数据源后，改一处即可全站生效，不会「改了卡片忘了图例」。顺带一提：颜色不写死色值，而是记下载令牌名（'--c-primary'），运行时再取 getComputedStyle —— 这样深色模式会自动跟随。

② 环形轮盘的布局：角度 → 极坐标 → 笛卡尔 
// ⭐ 5 个节点均分 360°：从正上方（-90°）开始，每格 72°
const N = 5;
const nodeAt = (i) => {
  const deg = -90 + i * (360 / N);
  const rad = deg * Math.PI / 180;
  return {
    x: CX + R * Math.cos(rad),   // 极坐标 = (R, θ)
    y: CY + R * Math.sin(rad),   // 转成笛卡尔 = (x, y)
    rad,
  };
};
// 相邻两点的夹角恒为 72°，所以「节点间距」天然均匀

极性布局的通用套路：先定角度（θ = 起点 + i·360/N），再乘半径换成 x / y。前几章画金字塔用的是 M / L / Z 直线指令，这里换成 cos / sin —— 极坐标是「圆周类图形」（轮盘、雷达图、螺旋、饼图）的通用入口。

本节小结

  • 时间可以被问成 5 个角度：时刻（点）、间隔（长度）、跨度（区间）、频率（重复次数）、周期（循环）。

自测 · 第 1 题

「2024 年 3 月 1 日 08:00 的气温读数」这一条数据，在时间属性里属于？

它落在一个瞬时上，是一个点，所以是时刻。间隔要两个时刻相减（如「从 08:00 到 12:00 共 4 小时」）；跨度是一整段连续覆盖的范围；周期是回到起点的重复段 —— 三者都不是这一条数据本身的属性。

自测 · 第 2 题

在设计时序图时忽略「周期性」，最可能造成的后果是？

线性时间轴把每一年或每一天并排铺开，周期性信号会被拉成一条看不出规律的锯齿线；这正是不用折线、改用日历热图（5.3）或螺旋图（5.4）的原因。选项 a 对应「有序性缺失」，b 对应「连续性混淆」，d 对应「结构性不匹配」。

5.2 标准时间可视化（折线图）

x 轴 = 时间，y 轴 = 度量。最常见的时序图，也是最能被「聚合尺度」左右结论的一张图。

1 你的原案例

原 6.2.1 节用折线图展示法国人名（Marie / Jean / Camille）在 1900–2020 年的使用频率变化。原始页面还配了「词云 + 鼠标高亮 + 时间段筛选」，但代码只给出了关键折线那几行。

三类数据 → 三种尺度的折线：本节把「同一份序列」放到不同聚合尺度下并排对照
聚合尺度点数（2024 日气温）看得出的东西会丢掉的东西
原始日数据366逐日抖动、极端天气长期趋势（被噪声淹没）
按周聚合约 53周级别的起伏、短期趋势周内的具体某天
按月聚合12全年季节曲线，一目了然月内所有细节
2 嵌入理论

标准时序图 = 二维线图

本质是「x = 时间、y = 度量」的二维线图，优势是在线性时间域中的变化趋势一目了然；代价是难以表达周期性 —— 这也是 5.3 日历热图与 5.4 螺旋图存在的理由。交互上，hover 高亮、tip 显示、时间段筛选已经是数据新闻的标配。

  • 曲线选型：点数 ≤ 50 用 linear（忠实于数据）；50–500 用 monotoneX / curveCatmullRom（平滑但不过冲）；> 500 才考虑面积图或箱形图。
  • 聚合权衡：聚合能降噪、更能看清趋势，但每一步聚合都在「用细节换清晰」，结论可能因此变化。

经验法则是先看目标再选尺度：要回答「某天下没下雨」就用日数据；要回答「这个夏天热不热」就用月聚合；要同时回答两者，就并排放（本节演示就是这个做法）。

3 ⭐ 关键代码
① 时间字符串 → Date，再交给时间轴 
// ⭐ CSV 里的年份是字符串 '1965'，先解析成 Date
const parseYear = d3.timeParse('%Y');      // '1965' → Date
const formatYear = d3.timeFormat('%Y');     // Date → '1965'
// 常用 token：%Y 四位年 · %m 月 01-12 · %d 日 · %H 时 · %M 分

// 时间轴 = 数值轴的特化版（Date 在底层就是数字）
const x = d3.scaleTime()
  .domain([new Date(1900, 0, 1), new Date(2020, 11, 31)])
  .range([0, innerW]);

svg.append('g')
  .attr('transform', `translate(${M.l},${M.t + innerH})`)
  .call(d3.axisBottom(x).ticks(10));

parseYear 处理字符串 → Date，是所有时序数据的第一步（CSV 里几乎没有真正的日期类型）。scaleTime 比 scaleLinear 多两个能力：① 自动按时间跨度挑 tick 间隔（10 年 / 12 月 / 30 天）；② 时区处理（真实项目记得加 .utc()）。

② 聚合：把日序列 rollup 成周均值 / 月均值 
// ⭐ 按「所属周 / 月」分组，再求均值 —— 一份代码换三种尺度
const byWeek = d3.rollup(
  daily,
  (v) => d3.mean(v, (d) => d.temp),         // reducer：均值
  (d) => d3.timeWeek.floor(d.date)           // key：这一天的“周起点”
);
const byMonth = d3.rollup(
  daily,
  (v) => d3.mean(v, (d) => d.temp),
  (d) => d3.timeMonth.floor(d.date)          // key：这一天的“月起点”
);
// rollup 返回 Map(Date → 均值)，再 [ ...map ] 展开即可画图

关键在 key 提取函数：timeWeek.floor(date) 把「这周的任意一天」都折回同一个周起点，于是同周的点自然归为一组。第 1 章学的 rollup（分组聚合）在这里终于派上正用 —— 聚合尺度的切换，本质只是换一个 key 函数。

③ 通用 hover 模板：透明覆盖层 + 焦点组 
// ⭐ 三层结构：透明矩形捕获事件 / focus 组显示 / text 显示数值
const focus = svg.append('g').style('display', 'none');
focus.append('line').attr('class', 'hover-line');   // 垂直参考线
focus.append('circle').attr('r', 4);                // 圆点
focus.append('text').attr('class', 'tip');              // 数值

svg.append('rect')                                  // 覆盖层
  .attr('width', innerW).attr('height', innerH)
  .attr('fill', 'none').attr('pointer-events', 'all')
  .on('mousemove', (event) => {
    const [mx] = d3.pointer(event);
    const date = x.invert(mx - M.l);              // 像素 → 数据
    const i = d3.bisector((d) => d.date).left(series, date);  // 找最近点
    focus.attr('transform', `translate(${x(series[i].date)},0)`);
  });

记住这三件套（透明矩形 + 焦点组 + bisector），几乎能套用到所有时序图上。x.invert() 把鼠标像素反算成数据值，d3.bisector 用二分查找找最近点 —— 比手写循环又快又准。

  • 标准时序图就是「x = 时间、y = 度量」的二维线图；它擅长趋势，不擅长周期。
  • 聚合尺度（原始 / 周 / 月）会显著改变图形形态与结论 —— 换尺度，本质只是换 rollup 的 key 函数。

自测 · 第 1 题

把 366 天的日气温序列按周聚合后再画折线，最直接的效果是？

聚合是「用细节换清晰」：366 个点被折成约 53 个点，噪声被平均掉、趋势更明显，代价是周内每一天的差异看不到了。它不会把时间域变成循环域 —— 那是 5.4 螺旋图做的事。

自测 · 第 2 题

d3.scaleTime 相比 d3.scaleLinear，多出来的核心能力是？

scaleTime 在数值轴之上加了「时间语义」：自动按跨度选刻度间隔（十年 / 十二月 / 三十天），并提供 .utc() 处理时区。字符串转 Date 靠 timeParse，聚合靠 rollup，画平滑曲线靠 curve* —— 都不是比例尺的职责。

5.3 日历热图（van Wijk）

把「一整年」摊成一张网格：x = 周、y = 星期、颜色 = 数值 —— 季节性一下就浮出来了。

1 你的原案例

原 6.2.2 节用日历热图展示 2024 年北京每日最高温度，每月之间用一条红线分隔。本节沿用同一份数据（data/weather_2024.csv，366 天），并把「为什么这样排比折线更易读」讲透。

折线图回答的是「随时间变化」；日历热图回答的是「随季节 / 星期变化」。同一份 366 天的数据，在折线图里是 366 个此起彼伏的锯齿，在日历里却能一眼看出：冬季整片偏蓝、夏季整片偏红，以及每 7 天重复一次的列节律。

2 嵌入理论

van Wijk 2008：日历热图的坐标约定

日历热图由 van Wijk 在 2008 年提出：x = 周（年内的第几周），y = 星期几，颜色 = 数值。它特别适合三类任务：① 长时序（跨年）+ ② 周期性（星期 / 月）+ ③ 异常检测（节假日、工作日 vs 周末）。

  • 周起点选谁：每周从周日或周一开始，会直接改变「周末」在视觉上的位置 —— 中文场景常改用周一起点。
  • 月份分隔：用红线把月份切开，比一个 7 × 53 的裸网格易读得多。
  • 配色：用顺序型 colormap（如 Viridis），因为「温度高低」是有顺序的 —— 参见第 3 章 3.2 colormap。

isMonthDivider 的巧妙之处：不必循环「找每个月的第一天」，只要判断「7 天前与今天是否同月」：同月就不画线，跨月就画一条分隔线。一次 O(n) 扫描即可，且天然正确。

3 ⭐ 关键代码
① d3.timeDay.range 把「一年」拆成「一天一天」 
// ⭐ 自动按日粒度切分整年，闰年 366 / 平年 365 自动正确
const days = d3.timeDay.range(
  new Date(2024, 0, 1),      // 2024-01-01
  new Date(2025, 0, 1)       // 2025-01-01
).map((d) => ({
  date: d,
  value: byKey.get(d3.timeFormat('%Y-%m-%d')(d)) ?? 0,
}));
console.log(days.length);   // 366（2024 是闰年）

d3.timeDay.range(start, stop) 一次命中「连续性 + 结构性」两个属性：既按日内粒度连续铺开，又自动处理月份与闰年。小坑：timeFormat('%Y-%m-%d') 与 CSV 里的日期字符串键必须完全一致，否则整天对不上、热图出现空洞。

② 周日为起点的「周列 / 星期行」布局 
// ⭐ 列 = 这是今年的第几周（把天数除以 7）；行 = 星期几
function weekCol(date) {
  return Math.floor(d3.timeDay.count(d3.timeYear.floor(date), date) / 7);
}
function dayRow(date) {
  return date.getDay();     // 0=周日, 1=周一, … 6=周六
}

g.selectAll('rect.cell')
  .data(days).join('rect')
  .attr('x', (d) => weekCol(d.date) * cellSize)
  .attr('y', (d) => dayRow(d.date) * cellSize)
  .attr('width', cellSize).attr('height', cellSize)
  .attr('fill', (d) => color(d.value));

周日 vs 周一是日历热图的设计分歧：getDay() 以周日为 0，是英文日历传统；中文场景常把行序改成 (getDay() + 6) % 7 让周一排第一行。本轮演示提供「周日起 / 周一起」开关，切换即可看到「周末」在网格里换位置。

③ isMonthDivider：月份分隔线的一遍扫描 
// ⭐ 判断「7 天前与今天是否同月」：同月不划线，跨月画线
function isMonthDivider(date) {
  const sevenDaysAgo = d3.timeDay.offset(date, -7);
  return date.getFullYear() !== sevenDaysAgo.getFullYear()
      || date.getMonth()    !== sevenDaysAgo.getMonth();
}

// 画竖线：跨月的那一列，从上到下切一刀
g.selectAll('line.mdiv')
  .data(days.filter((d) => isMonthDivider(d.date))).join('line')
  .attr('x1', (d) => weekCol(d.date) * cellSize)
  .attr('x2', (d) => weekCol(d.date) * cellSize)
  .attr('y1', (d) => dayRow(d.date) * cellSize)
  .attr('y2', (d) => dayRow(d.date) * cellSize + cellSize);

换成「找每月第一天」的直觉写法，就得处理 28 / 29 / 30 / 31 天的差异，还容易漏掉「列交叉」的情况。「回看 7 天」的写法只用一次 O(n) 扫描，天然覆盖所有月长与闰年 —— 这是 van Wijk 算法的精妙之处。

4 可运行演示

2024 全年日气温铺成「周 × 星期」热图（蓝=冷 / 红=热），月份之间用红线分隔。可切换「周一起 / 周日起」，鼠标悬停任一格看日期与温度。

本节小结

  • 日历热图 = 周列 × 星期行 × 颜色编码，由 van Wijk 2008 提出，专治「长时序 + 周期性 + 异常检测」。
  • 月份分隔用「7 天前是否同月」判断，O(n) 一遍扫描即可，不必找每月第一天。
  • 它和折线图回答不同问题：折线看「随时间变化」，日历看「随季节 / 星期变化」。
自测 · 1 题

isMonthDivider(date) 用「7 天前是否同月」来判断是否画月份分隔线，这样写的好处是？

把「判断是否跨月」交给相邻两周的对比，就绕开了「每月有多少天」这件事：不管 28 / 29 / 30 / 31 天，只要向前看 7 天即可，一次遍历完成。它不负责算温度，也不决定颜色 —— 那是 reducer 与 colormap 的活。

5.4 周期时间可视化（阿基米德螺旋）

直线表达趋势，圆圈表达周期，螺旋 = 圆 + 持续展开 —— 把一年卷成螺旋，周期性一眼可见。

1 你的原案例

原 6.2.3 节用阿基米德螺旋（等速螺旋）布局日期：每个回路代表 1 年 / 1 月 / 1 周，每个日期对应螺旋上的一个扇环。本节继续用 2024 日气温，并提供「每圈 = 1 年 / 1 季 / 1 月」三档切换 —— 同一份数据，卷的圈数不同，能看出的周期层级也不同。

每圈代表圈数（2024 一年）能看出的周期
1 年1 圈全年一次的季节循环
1 季4 圈四季的进退层级
1 月约 12 圈月内到月间的短周期起伏
2 嵌入理论

螺旋 vs 折线：两种时间域

折线把时间铺在线性时间域上，擅长表现「趋势」；螺旋把时间铺在循环时间域上，沿圆周重复，擅长表现「周期」。阿基米德螺旋的公式是 r = a + bθ：等速展开，每转一圈半径就增加一个常量 b —— 如果 b = 0，它就退化成普通的圆。

  • 动态 Δθ 算法：原文档的精妙点 Δθ = boxSize / √(b² + r²)，让每个扇环的弧长近似相等，从而在半径不断增大时仍保持视觉一致。
  • 实战取舍：螺旋适合「年 / 季节 / 周」这类有明确循环的周期，不适合「无周期」或「周期太长」的数据。

螺旋会把「相邻两圈」在视觉上贴得很近，读者容易误读成「同时发生」。所以务必给每圈的起点加标记（本演示用月份标签），并让读者知道「一圈 = 多久」。

3 ⭐ 关键代码
① 极坐标 → 笛卡尔：r = a + bθ 
// ⭐ 每环的宽度与圈间距
const boxSize = 22;
const coilGap = boxSize * 1.4;            // 相邻两圈的径向间距
const b = coilGap / (2 * Math.PI);          // 每转一圈，r 增加的常量
const startRadius = 60;
let theta = (startRadius - 0) / b;         // 起始角度

function pos(t) {                       // t: 角度（弧度）
  const r = 0 + b * t;                    // 阿基米德螺旋：r 与 θ 成正比
  return { x: r * Math.cos(t), y: r * Math.sin(t), r };
}

极坐标是 (r, θ)，笛卡尔是 (x, y)：θ 每增 2π，r 就增 b，这正是「每转一圈外扩一格」。b 越大，圈与圈之间越松散、螺旋越「舒展」；b = 0 则完全退化成圆 —— 这也说明「圆」是螺旋的特例。

② 动态角度增量：让每段弧长近似相等 
// ⭐ 弧长 = r · Δθ。r 越大，同样 Δθ 对应的弧长越长
function angleDelta(currentR) {
  return boxSize / Math.sqrt(b * b + currentR * currentR);
}
// 等价于「弧长 ≈ boxSize」：让每一格在视觉上一样大

let t = theta;
for (let day = 0; day < dayCount; day++) {
  const p = pos(t);
  // … 画第 day 天的扇环（t → t + Δθ）
  t += angleDelta(p.r);          // 角度增量随半径动态减小
}

这是原文档的核心洞察：外圈半径大，若角度增量恒定，格子就会被「拉长」。把 Δθ 写成 取整宽度 / √(b² + r²)，就相当于让每一格的弧长都约等于 boxSize，内外圈看起来一样整齐。代价：一圈不再严格等于 2π，所以「每圈 = 一个周期」要按圈索引来读，而不是按角度读。

③ 扇环路径：一个格子四个顶点的 M / L / Z 
// ⭐ 4 个关键点：起点外 → 终点外 → 终点内 → 起点内，闭合回起点
function segmentPath(t0, t1, r0, r1, halfWidth) {
  const at = (t, rr) => [rr * Math.cos(t), rr * Math.sin(t)];
  const [x0o, y0o] = at(t0, r0 + halfWidth);     // 起点 · 外
  const [x1o, y1o] = at(t1, r1 + halfWidth);     // 终点 · 外
  const [x1i, y1i] = at(t1, r1 - halfWidth);     // 终点 · 内
  const [x0i, y0i] = at(t0, r0 - halfWidth);     // 起点 · 内
  return `M ${x0o} ${y0o} L ${x1o} ${y1o} L ${x1i} ${y1i} L ${x0i} ${y0i} Z`;
}

一个扇环就是一条 M / L / L / L / Z 的路径 —— 和 5.1 学到的直线指令完全一样。为什么不用 d3.arc()：它是按「圆弧角度」算的，对半径持续变化的螺旋无法直接套用，手算 4 个顶点反而更灵活。

4 可运行演示

同一份 2024 日气温：先切换「每圈 = 1 年 / 1 季 / 1 月」，看圈数与半径增长如何变化；再勾选「等弧长 Δθ」，对比「外圈格子被拉长」与「内外圈宽度一致」两种效果。鼠标悬停任一格看日期与温度。

本节小结

  • 螺旋把时间放进「循环时间域」：r = a + bθ，每转一圈半径增加常量 b，b = 0 就退化成圆。
  • 动态 Δθ = boxSize / √(b² + r²) 让每段弧长近似相等，解决「外圈格子被拉长」的视觉不一致。
  • 每个日期 = 一个扇环，路径就是 M / L / L / L / Z 四个顶点 —— 不必依赖 d3.arc()。
自测 · 1 题

为什么要用动态角度增量 Δθ = boxSize / √(b² + r²)，而不是固定的 Δθ？

弧长 ≈ r · Δθ，半径 r 越大弧长越长。让 Δθ 随 r 增大而减小，就能把每一格的弧长稳定在 boxSize 附近，内外圈视觉一致。代价是「一圈」不再严格等于 2π —— 所以周期要靠圈索引来读，而不是靠角度。

5.5 Storyline 时间线（侏罗纪公园）

多条「生命线」并排铺在时间轴上：线靠近 = 相遇 / 冲突，线分开 = 分离 —— 把叙事画成一张图。

1 你的原案例

原 6.2.4 节用《侏罗纪公园》的 5 个角色（Alan & Kids / T-REX / Raptors / Malcolm / Dilophosaurus）做 Storyline 时间线，事件层用红色半透明圆圈标注关键冲突。本节沿用这份叙事数据（改写成 lesson.js 内的中文注释常量），并把「点击一条线就能读它的出场区间与关键节点」补上。

2 嵌入理论

Ogawa & Ma 2008：把叙事拆成生命线

Storyline 由斯坦福大学的 Ogawa & Ma 在 2008 年提出，最初用于电影与学术合作者关系网。核心是把每个角色 / 组织 / 进程抽象成一条生命线：线靠近 = 角色相遇或冲突，线分开 = 角色分离 —— 于是「谁在什么时候和谁在一起」变成可读的几何。

  1. 时间尺度映射：电影时长 → SVG 宽度，x 轴严格按比例对齐（0–127 分钟）。
  2. 样条平滑：用 Catmull-Rom 曲线，张力系数 0.5 —— 「自然流动」但不「过度弯曲」。
  3. 事件层：半透明红圈 + 文字，标注关键转折点，与线层解耦。

为什么用 Catmull-Rom 而不是 monotoneX？ monotoneX 保证「不过度弯曲」，但会把线画得过于直，丢掉叙事的「河流感」。Catmull-Rom 的张力 0.5 是经验值：比 0 更软（有故事感），比 1.0 更稳（不震荡）。做科学曲线拟合时才把张力调到 0.2–0.3。

3 ⭐ 关键代码
① 每个角色 = 一条 path（时间尺度映射） 
// ⭐ 横轴：0–127 分钟 → 屏幕宽度；每条线用 y 表达“关系”
const x = d3.scaleLinear().domain([0, 127]).range([M.l, W - M.r]);

const characters = [
  { name: 'Alan & Kids', token: '--ch-1', points: [
    { time: 5,  y: 80 }, { time: 18, y: 130 },
    { time: 78, y: 80 }, { time: 125, y: 40 },
  ]},
  { name: 'T-REX',       token: '--c-danger', points: [
    { time: 75, y: 280 }, { time: 78, y: 130 },
    { time: 120, y: 290 },
  ]},
];

const line = d3.line()
  .x((d) => x(d.time))
  .y((d) => yScale(d.y))
  .curve(d3.curveCatmullRom.alpha(0.5));   // 张力 0.5

characters.forEach((c) => {
  svg.append('path').datum(c.points)
    .attr('d', line)
    .attr('stroke', getToken(c.token))
    .attr('stroke-width', 3)
    .attr('fill', 'none');
});

用 y 值表达「关系」是关键：T-REX 与 Alan 都把自己的线画到 y = 130（同一时刻 t = 78），两条线就视觉聚拢 —— 表达「T-REX 在 78 分钟攻击了 Alan」。这不是算法生成的，而是手工叙事设计；库只是提供了「手工调 y」的工具。

② 事件层：与线层解耦的叙事锚点 
// ⭐ 事件层单独一个 <g>：半透明红圈 + 圆点 + 文字
const events = [
  { time: 78, y: 105, name: 'T-REX 攻击',
    desc: 'T-REX 冲出围栏，攻击 Alan 与孩子们的车' },
  { time: 48, y: 335, name: 'Nedry 事件',
    desc: 'Dilophosaurus 攻击断电的 Nedry' },
];

const layer = svg.append('g').attr('class', 'event-layer');
events.forEach((ev) => {                       // 只读渲染，事件本身不改线
  const g = layer.append('g').attr('tabindex', 0);   // 可聚焦，键盘也能看
  g.append('circle').attr('cx', x(ev.time)).attr('cy', yScale(ev.y))
    .attr('r', 18).attr('fill', 'color-mix(in srgb, var(--c-danger) 18%, transparent)');
  g.append('text').attr('x', x(ev.time)).attr('y', yScale(ev.y) - 9)
    .attr('text-anchor', 'middle').text(ev.name);
});

双层结构的价值：线层负责「关系的流动」，事件层负责「叙事的锚点」。两层解耦后，可以各自独立动画、独立筛选，互不干扰 —— 这也是 Storyline 能扩展成「案件多人时间线」「项目任务交接」的原因。

③ alpha(0.5)：张力系数怎么选 
// curveCatmullRom.alpha(t)，t 取值 0 → 1
d3.line().curve(d3.curveCatmullRom.alpha(0.0));  // 接近直线（最“硬”）
d3.line().curve(d3.curveCatmullRom.alpha(0.5));  // 标准 Catmull-Rom（推荐）
d3.line().curve(d3.curveCatmullRom.alpha(1.0));  // 高度曲线化（易震荡）

// 无 d3 依赖的等价近似：在「直线 ↔ Catmull-Rom」之间插值控制点
// 曲线段 p1→p2 的两个控制点：
//   直线版    c1 = p1 + (p2 - p1)/3,  c2 = p2 - (p2 - p1)/3
//   Catmull 版 c1 = p1 + (p2 - p0)/6,  c2 = p2 - (p3 - p1)/6
// c = lerp(直线版, Catmull 版, t)  → 三次贝塞尔近似

0.5 是经验值：比 0 更「软」（看起来有故事感），比 1.0 更「稳」（不会过山车）。做时间叙事就用 0.5；做科学曲线拟合用 0.2–0.3，让线更贴近数据。本页演示用「分段三次贝塞尔」近似 Catmull-Rom（不引 d3），并用滑块调节张力，效果与 alpha 一致。

4 可运行演示

点击任意一条生命线（或左侧角色名）—— 该线高亮加粗，其余变淡，右侧显示它的出场区间与关键节点。拖动「张力」滑块可实时改变曲线弯曲度。

本节小结

  • Storyline 把角色 / 组织 / 进程抽象成生命线：线靠近 = 相遇 / 冲突，线分开 = 分离。
  • 三大元素缺一不可：时间尺度映射、Catmull-Rom 样条、与线层解耦的事件层。
  • 张力 0.5 是叙事的经验值；要忠于数据时把张力降到 0.2–0.3，或直接用 monotoneX。
自测 · 1 题

在 Storyline 时间线里，一条生命线的 y 轴位置表达的是什么？

Storyline 的 y 轴不是数值轴，而是关系轴：两条线画到同一高度，读者就读到「这两个角色此刻在一起或起了冲突」。x 轴才是时间（严格按比例映射），出场次序与数值大小都由 x 表达。
