1.1 数据生成

一切可视化的起点：先把「现实世界」装进一张表格。

1 你的原案例

本章从头到尾只用一份数据：中国石油大学（华东）2025 级新生名册。它由 DeepSeek 大模型合成，含 80 条记录、8 列。

字段清单：中文列名是人读的，JS 变量是程序读的
列名含义原始类型建议 JS 类型
序号行号，唯一标识StringNumber（id）
姓名学生姓名StringString（name）
性别男 / 女StringString（gender）
生日出生日期StringDate（birthday）
年龄入学时年龄StringNumber（age）
班级软件工程 / 数据科学 + 班号StringString（class）
籍贯省市StringString（hometown）
民族民族StringString（ethnicity）
2 嵌入理论

AI 合成数据的可信度边界

合成数据可以拿来做教学与练习，但它不是真实数据的替代品。评估任意一份数据是否可信，都看这四个维度：准确性（反映真实世界的程度）、完整性（字段是否齐全）、一致性（同一概念在不同地方表达一致）、时效性（数据是否反映当前状态）。

采样偏差：模型倾向生成「看起来合理」的分布 —— 民族高度偏汉族、籍贯偏向大城市。所以本章的所有结论都只用来演示方法，不要外推到真实学生群体。

3 ⭐ 关键代码
① 字段名映射：中文列名 → 英文 JS 变量 
// 把中文 CSV 列名转成英文 JS 变量
const COLUMN_MAP = {
  "序号": "id", "姓名": "name", "性别": "gender",
  "生日": "birthday", "年龄": "age", "班级": "class",
};

为什么不用中文 key？ JS 引擎对中文标识符的容错性差；后端、JSON、URL 编码都可能引入乱码；IDE 的补全、搜索、重构对中文支持不一致。最佳实践：CSV 用人可读的中文名，JS 内部统一英文变量。

② 类型转换：把字符串变成数字与日期 
// 每一行数据都过一遍这个函数
function transformRow(d) {
  return {
    id:       +d["序号"],              // 一元 + ：字符串→Number 的最快写法
    name:     d["姓名"].trim(),       // trim() 去掉首尾空白
    birthday: new Date(d["生日"]),    // 字符串 → Date 对象
    age:      +d["年龄"],
    class:    d["班级"].trim(),
  };
}

坑：没有 trim() 的话，"软件工程1班 " 里的尾随空格会让后续的过滤与聚合「凭空多出一个班级」。兜底：new Date() 对 "2007/8/15" 兼容性差，稳一点用 d3.timeParse("%Y-%m-%d")。

③ d3.csv 第二参直接传 row 回调 
// 一行完成「加载 + 逐行转换」
const data = await d3.csv("data/newstudent.csv", transformRow);

// 验证类型确实转换了：
console.log(typeof data[0].age);                // "number"
console.log(data[0].birthday instanceof Date); // true

为什么这一行重要：① 它是异步函数，必须 await；② 第二参的 row 回调在每一行解析后立即调用，比「先加载再 .map()」省一次内存遍历；③ 异步加载不阻塞页面渲染，用户可以继续交互。

④ 原创 · 简化版 autoType 与五类清洗处方（脏数据急诊台） 
// 对单个值试解析 —— 一列的类型由逐值投票决定
function inferType(v) {
  const s = String(v ?? "").trim();
  if (s === "") return "null";                      // 缺失值
  if (/^-?\d+(\.\d+)?$/.test(s)) return "number";
  const t = Date.parse(s);
  if (!isNaN(t) && /[/-]/.test(s)) return "date";
  return "string";  // "19岁"、"1,105" 都掉进这里 → 整列判 string
}

// 五类处方 = 一条可复现的纯函数变换链
if (fx.thou)  spend = spend.replace(/,/g, "");         // ① 去千分位
if (fx.strip) age   = age.replace(/[^0-9.]/g, "");     // ③ 剥离非数字
if (fx.date && date) date = new Date(Date.parse(date))
  .toISOString().slice(0, 10);                         // ④ 归一化 ISO
if (fx.miss)  out = out.filter(d => d.spend !== "");   // ② 剔除缺失行
if (fx.dup) {
  const seen = new Set();
  out = out.filter(d => {
    const k = JSON.stringify(d);
    return seen.has(k) ? false : (seen.add(k), true); // ⑤ JSON 串当去重键
  });
}

对应演示：脏数据急诊台（勾选处方、看徽章翻绿）。autoType 只认「规矩」的值——千分位 "1,105"、带汉字的 "19岁"、空串都被拒绝转换；任何一处不治，条形图就地渲染失败。清洗必须写成可复现的变换链，而不是在表格软件里悄悄改数。

4 可运行演示

点「重新加载」观察控制台输出 —— 重点看 typeof data[0].age 与 birthday instanceof Date 两行。

原创演示 · 脏数据急诊台：一份带 5 类典型病症的数据，逐项勾选「处方」，看类型徽章翻绿、图表从渲染失败到成功 —— 清洗是可视化的第一公里。

理论透视 · 数据清洗：脏数据可归为五类典型病症——缺失值、类型错误（数字存成 "19岁"）、格式不一致（千分位、非标准日期）、重复行、异常值。它们为什么致命？因为任何聚合与映射都建立在「列的类型正确」之上：一个解析失败的值就能让整列退化为字符串，年龄变成分类变量、求和直接报错——这正是 Garbage In, Garbage Out。本演示的「类型徽章」复刻了 autoType 的原理：逐列采样 → 逐值试解析 → 投票定列型，任何一行不是 Number，整列都无法参与计算。最后记住一条纪律：清洗必须留下可复现的「处方记录」，永远不要悄悄改数。

本节小结

  • 数据的可信度看四维：准确性、完整性、一致性、时效性 —— 合成数据通常只在「准确性」上不达标。
  • d3.csv(url, rowCallback) 一行完成加载与逐行转换，既省内存也省一次遍历。
  • CSV 用中文列名给人看，JS 里统一英文变量给程序用；trim() 与一元 + 是类型清洗的两个必备动作。
自测 · 1 题

用 d3.csv(url, transformRow) 的第二参传入行回调，相比「先 await 再 .map() 转换」，主要好处是？

行回调在每一行解析完的那一刻就被调用，所以不必先把整份字符串数组读进内存再遍历一次。d3.csv 依然是异步的（必须 await），也不会自动改名或做类型转换 —— 那两件事都要你自己在回调里写。

1.2 数据定义

同样是「18」，它到底是三个数字、一条信息，还是能支撑决策的知识？

1 你的原案例

DIKW 金字塔把「从观察到决策」分成四层，每一层回答一个不同的问题：

层是什么回答的问题本课例子
Data 数据原始、离散的观察结果—（还没有上下文）一行行新生记录
Information 信息经过处理、组织、赋予上下文的数据谁 / 什么 / 何时 / 何地「软件工程1班平均年龄 18.1 岁」
Knowledge 知识对信息进一步提炼出的模式与规律如何「年龄与专业存在弱相关」
Wisdom 智慧运用知识做明智判断与战略决策为什么 / 应该怎么做「据此调整招生与培养方案」
2 嵌入理论

可视化在 DIKW 中的位置

关键洞见：可视化主要把 Data 升到 Information，少数场景能升到 Knowledge，但难以跨越到 Wisdom。

  • ✅ Data → Information：把表格「翻译」成可读图形（折线图、柱状图、热图）。
  • ⚠️ Information → Knowledge：模式发现需要统计模型辅助（如机器学习）。
  • ❌ Knowledge → Wisdom：决策与战略超出可视化的能力范围。

Rowley (2007) 的批评：DIKW 是过度简化的层次模型。但它作为教学脚手架仍然最有价值 —— 它逼你先问「我现在手上是数据还是信息」。

3 ⭐ 关键代码
① SVG 金字塔路径：M / L / Z 三个最常用指令 
// 梯形路径：从上到下 4 个点连线，最后闭合
const topW = 60, botW = 120;
const yTop = 20, yBot = 100;
const path = `
  M ${cx - topW/2} ${yTop}
  L ${cx + topW/2} ${yTop}
  L ${cx + botW/2} ${yBot}
  L ${cx - botW/2} ${yBot}
  Z
`;

M(moveto) 抬笔、L(lineto) 画线、Z(close) 闭合 —— 这三个指令能画出绝大多数示意图。模板字符串 ${...} 直接嵌入 JS 变量，比字符串拼接可读得多。

② 事件：为什么必须用 function 而不是箭头函数 
// ⚠️ 必须 function：因为回调里要用 this 访问当前元素
svg.append("g")
  .on("mouseover", function () {
    d3.select(this).select("path")
      .transition().duration(150)
      .attr("fill", d3.color(layer.color).brighter(0.5));
  })
  .on("click", () => showDetail(layer));  // 不用 this，箭头函数 OK

这是 D3 最常见的坑。箭头函数会捕获外层 this，于是 d3.select(this) 选中了错误的元素。只要回调里出现 this，就必须写成 function。

4 可运行演示

点击金字塔的任意一层 —— 右侧会显示该层的定义、典型可视化与所处能力边界。

本节小结

  • DIKW 四层回答四个不同问题：Data（无上下文）→ Information（谁/什么/何时/何地）→ Knowledge（如何）→ Wisdom（为什么）。
  • 可视化的主战场是 Data → Information；再往上一层就要靠统计模型，而不是「把图画得更好看」。
  • D3 事件回调里一旦用到 this，就必须写 function，不能写箭头函数。
自测 · 1 题

把「80 行新生记录」画成「各专业人数柱状图」，这一步主要完成了 DIKW 中哪一次跃迁？

把无上下文的离散记录聚合成「各专业人数」，并赋予「专业」「人数」这层语境，正是 Data → Information。要再升到 Knowledge，需要从信息中提炼出模式（例如「数据科学专业年龄偏大」），单靠看图还做不到。

1.3 数据属性

数据的「类型」决定了哪些视觉通道能用 —— 这是本章最重要的一条规则。

1 你的原案例
类别本课例子说明
类别型姓名、性别无顺序关系
序数型班级、学位有顺序，无间距
数值型年龄、考试成绩定量，可加减乘除
2 嵌入理论

Stevens 测量尺度（1946）：比你原文更精细的 4 类

尺度允许的运算典型示例对应原文
名义 Nominal等价 / 不等价姓名、性别类别型
序数 Ordinal比较大小（> <）等级、班级序号序数型
区间 Interval可加减，不可乘除温度（°C）—
比率 Ratio加减乘除都允许年龄、价格数值型

关键区别：区间尺度没有「真零点」（0°C 不是「没有温度」），比率尺度有真零点（0 元 = 没有钱）。

Mackinlay 视觉通道排序（1986）

把视觉通道按「能承载的信息类型」分成三档：定量型（位置、长度、角度）适合比率 / 区间；顺序型（亮度、密度、饱和度）适合序数；定性型（色相、形状）适合名义。

把比率数据（如年龄）映射到色相是最常见的错配：彩虹色相既不连续、又不 CVD 友好，读者无法从颜色判断大小。同理，把名义数据（如专业）放到位置轴上排序，会凭空造出一个并不存在的顺序。

3 ⭐ 关键代码
① 比例尺选型：属性 ↔ 通道的映射 
// 比率 / 区间数据 → scaleLinear（连续定量）
const x = d3.scaleLinear().domain([0, 100]).range([0, 800]);

// 名义 / 序数数据 → scaleBand（离散分类）
const x = d3.scaleBand()
  .domain(["软件1班", "软件2班", "数据1班"])
  .range([0, 800]);

domain() 是数据域（输入），range() 是值域（输出像素）。选错比例尺是初学者最常犯的错：类别数据用 scaleLinear 会算出没有意义的中间值，比如「0.5 个班」。
口诀：连续定量用 Linear，离散分类用 Band，序数还可以用 Point。

② colormap 选型：顺序 / 定性 / 发散 
// 顺序型（顺序有意义）→ Viridis，CVD 友好且感知均匀
const color = d3.scaleSequential(d3.interpolateViridis);

// 定性型（无顺序）→ schemeTableau10
const color = d3.scaleOrdinal().range(d3.schemeTableau10);

// 发散型（有中点）→ RdBu
const color = d3.scaleDiverging(d3.interpolateRdBu);

常见错误：用彩虹色 interpolateRainbow 去编码数值 —— 既不 CVD 友好，又会在色相转折处造出并不存在的「假边界」。什么时候用发散型：数据有明确的中点（正负、温度相对平均值）。

4 可运行演示

前三个是「属性 → 通道」的正确匹配，第四个是故意做错的对照 —— 对比着看，就知道「错配」到底丢掉了什么。

本节小结

  • Stevens 4 尺度：名义（等价）、序数（可比较）、区间（可加减，无真零点）、比率（有真零点）。
  • Mackinlay 3 档通道：定量型（位置/长度/角度）、顺序型（亮度/密度/饱和度）、定性型（色相/形状）。
  • 匹配规则：比率/区间 → 定量通道；序数 → 顺序通道；名义 → 定性通道。错配会直接丢信息。
自测 · 第 1 题

「专业」（软件工程 / 数据科学）属于名义尺度，按匹配矩阵，它最适合映射到哪一类视觉通道？

名义尺度没有顺序，所以只能用「能表达类别差异」的通道 —— 色相（定性型）是首选。用亮度会暗示一个并不存在的顺序；用位置排序则等于凭空造出「软件工程 > 数据科学」这样的假关系。

自测 · 第 2 题

「0°C 并不代表没有温度」，这句话说明温度属于 Stevens 的哪一种尺度？

区间尺度没有真零点，所以可以比较差值（20°C 比 10°C 高 10°C），但不能说「20°C 是 10°C 的两倍」。比率尺度（如年龄、价格）才有真零点，才允许乘除。

1.4 数据变换

D3 的 8 个数组函数：把「原始数据」加工成「可以画的数据」。

1 你的原案例
#函数用途类比
1map(iterable, mapper)逐元素变换Array.map
2reduce(iterable, reducer, init)归约为一个值Array.reduce
3cross(...iterables, reducer)笛卡尔积—
4merge(iterables)合并为扁平数组Array.flat
5pairs(iterable, reducer)相邻元素对—
6transpose(matrix)矩阵转置—
7zip(...arrays)按位合并—

2 嵌入理论

函数式数据流

这 8 个函数有三个共同点：不可变（输入不变，返回新数组）、纯函数（相同输入 → 相同输出）、可链式（返回值仍是数组，可以接下一层变换）。

  • 为什么函数式？ 可推理（每层独立可测）、可并行（map/reduce 天然并行）、可缓存（纯函数可记忆化）。
  • 与 OLAP 的关系： transpose 做宽/长格式转换，group + rollup 做切片、切块、钻取 —— 这就是数据立方体的雏形。
3 ⭐ 关键代码
① map / filter / reduce 链式组合 
// 一条链算完「男生平均年龄」
const boys = students.filter(s => s.gender === "男");
const avgAge = boys
  .map(s => s.age)                     // ② 提取年龄
  .reduce((sum, a) => sum + a, 0) / boys.length;  // ③ 合计后求平均

链式调用每一步都返回新数组，不会修改原数组。对照命令式写法：后者需要 4 个临时变量加一个 for 循环，函数式一行搞定。性能权衡：每次 map/filter 都会创建新数组，对百万级以上的数组才明显。

② cross：笛卡尔积 
const genders = ["男", "女"];
const majors  = ["软件工程", "数据科学"];
const combos  = d3.cross(genders, majors);
// → [["男","软件工程"], ["男","数据科学"],
//    ["女","软件工程"], ["女","数据科学"]]

笛卡尔积常用在「两两组合」分析（性别 × 专业的人数统计）。第二参 reducer 可选，用来把两个元素先合并成一个。规模提醒：n 个数组的笛卡尔积大小是各数组长度的乘积，很容易爆炸。

③ group 与 rollup：分组保留 vs 分组聚合 
// group：返回 Map，每个 key 下保留所有元素
const byClass = d3.group(students, s => s.class);

// rollup：返回 Map，每个 key 只保留聚合后的值
const countByClass = d3.rollup(
  students,
  v => v.length,     // reducer
  s => s.class       // key 提取函数
);

一句话区分：group 是「分组保留」，rollup 是「分组聚合」。rollup 的第二参是 reducer（这里取长度）。后续第 2 章会用它把扁平表变成树形数据。

4 可运行演示

切换下拉框选择函数 —— 上方是「数据流管」会随之点亮对应的一段，下方是输入与输出。

本节小结

  • D3 的数组函数是不可变 + 纯函数 + 可链式的，可以像管道一样一层层加工数据。
  • map 变形状、filter 选子集、reduce 归约值，三者串起来就是最常见的数据清洗链。
  • group 保留每组元素，rollup 只保留聚合值 —— 前者做树，后者做汇总。
自测 · 1 题

要统计「每个班级有多少人」，同时把每个班的学生名单也保留下来做后续 drill-down，应该用？

group 返回的 Map 里每个 key 都保留了完整元素数组，所以既能 v.length 数人数，又能继续读名单。rollup 会把元素丢掉只留聚合值 —— 数据更紧凑，但不能再 drill-down。

1.5 D3 数据选择器

D3 的核心不是「画图」，而是「把数据绑定到 DOM，并在数据变化时算出该增、该改、该删」。

1 你的原案例

2 嵌入理论

Data-Join 三态模型

把数据数组「绑定」到 DOM 元素上，当数据变化时，多出来的、对得上的、多余的元素会分别落入三个集合：

  • 新数据 > 旧元素 → enter：需要 append 新元素（演示里是绿色）。
  • 新数据 = 旧元素 → update：需要修改属性（演示里是蓝色）。
  • 新数据 < 旧元素 → exit：需要 remove 旧元素（演示里是红色）。
3 ⭐ 关键代码
① .join(enter, update, exit) 三态 
const circles = svg.selectAll("circle")
  .data(currentData)
  .join(
    enter  => enter.append("circle").attr("fill", "green"),  // 新增
    update => update.attr("fill", "cyan"),                 // 更新
    exit   => exit.remove()                                  // 删除
  );

join 的三个回调分别在 enter / update / exit 阶段被调用，比 v3 的 enter().append() + exit().remove() 更简洁，也更不容易漏掉一支。类比：这就是 React 的 diff + patch —— 只不过 React 帮你做了，D3 让你自己写变换函数。

② key 函数：元素身份的稳定器 
// ❌ 不带 key：按 index 绑定，数据重排 → 全部「update」，动画错乱
svg.selectAll("circle").data(newData);

// ✅ 带 key：用唯一字段绑定身份
svg.selectAll("circle").data(newData, d => d.id);
// 与 React 的 key={item.id} 是完全相同的思想

没有 key 时，D3 按 index 绑定身份；数据一重排，所有元素都「换了位置」，过渡动画看起来像是整排重画。带上 key 之后，每个元素知道自己的 id，重排只是 cx 变化，动画自然连贯。

③ select vs selectAll 
// select：只操作 1 个元素（第一个匹配）
const title = d3.select("#title");

// selectAll：批量绑定数据，按顺序一一对应
const bars = d3.selectAll(".bar").data(values);

select 用于「操作单个元素」，selectAll 用于「批量绑定数据」。最佳实践：先用 selectAll 创建占位 selection（此时可能为空），再 .data().join(...) —— 这正是 enter 存在的意义。

4 可运行演示

点三个按钮分别触发 enter / update / exit，注意观察圆点的颜色与位置变化。

本节小结

  • Data-Join 三态：新数据多 → enter（append）、对得上 → update（改属性）、旧元素多 → exit（remove）。
  • .join(e, u, x) 一个方法搞定三态，比手写 enter/exit 更不容易漏。
  • key 函数（.data(d, d => d.id)）让元素在重排后保持身份，是过渡动画自然的前提。
自测 · 1 题

数据从 [1, 2, 3] 变成 [3, 2, 1]（只是顺序变化），如果绑定时不提供 key 函数，会发生什么？

元素数量没变（还是 3 个），所以既不 enter 也不 exit。但因为缺少 key，D3 按索引绑定身份，导致每个圆都觉得「我的数据变了」，于是全部走 update —— 元素没增删，动画却像整排重画。补上 d => d.id 就正常了。
