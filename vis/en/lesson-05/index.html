5.1 The Box Model

Every element is a box — understand it and you can read any layout

To CSS, every element on a page is a rectangular box. Understanding which layers make up that box and how much space each one takes is the first step towards understanding layout.

📦 The four layers of the box model

From the inside out: content → padding → border → margin.

  • content: the area text and images actually occupy, sized by width / height.
  • padding: the space between the content and the border — the background color paints over it.
  • border: the border itself, which also takes up real space.
  • margin: the distance from one box to the next — the background does not paint over it, and adjacent vertical margins may collapse.

The two box-sizing values

ValueWhat width meansActual width taken
content-box (default)The content area onlywidth + padding + border
border-box (recommended)Includes padding and borderexactly width

⭐ Key point: by default width: 200px counts the content area only. Add padding: 20px and border: 2px and the box is actually 244px wide — which is exactly the usual cause of "I set a width and it still overflows". That is why almost every project starts with box-sizing: border-box. 

/* Recommended: let width/height include padding and border */
* { box-sizing: border-box; }

.card {
  width: 240px;
  padding: 16px;        /* padding */
  border: 2px solid #ccc; /* border */
  margin: 10px;          /* margin */
}

⭐ Key point: box-sizing: border-box makes width stand for the final width the box occupies — padding and border squeeze the content inwards rather than pushing the box outwards. That way, when several elements sit side by side, their widths simply add up to the total, which is easy to reason about and cannot overflow.
Common trap: vertical margins between elements undergo "margin collapsing" — two adjacent 20px margins yield 20px, not 40px.

5.2 Document Flow

How do elements arrange themselves by default?

Normal flow is the browser's default typesetting behaviour. Write no layout code at all and elements arrange themselves in normal flow — it is the "baseline state" that every other layout is measured against.

🌊 The two rules of normal flow

Block-level elements stack top to bottom, each taking a full row, and their width fills the parent container by default.
Inline elements sit side by side from left to right, wrapping only when the row runs out of room, with width and height determined by their content.

  • Common block-level elements: div, p, h1, section, li
  • Common inline elements: span, a, strong, em, code
  • Inline-block inline-block: sits side by side like an inline element but accepts width and height — the best of both.

⭐ Key point: leaving the document flow means an element no longer occupies its original position. position: absolute / fixed and float all take an element out of normal flow, and the elements after it "move up" to fill the gap — which is a very common source of a broken layout. Chapter 8 covers positioning properly. 

/* Block-level: takes a full row on its own */
div { display: block; }

/* Inline: sits side by side, sized by content — setting width has no effect */
span { display: inline; }

/* Inline-block: sits side by side AND accepts width and height */
.tag {
  display: inline-block;
  width: 80px;
  height: 32px;
}

⭐ Key point: setting width / height on an inline element has no effect, because its size is determined by its content — one of the most common traps for beginners. When you need "side by side and sized", switch to inline-block.
Note: the newline between inline-block elements renders as a whitespace gap. To remove it, set the parent to font-size: 0, or use modern Flex layout instead.

Switch the layout mode and drag the container width: watch when the boxes wrap, and when they get squeezed instead.

5.3 The display Property

Decides the "identity" an element joins the layout with

display is one of the most important properties in layout: it decides whether an element is block-level, can take a width and height, and how its children are arranged.

ValueLayout behaviourWidth/height?Typical use
blockOwn rowYesContainers, paragraphs, headings
inlineSide by sideNoText fragments, links
inline-blockSide by sideYesTags, buttons
flexOne-dimensional flex insideYesNav bars, toolbars (Ch. 6)
gridTwo-dimensional grid insideYesPage skeletons, card walls (Ch. 7)
noneNot rendered—Hiding an element (removed from the layout tree)

⭐ Key point: display governs not only the element itself but also how its immediate children are arranged — only once you set display: flex or grid on a parent do the children follow flex or grid rules. That is the heart of Chapters 6 and 7.
Note: display: none differs from visibility: hidden — the former leaves the layout entirely, while the latter still occupies its original space. 

/* Make three side-by-side boxes lay out with flex / grid */
.toolbar { display: flex; gap: 10px; }
.wall    { display: grid; grid-template-columns: repeat(3, 1fr); }

/* Hiding an element: the two ways behave differently */
.gone    { display: none; }        /* takes no space */
.invisible { visibility: hidden; } /* still takes space */

⭐ Key point: switching display makes the browser recalculate the layout (reflow), which costs far more than changing only a color. So never animate display — animate opacity / transform instead.

Click different values and observe how the same set of boxes lays out under block / inline / inline-block.
