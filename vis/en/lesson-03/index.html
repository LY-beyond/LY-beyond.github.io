3.1 The 12-Column Grid

Give every element on the page one shared ruler

Chapter 1 said "align things" — but align them to what? The answer is a grid system: slice the page horizontally into equal-width columns and place every element by "how many columns it spans".

📐 The four parts of a grid

Container: the maximum content width, centered.
Columns: usually 12.
Gutters: the spacing between columns.
Margins: the whitespace between the container and the screen edge.

⭐ Key point: why 12 columns in particular? Because 12 divides evenly by 1, 2, 3, 4, 6 and 12 — so you can build "a half (6+6)", "a third (4+4+4)", "a quarter (3×4)" or "two thirds (8+4)" without ever changing the grid. That is the engineering advantage of the number 12, not aesthetic mysticism. 

/* The most basic 12-column grid */
.grid-12 {
  display: grid;
  grid-template-columns: repeat(12, 1fr);
  gap: 24px;               /* this is the gutter */
  max-width: 1180px;
  margin: 0 auto;            /* center the container */
}

/* Place elements by "how many columns they span" */
.col-8 { grid-column: span 8; }   /* two thirds wide */
.col-4 { grid-column: span 4; }   /* one third wide */

⭐ Key point: using span N instead of hard-coded pixel widths means every element rescales automatically when the container width changes and alignment is never lost — and it is naturally compatible with small screens (Chapter 8 covers collapsing columns).

Change how many columns each block spans and watch them stay on the same set of column lines.

3.2 The 8pt Spacing Rhythm

Stop using "made-up" numbers like 13px, 17px and 23px

Besides horizontal columns, the vertical axis needs a ruler too — that is the spacing scale. The industry standard is the 8pt grid: every spacing value is a multiple of 8.

StepValueTypical use
--space-xs4pxBetween an icon and its label
--space-sm8pxItems inside a group, tag spacing
--space16pxCard padding, regular spacing
--space-lg24pxBetween cards
--space-xl40pxBetween page sections

⭐ Key point: the value of a spacing scale is not that "the numbers look nice" — it is that every whitespace decision becomes "pick one of five steps" instead of "make up 17px on the spot".
The direct payoff: a consistent rhythm, batch adjustments at redesign time, and no arguments in a team.
This site's tokens.css is defined exactly that way — you have already seen it. 

:root {
  --space-xs: 4px;
  --space-sm: 8px;
  --space:    16px;
  --space-lg: 24px;
  --space-xl: 40px;
}

/* Use the steps, not made-up values */
.card    { padding: var(--space); }
.section { margin-bottom: var(--space-xl); }
.tag     { margin-right: var(--space-xs); }

⭐ Key point: there is a reason 4px is the smallest step — it is small enough for fine detail and it is half of 8, so "half a standard gap" still belongs to the system, and values like 6px or 10px that break the rhythm never appear.

Switch between "made-up values" and the "8pt scale" and compare how tidy the same content looks.

3.3 Snapping to the Grid

Keep a magnifying glass handy and check alignment as you go

Once the grid is drawn you still need a way to check it: overlay the column lines semi-transparently on the page and any element that has "drifted" becomes visible at a glance.

🔍 Three common ways elements drift

1. Uneven side edges: the container padding and the content padding stack up, so left and right no longer match.
2. Inconsistent card widths: widths hard-coded in pixels instead of using span.
3. Spacing out of proportion: 14px in one place and 22px in another — the rhythm is interrupted.

⭐ Key point: when debugging a layout, turn the grid overlay on before discussing details. Plenty of pages where "something looks off but I can't say what" turn out to be full of problems once the grid is visible.
Practical tip: bind the overlay to a shortcut key (say G to toggle) and check as you build — far cheaper than fixing it afterwards. 

/* Grid overlay: absolute positioning + translucent columns */
.overlay {
  position: absolute;
  inset: 0;
  display: grid;
  grid-template-columns: repeat(12, 1fr);
  gap: 24px;
  pointer-events: none;   /* so it never blocks clicks */
}
.overlay span {
  background: rgba(15,118,110,.10);
}

⭐ Key point: pointer-events: none is essential — without it the overlay swallows every click on the page. A debugging tool must have zero side effects.

Turn the grid overlay on, then switch between "aligned" and "off-grid" and see how obvious the difference becomes.
