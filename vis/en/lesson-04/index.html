4.1 The Holy Grail Layout

Header + two sidebars + main content + footer

"Holy grail layout" is a classic exercise: a header, a footer, a sidebar on each side, and the main content in between — the main content region takes priority, the sidebars have fixed widths, and the whole thing stays fluid.

🏆 The modern implementation: grid-template-areas

Using Grid's "draw a map" syntax, four lines of CSS describe the entire page skeleton — far clearer than the traditional float / negative-margin approach. 

.layout {
  display: grid;
  grid-template-columns: 200px 1fr 180px;
  grid-template-areas:
    "header  header  header"
    "left    main    right"
    "footer  footer  footer";
}

⭐ Key point: readability is the biggest advantage of grid-template-areas — you can "see" what the page looks like straight from the CSS.
Small-screen adaptation: just redraw the areas as a single column in a media query (every row uses the same name) and the whole page stacks vertically, without touching the HTML at all.

👉 See it in the case

The case’s skeleton is a simplified holy grail — nav + main + footer — at 9.2 Skeleton and grid; lab steps 1–2 build it.

.layout {
  display: grid;
  grid-template-columns: 200px 1fr 180px;
  grid-template-areas:
    "header header header"
    "left   main   right"
    "footer footer footer";
  gap: 12px;
}
.header { grid-area: header; }
.left   { grid-area: left; }
.main   { grid-area: main; }
.right  { grid-area: right; }
.footer { grid-area: footer; }

/* Small screens: stack everything into one column */
@media (max-width: 700px) {
  .layout {
    grid-template-columns: 1fr;
    grid-template-areas:
      "header" "left" "main" "right" "footer";
  }
}

⭐ Key point: each string in areas represents "one grid row", and a name that spans several columns is written that many times. Getting the cell count wrong invalidates the entire rule, so keep the columns lined up.

4.2 The Card Wall

The most common layout on listing pages

The card wall (card grid) appears on almost every website: a set of equal-width blocks whose column count changes with the screen width.

⭐ Key point: one line of CSS does it — grid-template-columns: repeat(auto-fit, minmax(240px, 1fr)). It solves three problems at once: an adaptive column count, a minimum column width and evenly shared leftover space, with no media query at all.
This site's portal home page uses exactly that line.

👉 See it in the case

The portfolio wall adapts its column count with auto-fit — 9.6 Card wall. Lab step 6 checks for at least two columns.

.wall {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(240px, 1fr));
  gap: 20px;
}

/* The card itself: flex keeps the "bottom button" pinned to the base */
.card {
  display: flex;
  flex-direction: column;
  padding: 20px;
}
.card .cta { margin-top: auto; }

⭐ Key point: margin-top: auto is the usual trick for pushing an element inside a card "all the way to the bottom" — in a flex column layout, an auto margin swallows every bit of leftover space. Also, the 1fr in minmax(240px, 1fr) cannot be dropped, or the cards will not stretch and whitespace will show up on the right.

Adjust "minimum column width" and "gap" and watch how the number of cards and the sense of breathing room change.

4.3 The Dashboard Grid

How modules of different sizes coexist

The hard part of a dashboard is that its modules come in different sizes: a large chart needs to span columns, while a small metric occupies a single cell.

⭐ Key point: still Grid, but with the idea of a fixed column count plus local spanning — first divide the container into a fixed N columns (say 4), then let large modules use grid-column: span 2 and full-width modules span 4.
That is far more flexible than hard-coding a width per module, and it stays aligned by construction.

👉 See it in the case

The numbers strip hands differently sized cells to differently important data — a miniature dashboard grid, at 9.7 The numbers strip.

.dashboard {
  display: grid;
  grid-template-columns: repeat(4, 1fr);   /* baseline: 4 columns */
  gap: 14px;
}

.w2 { grid-column: span 2; }   /* spans two cells */
.w4 { grid-column: span 4; }   /* full row */

/* On small screens drop to 2 columns; the spans shrink automatically */
@media (max-width: 720px) {
  .dashboard { grid-template-columns: repeat(2, 1fr); }
  .w4 { grid-column: span 2; }
}

⭐ Key point: using span rather than a hard-coded 1 / 3 means the same classes still hold once the small screen drops to 2 columns (span 2 is now a full row), so you only have to override a handful of "extra-wide" modules.
