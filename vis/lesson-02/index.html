2.1 先问目标与优先级

别急着打开编辑器，先回答三个问题

布局的本质是把内容按重要性排布到空间里。所以设计布局的第一步不是 CSS，而是想清楚内容的主次。

❓ 动手前必答的三个问题

1. 这个页面要让用户做什么？（唯一目标，例如"报名课程"）
2. 最重要的一件事是什么？（它应该最大、最显眼）
3. 哪些是次要信息？（排在后面、视觉弱化）

从内容清单到布局

  1. 列清单：把页面要放的所有内容写下来（标题、图片、按钮、说明…）
  2. 排优先级：每项打 1～3 星，星星多的排前面、给更大空间
  3. 做分组：把相关的项归到一起（对应第 1 章的亲密性）
  4. 定顺序：按"用户视线会怎么走"决定上下顺序

⭐ 关键点：布局问题，十有八九是优先级问题。 如果一个页面看起来"乱"，往往不是 CSS 写错了， 而是所有内容都在抢注意力——没有主次，就没有秩序。 

/* 优先级 → 视觉权重的映射（用变量固定下来） */
:root {
  --w-primary:   700;   /* 一级：大字号 + 加粗 + 主色 */
  --w-secondary: 500;   /* 二级：正常 */
  --w-tertiary:  400;   /* 三级：灰色弱化 */
}

.card-title { font-size: 22px; font-weight: var(--w-primary); }
.card-desc  { font-size: 14px; color: var(--c-text-soft); }

⭐ 关键点解释：把"优先级"翻译成可复用的视觉档位（字号 / 字重 / 颜色）， 而不是每个元素单独调——这样页面再加内容也不会乱。

用 ↑ ↓ 调整内容顺序，观察页面骨架如何随优先级重排。

2.2 阅读模式与视线路径

用户的眼睛会怎么"走"过你的页面

人看网页不是"逐字读"，而是扫描。大量眼动实验总结出几种典型的视线路径，了解它们就能把重要内容放在"必经之路"上。

模式路径适合的页面
F 型先横向扫一遍标题 → 再横向扫一遍 → 最后沿左侧纵向快速下拉以文字为主：文章、文档、列表
Z 型左上 → 右上 → 左下 → 右下（对角线）视觉化落地页、海报式页面
古腾堡图左上（主视觉区）→ 右上 → 左下 → 右下（行动区）对称型页面、卡片式版面

⭐ 关键点：把最重要的内容放在视线路径上——
· F 型页面：关键信息尽量靠左、靠上；
· Z 型页面：把"行动按钮（CTA）"放在路径终点（右下）；
· 反过来，如果你把重点放在路径之外，用户可能根本不会看到它。 

/* Z 型落地页：用 Grid 把 CTA 放到路径终点 */
.landing {
  display: grid;
  grid-template-columns: 1fr 1fr;
  grid-template-areas:
    "brand   nav"
    "hero    hero"
    "text    cta";   /* ← 行动按钮落在右下，符合 Z 型终点 */
}

⭐ 关键点解释：这就是第 4 章"布局模式"与本章的结合点—— 先由视线路径决定"什么放在哪"，再由 Grid / Flex 把它实现出来。

切换三种阅读模式，观察视线路径在同一个骨架上的走向，以及"重点区"应该在哪儿。

2.3 线框图：先骨架后皮肤

用灰块把结构定下来，再谈颜色和文案

线框图（wireframe）是用灰色方块和占位文字画出的页面结构草图——只关心"哪块放哪、占多大"，不关心长得好不好看。

✏️ 为什么一定要先画线框？

1. 改起来便宜：结构没定就做视觉，一旦推翻要重做全部样式。
2. 逼你想清楚：画不出灰块，说明你还没想明白这块内容要放什么。
3. 沟通成本低：给老师/队友看灰块，对方更容易提结构意见，而不是纠结颜色。

⭐ 关键点：定骨架的顺序建议是 ① 分区块（页头/主体/页脚）→ ② 定每块占几栏 → ③ 再填内容 → ④ 最后上色。
常见错误：一上来就调颜色和阴影，结果发现结构不对，全部推翻重来。 

/* 线框阶段：只用灰块和虚线，把结构占位先搭出来 */
.wire-block {
  background: #e8e6e1;
  border: 1px dashed #b8b2a8;
  border-radius: 6px;
  min-height: 60px;
}

/* 结构定了，再替换成真实样式 —— 骨架不用改 */
.hero { background: var(--c-surface); border-radius: 12px; }

⭐ 关键点解释：线框图到成品的转换，理想情况下只改"皮肤"（颜色/字号/圆角），不改"骨架"（分栏与顺序）。 如果你发现必须动骨架，说明线框阶段想得还不够清楚。

切换「线框图 / 高保真」，观察同一套骨架的两种呈现——注意骨架完全没变。
