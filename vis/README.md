# 页面布局教学平台

一个**零依赖、零构建**的教学网站：纯 HTML + CSS + JavaScript（原生 ES Modules）。
**中英双语**，两种语言内容一一对应。

主题：**如何设计一个 web 页面的布局**。课程分三部分共 9 章：
**设计篇**回答"怎么设计"，**实现篇**回答"怎么写代码"，**实战篇**用一个完整案例把两者串起来。

## 🧭 课程主线：知识点 ⇄ 案例 双向贯通

本课程不是「先讲 8 章知识点、最后附送一个案例」，而是**由同一个案例把 9 章串成一条线**：

```
目标        →  骨架     →  刻度      →  导航    →  首屏   →  关于我  →  作品集  →  数据    →  响应式
需求/优先级     12 列栅格    8pt 间距     Flex+sticky  层次/平衡   4:8 双栏   auto-fit   信息层级   移动优先
第 1、2 章      第 1、3 章   第 1、3 章    第 1、6、8 章  第 1、7、8 章 第 1、5、7 章 第 1、6、7 章 第 1、3、4 章 第 3、8 章
```

它有**四个可见的落点**，读者无论从哪一章进来都能看到这条主线：

| 落点 | 位置 | 作用 |
|---|---|---|
| **「课程主线」时间轴** | 门户首页 `#storyline` | 8 个步骤卡片一眼看完，每张标注「用到第几章」，点进去直达对应步骤 |
| **「案例抓手」卡片** | 第 1–8 章 **30 个小节**的「讲解」末尾（30 × 2 = 60 张，中英各一份） | 正向：这个小节在第 9 章的**哪一步**、实战环节的**哪一关**用到 |
| **「这一步用到了」卡片** | 第 9 章 **8 个步骤**的「讲解」开头（8 × 2 = 16 张） | 反向：这一步用到了前面**哪几章**，链接可直接跳到那一节 |
| **「这段代码用到」角标** | 第 9 章 **8 个步骤**的「关键代码」tab 顶部（8 × 2 = 16 张） | 读到代码时顺手就知道**这个写法出自哪一章**（`7fr 5fr` ← 第 7 章、`clamp()` ← 第 8 章、`margin-top: auto` ← 第 6 章） |

合起来是 **92 处交叉引用**（76 张卡片 + 16 张代码角标）+ **268 处带锚点链接**
（全站 618 处站内链接，`node link-check.mjs` 实测**失效 0 处**），
并且每个章节页的小卡片都指向 `../lesson-09/#ch-9-X` 或 `../practice.html` —— 知识点与案例**互相认识**。

此外，各章的**演示素材也统一到同一个案例**：第 1 章讲「对齐」用的示例数据是作品集的
顶部导航 / 首屏 / 卡片墙 / 数据区，第 8 章卡片墙演示里的 6 张卡片用的是这 6 个作品名 ——
全站只有一位主角（李雷 / Alex Chen），不再出现与案例无关的占位人名，学生一路看下来始终在调**同一个页面**。

> 为什么这样设计：设计篇与实现篇按**知识点**组织，方便"我想单独查 Flexbox"；
> 而主线通过**交叉引用**呈现，方便"我在做作品集，这块该用哪一章"。
> 两者兼顾，也不必为了案例化而牺牲知识的可检索性。

## ▶️ 本地运行

因为使用了 ES Modules（`import`），**不能直接双击 `index.html`**，需要起一个静态服务器：

```bash
cd Visualization
python -m http.server 8080
```

然后浏览器打开 <http://localhost:8080>。

> 也可以用 VSCode 的 Live Server 插件，右键 `index.html` → Open with Live Server。

## 📝 学习成果检验（答题系统）

门户首页的「📝 测验」区块内嵌了一套纯前端答题系统（**中英双语**），
用来在学完 9 章后检验掌握程度。

| 项 | 说明 |
|---|---|
| **题库** | `quiz-data.js`（中）/ `en/quiz-data.js`（英）：各 **30 道选择题 + 20 道判断题**，覆盖第 1–9 章全部知识点，每题带章节、知识点、答案与解析 |
| **双语做法** | **引擎只有一份** `quiz.js`：界面文案集中在开头的 `T` 表（默认中文），`en/quiz-ui.js` 用 `window.QUIZ_UI` 覆盖成英文 —— 逻辑改一处，中英不会各自漂移（与 `lesson-core.js` 同思路）；两份题库**逐题一一对应**（同一套 id / chapter / answer） |
| **抽题** | 每次随机抽 **8 道选择题 + 2 道判断题**；按章节分桶后轮转取题，保证一局覆盖 ≥ 8 个不同章节，不会全落在同一章 |
| **洗牌** | 题序、选项顺序都会打乱；答案以下标存储，洗牌后重算，避免靠「答案总在 B」蒙对 |
| **判分** | 每题 10 分、满分 100；提交后给出得分环、评级、用时、**逐题解析**与**薄弱章节回看链接** |
| **错题本** | 答错的题自动收录（累计错误次数 + 上次所选），之后答对自动移出；支持「重做错题」与逐条移除 |
| **历史成绩** | 保留最近 20 次「随机测验」成绩，附平均分 / 最高分；重做错题不计入，避免刷分 |
| **存储** | `localStorage` 两个键：`layout-course-quiz-wrong` / `layout-course-quiz-history`（与 `layout-course-lang` 同一命名风格，仅存本机） |
| **无障碍** | 选项是原生 `<button>`（键盘可达、`aria-pressed` 标注选中），提示用 `role="status"` 播报，正误同时用「颜色 + ✓/✗」双重编码 |

> ⚠️ **前端方案的固有限制**：题库随静态文件一起下发，**答案对用户可见**（F12 即可查看），
> 也没有跨设备同步成绩的能力。因此本系统定位为「**自学自测**」，不是防作弊的正式考试。

### 加题 / 改题

1. 在 `quiz-data.js`（中）**和** `en/quiz-data.js`（英）的 `choice`（选择题）或 `judge`（判断题）数组里增删题目，
   两份要保持同一顺序、同一个 `id` 与 `answer`：
   ```js
   { id: 'c-31', chapter: 8, topic: 'z-index', q: '题干……', options: ['A', 'B', 'C', 'D'], answer: 0, explain: '解析……' }
   { id: 'j-21', chapter: 8, topic: 'z-index', q: '判断题干……', answer: false, explain: '解析……' }
   ```
2. `id` 必须**全局唯一**（错题本、历史成绩都按 id 认题），`chapter` 取值 1–9，
   选择题的 `answer` 写选项**下标**，判断题的 `answer` 写 `true / false`。
3. 新增界面文案时，记得在 `quiz.js` 的 `T` 表和 `en/quiz-ui.js` 里**同时加键**。
4. 跑一次自检：

   ```bash
   node quiz-check.mjs
   ```

   输出 `✓ 校验通过` 即为合格：它会检查两份题库各自的合法性，断言中英**逐题一一对应**，
   并核对英文文案表的键与 `T` 表完全一致（漏一个键，英文页面会把 `[key]` 直接显示出来）。

> 英文门户在 `en/index.html` 的 `#quiz` 处放的是同一套答题系统（英文题库 + `en/quiz-ui.js`），
> 结构计数与中文版一致 —— `parity-check.mjs` 照样通过。

## 🧪 实战环节（动手练习）

从门户顶栏的「🧪 实战」进入独立工作台 `practice.html`：
按**第 9 章的真实案例**（个人作品集网站）自己动手写一遍，共 **8 个环节**，
每个环节都有要求、提示和检查点，最终长成一个能导出成文件的完整页面。

| 项 | 说明 |
|---|---|
| **案例** | `practice-data.js`：8 个环节直接对应第 9 章的 9.1–9.8，形成「先看老师做 → 自己做一遍」的闭环 |
| **环节** | 搭骨架 → 容器/栅格/间距档位 → 导航栏 → 首屏 Hero → 关于我双栏 → 作品卡片墙 → 数据统计 → 响应式重构 |
| **起始代码** | 第 1 个环节从「空格子」开始；此后每个环节的起点就是**上一环节的成果**，代码是连续累积的（不是 8 个孤立小练习） |
| **编辑器** | HTML / CSS 两个 `<textarea>` 分栏；Tab 插两空格、回车继承缩进；不用写 `<style>`，也不必重复 `box-sizing` 等重置 |
| **实时预览** | `<iframe srcdoc>` **就地更新、不闪屏**；iframe 按真实宽度布局后等比缩放，所以「桌面 1180 / 平板 768 / 手机 375」切档能直接看到媒体查询生效 |
| **提示** | 分级解锁：思路 → 关键属性 → 兜底片段；另有折叠的「语法速查」（本环节会用到的属性 + 一句话解释） |
| **检查点** | 每关 7–9 项，在 **1180px 宽度**下测量真实渲染结果（计算样式 + 元素几何），**不比对代码文本** |
| **存档** | 自动草稿（刷新后继续）+「我的作品」手动存档（最多 10 份，可载入继续 / 删除） |
| **导出** | `Blob` + `<a download>` 导出成独立 `.html`，双击即可打开 —— 可以直接当作业交 |

### 检查点能查出什么？

判定用的是浏览器的**最终渲染结果**，所以「怎么写」是自由的，只要求「效果对」：

| 类型 | 例子 | 对应章节 |
|---|---|---|
| `exists` / `count` | 存在 `section.hero`；卡片墙至少 4 张卡 | 第 2、9 章 |
| `style` | `getComputedStyle(nav).display === 'flex'` | 第 5、6、7 章 |
| `columns` / `colsCompare` | 正好 12 列；左栏比右栏宽（7fr 5fr） | 第 3、7 章 |
| `sameRow` | 至少 2 张卡片在同一行（比较 `rect.top`） | 第 6、7 章 |
| `centered` | 容器左右留白差 ≤ 4px（真的居中了） | 第 1、3 章 |
| `cssVar` | `--space-lg` 等于 `24px`（间距体系落实了） | 第 3 章 |
| `atWidth` | **切到 375px 再测**：375 单列、1180 两栏 | 第 8 章（响应式） |

### 加 / 改案例

1. 在 `practice-data.js`（中）**和** `en/practice-data.js`（英）的 `steps` 数组里增删环节。
   两份要保持同一顺序、同一个 `id`，且**检查点结构完全一致**（类型 / 选择器 / 数值；只有提示文案不同）。
   每个环节需要 `task`（要求）、`hints`（≥ 2 级提示）、
   `syntax`（语法速查）、`checks`（检查点）、`solution`（参考答案）。
2. 约定：**起始代码 = 上一环节的参考答案**；只重构 CSS 的环节可以把 `solution.html` 留空表示沿用上一环节。
3. 跑一次自检：

   ```bash
   node practice-check.mjs
   ```

   它会检查字段完整性、**检查点里的选择器能否在参考答案 HTML 里找到**（类名拼错会让学生永远过不了关）、
   **光标锚点能否在起始代码里定位**，以及后面的环节有没有丢掉前面用到的类名。

5. 想核对／手工粘贴各环节答案，跑：

   ```bash
   node practice-answers.mjs
   ```

   会在同目录生成 `practice-answers.md`（从 `practice-data.js` 自动导出，**不要手改**）：
   每个环节都给了「起始代码（对照用）」和「✅ 答案 · HTML / CSS」，CSS 是**完整累积版**，整段替换即可。

4. ⚠️ 改过检查点后，务必在浏览器里点一次「查看参考答案 → ✅ 检查这一环节」，
   确认参考答案能**全项通过**。`practice-check.mjs` 只能做静态可达性检查，
   真正的样式与尺寸判定必须由浏览器完成。

> ⚠️ **必须接受的限制**（纯前端方案的边界）：
> ① 没有「编译」——只有实时渲染，CSS 写错不报语法错，只是「没效果」；
> ② 不能批改代码质量，只判定渲染结果是否满足检查点；
> ③ 参考答案随静态文件下发（F12 可见），定位是「动手练习」而不是考试；
> ④ 没有后端，作品只能存在本机 + 自己导出 `.html`，无法提交给老师。

## 🧩 如何新增一节 / 一章

### 加一个小节

1. 在 `lesson-0X/index.html` 里复制一个 `<article class="chapter" id="ch-X-Y">` 块，
   改标题与内容（保持三个 `.tab-panel` 结构）。
2. 在左侧 `.chapter-nav` 的 `<ul>` 里加一个 `<a data-chapter="ch-X-Y">`。
3. 在 `lesson-0X/lesson.js` 里注册演示：

```js
window.DEMOS['d-X-Y'] = function (mount) {
  mount.innerHTML = `<div class="demo-card"> ... </div>`;
  // 绑定交互 ...
};
```

4. 页面里放占位符：`<div class="demo-mount" data-demo="d-X-Y"></div>`
5. **同步英文版**：在 `en/lesson-0X/index.html` 加同样的结构与占位符，
   并在 `en/lesson-0X/lesson.js` 里注册同名 demo（保证两版结构与 demo 数量一致）。

> ⚠️ 演示必须注册在 `initLesson()` **之前**。
>
> ⚠️ 改完中文**务必同步英文**，然后跑 `node parity-check.mjs` 复核。

### 加一整章

1. 复制 `lesson-09/` 整个目录为 `lesson-10/`。
2. 改 `index.html` 里的标题、`data-current`、`.tabs` 链接、pager。
3. 改 `lesson.js` 里的 demo 名称与 `initLesson('lesson-10')`。
4. 在门户 `index.html` 加一张卡片，并更新其余各章顶栏 tabs。
5. **英文版同样复制一份到 `en/lesson-10/`**，改英文标题与文案；
   并更新 `en/index.html` 与 `en/lesson-01…09/index.html` 里的顶栏 tabs。

## 🛠️ 技术要点

- **无框架、无打包、无 npm** —— 浏览器直接运行，改完刷新即生效。
- **设计令牌化**：配色 / 间距集中于 `tokens.css`。
- **样式复用**：`lesson.css` 一份服务 9 章。
- **逻辑复用**：`lesson-core.js` 统一 Tab / 导航 / Demo 注入。
- **ES Modules**：各章 `lesson.js` 通过 `import` 引入公共引擎。
- **课程主线靠"交叉引用"而不是"目录重构"**：三处交叉引用都是直接写在 HTML 里的普通元素 —— `.case-note`（第 1–8 章「讲解」末尾的「案例抓手」+ 第 9 章「讲解」开头的「这一步用到了」，橙色）与 `.code-source`（第 9 章「关键代码」tab 顶部的「这段代码用到」，蓝色），样式都在 `lesson.css`，指向 `../lesson-09/#ch-9-X` 等锚点。`parity-check.mjs` 保证中英两版数量与结构一致，`link-check.mjs` 保证这些锚点不断链。**加新小节时照抄一个元素即可，无需任何脚本。**
- **演示素材与案例同源**：第 1 章 `d-1-1`「对齐」演示的示例数据、第 8 章卡片墙演示里的 6 张卡片，用的都是作品集案例里的区块名与作品名 —— 学生一眼看出"这是案例的哪一块"，不会因为冒出无关人名而分神。
- **改动后跑一遍自检**：`node parity-check.mjs && node link-check.mjs && node quiz-check.mjs && node practice-check.mjs`（PowerShell 5.1 下把 `&&` 换成 `;`）。四个脚本都不联网、不写文件，纯静态检查。
- **中英双语**：英文版在 `en/`，与中文版**同构**；`node parity-check.mjs` 逐页校验两版结构一致。
- **切换器刻意用普通 script**：`i18n.js` 不用 ES Module —— 这样即使用 `file://` 直接打开（module 会被浏览器 CORS 拦截），**语言切换仍然可用**。
- **答题系统同样用普通 script**：`quiz-data.js` / `quiz.js` 沿用同一取舍，门户首页双击打开也能答题。
- **答题系统 / 实战环节都是中英共用一个引擎**：界面文案集中在各自 `*.js` 开头的 `T` 表（默认中文），`en/quiz-ui.js` 与 `en/practice-ui.js` 用 `window.QUIZ_UI` / `window.PRACTICE_UI` 覆盖成英文；题库与案例则是两份数据文件，`node quiz-check.mjs` / `node practice-check.mjs` 会断言它们**逐题 / 逐环节一一对应**（id、章节、答案、检查点结构）以及文案表键名完全对齐。
- **实战环节同样用普通 script**：`practice-data.js` / `practice.js` 不用 ES Module，`file://` 双击 `practice.html` 也能用。
- **预览沙箱刻意不给 `allow-scripts`**：`allow-scripts` + `allow-same-origin` 是已知的**沙箱逃逸组合**（iframe 内的脚本能把自己重新加载成非沙箱文档），而「自动检查」又必须靠 `allow-same-origin` 同源读取 iframe 文档（`getComputedStyle` / `getBoundingClientRect`）—— 二者只能选一个。本案例是纯 HTML/CSS 练习，所以选「脚本不执行、检查可用」。注入前还会用 `DOMParser` 剥掉 `<script>` / `on*` / `javascript:`（导出的 `.html` 同理），并且会在预览下方**明确提示「已移除 N 个 script / N 处内联事件」**，避免学生对着没反应的预览发懵。万一浏览器拒绝同源读取，引擎会降级成「只预览、不检查」并给出提示。
- **预览用真实宽度布局 + `transform: scale()` 缩放**：缩放只改变视觉大小、不改变布局宽度，所以媒体查询、`vw`、`position: fixed` 都真实生效 —— 这也是「手机 375」切档能验证响应式的原因。
- **相对路径**：全站使用相对路径，可直接部署到 GitHub Pages 子路径。

## ✅ 第 9 章附带的「设计自查清单」

布局做完后逐条检查（这也是全课程设计篇的浓缩）：

1. 所有元素都对齐到同一条线了吗？
2. 相关的内容靠得更近了吗？（组内 &lt; 组间）
3. 最重要的内容最显眼吗？字号跨度够吗？
4. 同类元素的圆角 / 阴影 / 颜色一致吗？
5. 分组清晰到"不需要文字解释"吗？
6. 左右视觉重量是否平衡？留白是否有节奏？
7. 间距是否都来自同一套档位？
8. 手机宽度下内容是否还能顺畅阅读？

## 🚀 部署到 GitHub Pages

1. 推到一个 GitHub 仓库（如 `Visualization`）。
2. 仓库 **Settings → Pages → Source** 选 `Deploy from a branch`。
3. 分支选 `main`，目录选 `/(root)`，保存。
4. 稍等片刻访问 `https://<用户名>.github.io/<仓库名>/`。

> 因为路径全是相对的，**无需任何额外配置**。

上线后有两个入口：

- 中文：`https://<用户名>.github.io/<仓库名>/`
- 英文：`https://<用户名>.github.io/<仓库名>/en/`
