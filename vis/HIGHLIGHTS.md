# 页面布局教学平台 · 项目亮点

> 一个**零构建**的静态教学网站：纯 HTML + CSS + 原生 JavaScript，中英双语；
> 除内置的一个 17 KB 力导向库（d3-force）外没有运行时依赖 —— 双击就能打开，也能直接托管到 GitHub Pages。
>
> 主题是「如何设计一个 web 页面的布局」：三篇 9 章、38 个小节，配套答题系统、实战工作台与课程知识图谱。

## 亮点 ① 课程设计：一个案例贯穿 9 章

多数教程是「先讲 8 章知识点、最后附送一个案例」，学生学到一半就忘了这些知识最终要用来干什么。
本站反过来——**用同一个「个人作品集网站」把 9 章串成一条线**：

```
目标        →  骨架     →  刻度      →  导航    →  首屏   →  关于我  →  作品集  →  数据    →  响应式
需求/优先级     12 列栅格    8pt 间距     Flex+sticky  层次/平衡   4:8 双栏   auto-fit   信息层级   移动优先
第 1、2 章      第 1、3 章   第 1、3 章    第 1、6、8 章  第 1、7、8 章 第 1、5、7 章 第 1、6、7 章 第 1、3、4 章 第 3、8 章
```

这条主线有**四个看得见的落点**，读者从任何一章进来都能看到它：

| 落点 | 位置 | 作用 |
|---|---|---|
| 「课程主线」时间轴 | 门户首页 `#storyline` | 8 张步骤卡片一眼看完，每张标注「用到第几章」，可直达 |
| 「案例抓手」卡片 | 第 1–8 章 **30 个小节**的讲解末尾 | **正向**：这一节在第 9 章哪一步、实战哪一关用到 |
| 「这一步用到了」卡片 | 第 9 章 **8 个步骤**的讲解开头 | **反向**：这一步用到前面哪几章，链接可跳回那一节 |
| 「这段代码用到」角标 | 第 9 章 **8 个步骤**的关键代码顶部 | 读到代码就知道这个写法出自哪一章（`7fr 5fr` ← 第 7 章、`clamp()` ← 第 8 章） |

**再加上演示素材同源**：全站只有**一位主角**——李雷（英文版 Alex Chen），第 1 章的示例数据、第 9 章各个演示、实战环节的案例都是同一个人；第 1 章讲「对齐」用的示例数据就是作品集的四个区块，第 8 章卡片墙演示里的 6 张卡片就是这 6 个作品名。学生一路看下来，始终在调**同一个页面**。

> **为什么不干脆按案例重构目录？** 因为设计篇与实现篇按**知识点**组织更好查（"我想单独查 Flexbox"），
> 而主线通过**交叉引用**呈现更好用（"我在做作品集，这块该看哪一章"）。两者兼顾，不必为了案例化而牺牲知识的可检索性。

## 亮点 ② 38 个交互演示：讲完立刻能上手看

每个小节都由**三个 Tab** 组成，学生不用来回切页面：

| Tab | 内容 |
|---|---|
| 📖 讲解 | 原则与代码的关系，讲"为什么" |
| 💻 关键代码 | 带语法高亮的代码；第 9 章还附「这段代码用到哪几章」角标 |
| 🎮 交互演示 | **可操作**的实时演示（切状态、拖滑块、点按钮），不是静态截图 |

演示用的是真控件，例如：

- **第 1 章「对齐」（d-1-1）**：切换「未对齐（凭感觉摆）/ 已对齐（共用一条线）」，配合一条红色虚线参考线，一眼看出左边缘是否真的落在同一条线上；
- **第 1 章「亲密性」（d-1-2）**：拖「组内间距 / 组间间距」两个滑块，观察"分组感"什么时候才真正出现；
- **第 3 章「12 列栅格」（d-3-1）**：用滑块调整各区块的跨列数，看布局如何随列线变化；
- **第 3 章「对齐检查」（d-3-3）**：勾选「显示栅格叠加层」，验证元素是否都落在同一套列线上；
- **第 9 章各步骤**：每步都能调参数（容器宽度、列间距、断点）并实时看结果。

技术上有两点讲究：演示**懒加载**（切到演示 Tab 才渲染，首屏更快），且**只渲染一次**（来回切 Tab 不会重置你调好的状态）。

## 亮点 ③ 中英双语：一份引擎 + 一张文案表

这不是"把中文复制一份改成英文"，而是**架构层面的双语**：

```
       中英共用               仅英文
   ┌──────────────────┐   ┌────────────────────────┐
   │ quiz.js          │   │ en/quiz-ui.js          │
   │ practice.js      │◄──│ en/practice-ui.js      │
   │（逻辑只有一份）    │   │ window.QUIZ_UI /       │
   └────────┬─────────┘   │ window.PRACTICE_UI     │
            │ 读文案表      └────────────────────────┘
   ┌────────▼─────────┐
   │ T 表（默认中文）   │  quiz 84 键 / practice 73 键
   └──────────────────┘
```

- **引擎单份**：改一处逻辑，中英同时生效，不存在"两份代码慢慢分叉"的问题；
- **文案覆盖表**：英文版只提供键值覆盖；`node quiz-check.mjs` 会**逐键断言**英文表与 `T` 表完全对齐（少一个键，页面就会露出 `[key]` 这种原文）；
- **数据分两份、脚本保证对齐**：题库与实战案例各有中英两份（英文题干/提示/解析要地道），自检脚本断言它们**逐题 / 逐环节一一对应**（同一套 id、chapter、答案下标、检查点结构）；
- **页面同构**：`en/` 与根目录结构完全一致，`node parity-check.mjs` 逐页比对 10 项结构指纹，防止"改了中文忘了英文"。

> 一个刻意的取舍：`i18n.js` / `quiz.js` / `practice.js` **不用 ES Module**，而是普通 `<script>`。
> 因为 `<script type="module">` 在 `file://` 下会被 CORS 拦掉——这样站点拷到 U 盘、双击打开，语言切换与答题系统照样能用。

## 亮点 ④ 答题系统：抽题 + 错题本 + 历史成绩

门户首页就是一套完整的测验系统（`#quiz`）：

- **50 道题库**（30 选择题 + 20 判断题），覆盖全部 9 章；
- **每轮随机抽 10 题**：8 道选择 + 2 道判断，且**尽量分散在不同章节**——避免一套卷子全砸在同一章上；
- **作答体验**：进度条、上一题 / 下一题、随时交卷、未答警示；
- **交卷即出结果**：总分、逐题回顾（你的答案 / 正确答案 / 解析），解析会指回对应章节；
- **错题本 + 历史成绩**：答错的题自动进错题本，成绩自动记入历史，**全部存在浏览器本地**（localStorage），不联网、无后端、无账号。

> `quiz-check.mjs` 会校验 id 全局唯一、`chapter` 取值合法、选择题答案是合法下标、判断题答案是布尔值——
> 这些都是"错一个就整题判错"的地方。

## 亮点 ⑤ 实战工作台：在浏览器里写代码，并**自动判分**

`practice.html` 是一个独立的"练习工作台"，把整个案例拆成 **8 个环节**，像闯关一样推进：

**左题右码 + 实时预览**：左边是题目要求、检查清单、提示；中间是 HTML / CSS 两个编辑器；右边是实时预览（改代码即刷新）。

**57 个检查点，是真的在"量"你的页面**——不是让你自己对答案：

```
用户代码 → 注入沙箱 iframe → 引擎用 getComputedStyle / getBoundingClientRect
        → 逐条断言（如：.grid 的 display === 'grid'、卡片间距在 24±2px、窄屏下列数变 1）
        → 给出「8 / 8 项通过」或「第 3、5 项未通过」
```

- **三档预览宽度**：桌面 1180 / 平板 768 / 手机 375，可以亲眼验证响应式；
  检查时**固定用 1180 宽**，保证判分结果与学生当前预览档位无关（可复现）；
- **预览缩放用 `transform: scale()`**：只改变视觉大小、不改变布局宽度，所以媒体查询、`vw`、`position: fixed` 都**真实生效**——这正是"手机 375 档"能验证响应式的原因；
- **分级提示**：卡住可以一级一级看提示，而不是一次给答案；
- **参考答案**：填入前要**二次确认**（避免一键抹掉自己写的代码）；
- **存档 / 导出**：进度自动存在本地，还能把当前代码导出成 `.html` 拿走。

**安全上的取舍（有明确理由）**：预览沙箱**刻意不给 `allow-scripts`**。因为 `allow-scripts` + `allow-same-origin` 是已知的**沙箱逃逸组合**（iframe 里的脚本能把自己重新加载成非沙箱文档），而"自动检查"又必须靠 `allow-same-origin` 同源读取 iframe 文档——两者只能选一个。本案例是纯 HTML/CSS 练习，所以选"脚本不执行、检查可用"。
配套还做了：注入前用 `DOMParser` 剥掉 `<script>` / `on*` / `javascript:`（导出时同样处理），并在预览下方**明确提示「已移除 N 个 script / N 处内联事件」**（避免学生对着没反应的预览发懵）。万一浏览器拒绝同源读取，引擎会**降级成"只预览、不检查"并给出提示**，而不是静默失效。

## 亮点 ⑥ 工程品质：没有构建步骤，却有完整的工程约束

| 做法 | 说明 |
|---|---|
| **零构建** | 没有 `node_modules`、没有打包器、没有转译；改完刷新就生效，学生可以直接读源码学写法 |
| **设计令牌单一来源** | 配色 / 间距 / 圆角 / 字体集中在 `tokens.css`，暗色模式只覆盖令牌值，两个主题共用同一套样式规则 |
| **样式复用** | `lesson.css` 一份服务 9 章；`styles.css` 服务门户 |
| **逻辑复用** | `lesson-core.js` 统一 Tab / 导航 / Demo 注入引擎，各章 `lesson.js` 只注册自己的演示；`lesson-path.js` 被引擎挂载一次，中英 18 页自动得到「小节流动路径带」 |
| **相对路径** | 全站相对路径，可直接部署到 GitHub Pages 子路径，无需任何配置 |

**四个开发自检脚本**（都不联网、不写文件、纯静态检查）：

| 脚本 | 保证什么 |
|---|---|
| `parity-check.mjs` | 逐页比对中英两版 **10 项结构指纹**（章节/sidebar/tab/面板/演示/代码块/表格/翻页…） |
| `link-check.mjs` | 扫描全部页面，校验**每一处站内链接与锚点**是否有效（618 处） |
| `quiz-check.mjs` | 题库合法性 + 中英逐题对应 + 英文文案表与 `T` 表**逐键**一致 |
| `practice-check.mjs` | 案例字段齐全、检查点选择器可达、光标锚点可定位、类名未丢失 |

> 一条命令跑完全部：`node parity-check.mjs && node link-check.mjs && node quiz-check.mjs && node practice-check.mjs`

## 亮点 ⑦ 细节与健壮性（都是查过、量过的）

- **暗色模式**：顶栏月亮/太阳按钮手动切换 + 未选择时跟随系统 `prefers-color-scheme`，两套主题共用同一份样式规则；
- **对比度实测**：关键元素（正文、代码角标、案例卡片、侧栏、按钮等 11 类）在**亮/暗两种主题下对比度均 ≥ 4.5:1**；
- **响应式无溢出**：22 个页面在 **1440px 与 375px 两档宽度下横向溢出均为 0**；
- **零控制台噪音**：所有页面 **0 个 JS 异常、0 个 console.error、0 个资源 404**（站点声明了 SVG 图标，浏览器因此不再去请求默认的 `/favicon.ico`）；
- **无障碍**：按钮组与分组容器带 `role="group"` + `aria-label`（语言切换器、预览宽度组），答题进度条带 `role="progressbar"` + `aria-valuenow`，语言链接带 `hreflang`；
- **键盘友好**：编辑器支持 Tab 缩进、回车继承缩进；提示条用 `role="status"` 播报；
- **判分可复现**：检查点固定在 1180px 宽运行，不受当前预览档位影响；
- **小节流动路径带**：每章标题下方一条 SVG 波浪贝塞尔轨道，01/02… 编号节点串起本章小节，虚线靠 `stroke-dashoffset` 动画沿线流动；几何由 `lesson-path.js` 读取左侧目录自动生成（**18 页零数据文件、零 HTML 改动**），`pathLength="1"` 归一化让任意小节间距都无缝循环；纯装饰带 `aria-hidden`，系统开启「减少动态效果」时自动停流，窄屏在带内横滚而不撑破页面。

## 亮点 ⑧ 课程知识图谱：把 9 章的关系画成一张能拖的图

章节卡片墙是**平铺清单**、课程主线是**线性 8 步**，都回答不了「这两章是什么关系」「第 3 章我在案例哪一步会用到」。
门户首页的 `#graph` 用一张**可交互的关系图**补上这一层：**节点 = 篇章 / 章 / 知识点 / 案例步骤，边 = 三种有真实语义的关系**。

| 关系 | 含义 | 视觉 |
|---|---|---|
| **包含** | 篇 → 章 → 小节 / 案例步骤 | 实线 |
| **前置知识** | 学之前建议先看（如「先懂盒模型再学 Flex」） | 虚线 + 说明文字 |
| **用于案例** | 这一节在第 9 章哪一步、实战哪一关被用到 | 点线 |

**两个层级，避免"漂亮但读不懂的毛线球"**：

```
总览（3 篇 + 9 章，12 节点） ──🗺 全图──▶ 51 节点 / 121 边（全部带名称：篇章/章节加粗大字，
      小节小字，节点正下方排布 + 底色描边，压着连线也能读；悬停邻接高亮探索局部）
      └── ◀ 返回 / ⌂ 总览（历史栈 + 面包屑）
```

**交互**：按住节点可**自由拖动**，松手即停在放下的位置（坐标钉在 fx/fy，不再被弹簧拉回；`适应窗口` 一键复位）；悬停即邻接高亮（无关节点淡到 0.22）、滚轮缩放、空白处平移。
**另有三件工程细节**：

- **列表视图**（`☰ 列表`）：同一份数据的等价入口 —— 键盘、读屏、手机都比 SVG 顺手（有对应页面的节点是链接，其余为静态条目）；
- **导出 PNG**：`XMLSerializer` + canvas 原生导出（不需要 html2canvas），因为颜色都写成了 SVG 表现属性，导出**不会掉色**；
- **无障碍**：所有操作都有工具栏按钮兜底（缩放 / 复位 / 全图 / 列表 / 导出），视图切换通过 `role="status"` 播报。

> **布局用 d3-force，渲染自己写**：力导向的物理（Verlet 积分、quadtree 多体、collide、alpha 衰减）自己写容易做糙，
> 所以用业界标准库；但它**必须是本地文件而不是 CDN**（否则断网或 `file://` 打开就废了），
> 于是只内置真正需要的 4 个文件共 **17 KB**（整个 d3 约 280 KB、ECharts 约 1 MB，而我们只用得上力导向）。
> 渲染保持手写 SVG：节点可聚焦、可读屏、颜色对比度可测、导出 PNG 不掉色 —— 这些 canvas 方案都做不到。
> 布局还做了**确定性**处理（固定种子初值 + `simulation.stop()` 手动 tick），同一视图每次打开位置完全一致。

## 🧩 关键技术决策

| 决策 | 为什么 | 代价 |
|---|---|---|
| **不用框架、不用打包器** | 教学站点的源码本身就是教材：学生"查看源代码"看到的就是最终代码 | 需要自己写少量复用逻辑 |
| **纯前端 + localStorage** | 无后端、无账号、无隐私负担；成绩与进度只存在用户浏览器里 | 换设备不同步 |
| **`lesson.js` 用 ES Module，`i18n/quiz/practice` 用普通 script** | 前者靠模块化拆分 9 章；后者要保证 `file://` 双击也能用（module 会被 CORS 拦） | 三种文件的加载方式不统一（已在 README 说明） |
| **沙箱不给 `allow-scripts`** | 避免 `allow-scripts` + `allow-same-origin` 的沙箱逃逸组合，同时保住同源测量能力 | 学生写的 JS 不会执行（本课程是纯 HTML/CSS 练习） |
| **预览缩放用 `transform: scale()`** | 只改视觉大小、不改布局宽度，媒体查询与 `vw` 才真实生效 | 需要额外处理滚动与尺寸同步 |
| **主线用"交叉引用"而非重构目录** | 兼顾"按知识点查阅"与"按案例学习"两种使用方式 | 需要维护交叉引用的一致性（已由 `link-check.mjs` 兜住） |
| **引擎单份 + 文案覆盖表** | 双语不会分叉；改逻辑只改一处 | 英文文案要单独维护（已被 `quiz-check.mjs` 的逐键断言兜住） |
| **图谱布局用 d3-force（本地内置 17 KB）** | 物理模型专业（quadtree 多体、collide 防重叠、alpha 衰减）；业界标准库，学生以后一定会遇到 | 
| **图谱数据从正文抽取、不手写** | 图谱与正文不可能脱节；中英天然逐项对应 | 改正文后需要重跑生成器（`graph-check.mjs` 会立刻发现不一致） |

## 🚀 运行与部署

**本地直接看**（无需任何工具链）：

```bash
# 方式一：双击打开
index.html          # 中文门户
en/index.html       # 英文门户

# 方式二：起个静态服务（推荐，体验与线上一致）
python -m http.server 8000
# 然后访问 http://127.0.0.1:8000/
```

**部署到 GitHub Pages**：

1. 推送到 GitHub 仓库；
2. 仓库 **Settings → Pages → Source** 选 `Deploy from a branch`；
3. 分支选 `main`、目录选 `/(root)`，保存；
4. 稍等片刻访问 `https://<用户名>.github.io/<仓库名>/`（英文版在 `/en/`）。

> 因为全站使用相对路径，**无需任何额外配置**。

## 🧭 可扩展性

| 想加什么 | 怎么做 |
|---|---|
| 加一个小节 | 复制一个 `<article>`（含三个 tab 面板）+ 侧栏加一条 + 注册一个演示；中文改完同步 `en/`，跑 `parity-check` |
| 加一整章 | 复制一章目录 → 改标题与顶栏 tabs → 门户加一张卡片 → 同步英文版 |
| 加一道题 | 在 `quiz-data.js` 与 `en/quiz-data.js` 同位置各加一条（同 id、同答案）→ `quiz-check` |
| 加一个实战环节 | 在 `practice-data.js` 与英文版各加一个环节（要求 / 提示 / 检查点 / 参考答案）→ `practice-check` |
| 加第三种语言 | 引擎已经是"单份引擎 + 文案覆盖表"，新增一份覆盖表 + 一份数据文件 + 一个目录即可（`parity-check` 可扩展为多语言比对） |
| 给图谱加节点/关系 | 在 `graph-data.js` 与 `en/graph-data.js` 同一视图里各加一条（同 id、同边、只换文案）→ `graph-check.mjs` 会说哪里不一致 |
