9.1 案例规划与线框图

先定目标与结构，再动手写代码

从这一节开始，我们要完整做出一个「个人作品集网站」。整个过程分 8 步， 每一步都会用到前面章节讲过的设计原则与技术。

🎯 案例需求（第 2 章：先问目标）

页面目标：让访客在 10 秒内知道"我是谁、我能做什么"，并愿意联系我。
目标用户：招聘方、合作方。
成功标准：访客看完作品集后点击"联系我"。

内容清单与优先级

区块优先级理由（第 1 章：对比与层次）
Hero｜一句话介绍 + 头像★★★首屏决定访客是否留下
作品集★★★证明能力，是核心说服材料
关于我★★补充背景，建立信任
数据统计★★用数字强化可信度
联系方式★★转化入口

⭐ 关键点：注意我们是先列出"页面要让用户做什么"，再倒推出区块的—— 顺序是「目标 → 内容 → 结构 → 视觉 → 代码」，而不是打开编辑器就开始写。
视觉动线（第 2 章）：Hero 在左上（第一眼），作品集居中（主体）， 联系方式在底部（Z 型终点），符合访客的阅读路径。

在线框图和"内容填充"之间切换，观察骨架不变、内容逐步填入的过程。

9.2 页面骨架与栅格

给整个网站装上"统一的刻度"

骨架有了，接下来是给页面装上刻度——这一步决定了后面所有区块能否对齐。

📐 三件事（第 3 章：栅格系统）

1. 容器：内容最大宽度 1180px，两侧留白，水平居中。
2. 栅格：12 列，列间距 24px。
3. 间距体系：8pt 档位（8 / 16 / 24 / 40）。

⭐ 关键点：容器 + 栅格一次定义，全站复用—— 后面 6 个区块都直接用 .container 和 .grid， 这样它们的左右边界天然对齐（第 1 章：对齐原则）。
为什么是 1180px？ 这是常见经验值： 在 1366px 及以上的屏幕上左右各留约 90px 呼吸空间， 单行文字长度也不会超过阅读舒适区（约 75 字符）。

👉 这一步用到了

用到：第 3 章 12 列栅格 · 8pt 间距 · 第 1 章 对齐

📚 这段代码用到：第 3 章 8pt 间距（:root 里的档位）· 第 3 章 12 列栅格（repeat(12, 1fr)）· 第 1 章 对齐（容器居中）

/* ① 容器：控制内容最大宽度并居中 */
.container {
  width: min(100% - 48px, 1180px);
  margin-inline: auto;
}

/* ② 12 列栅格：全站共用 */
.grid {
  display: grid;
  grid-template-columns: repeat(12, 1fr);
  gap: var(--space-lg);
}

/* ③ 间距档位（放在 tokens.css 里） */
:root {
  --space-sm: 8px;
  --space:    16px;
  --space-lg: 24px;
  --space-xl: 40px;
}

⭐ 关键点解释：width: min(100% - 48px, 1180px) 是 "小屏留 24px 边距、大屏最多 1180px" 的一行写法， 比先写 max-width 再配媒体查询更简洁。

调整容器宽度与列间距，观察 6 个区块是否始终对齐到同一套列线。

9.3 顶部导航栏

全站第一个"对齐示范"

导航栏是最简单的区块，却集中体现了三条原则。

🧭 导航栏的设计决策

布局方式：Flex + justify-content: space-between （第 6 章）——让 Logo 与菜单分列两端。
对齐：align-items: center 保证文字垂直居中（第 1 章）。
亲密性：菜单项之间用 gap 收紧，与 Logo 之间留大距离， 让"Logo"与"菜单"形成两个清晰的组（第 1 章）。

⭐ 关键点：导航栏需要吸顶时用 position: sticky（第 8 章）， 而不是 fixed——sticky 会保留原本占位， 不会让下面的内容"跳上来"。
易错点：sticky 的父元素不能有 overflow: hidden， 否则会失效（因为滚动容器变了）。

👉 这一步用到了

用到：第 6 章 对齐与分布 · 第 8 章 position · z-index · 第 1 章 亲密性

📚 这段代码用到：第 8 章 position: sticky（吸顶但保留占位）· 第 6 章 对齐与分布（justify-content 两端分开）· 第 1 章 亲密性（菜单项用 gap 收紧）

.site-header {
  position: sticky;      /* 吸顶，且保留占位 */
  top: 0;
  z-index: 50;
  backdrop-filter: blur(10px);   /* 毛玻璃效果 */
  border-bottom: 1px solid var(--c-border);
}

.site-header .inner {
  display: flex;                  /* 第 6 章 */
  align-items: center;
  justify-content: space-between;  /* Logo ↔ 菜单 分列两端 */
  height: 60px;
}

.site-header nav {
  display: flex;
  gap: 6px;                  /* 菜单项之间：紧 */
}

⭐ 关键点解释：justify-content: space-between 在两个子元素时表现为"一左一右"；若有多个子元素， 它会把第一个和最后一个贴边、中间平均分布—— 理解这一点就不会误用。

调整菜单项数量与对齐方式，观察导航栏的分布与分组变化。

9.4 首屏 Hero

决定"访客是否留下"的一屏

首屏（Hero）是全页视觉重量最大的区块，也是设计原则最密集的地方。

🎨 Hero 用到的四条原则

层次：主标题 40px+，副标题 16px，正文 14px——档位拉开（第 1.3 节）。
留白：上下 padding 用最大的 --space-xl，让核心内容"浮"出来。
平衡：左侧文字 + 右侧头像，用 7fr 5fr 做非对称平衡（第 1.6 节）。
动线：标题 → 副标题 → 按钮，自上而下，符合 Z 型起点（第 2 章）。

⭐ 关键点：Hero 里只能有一个"主角"。
· 如果标题、头像、按钮都在抢注意力，访客反而不知道该看哪；
· 正确做法：标题最大，其他元素依次减弱，最后用一个高对比按钮收尾。
对比的力量来自"落差"——把次要元素主动弱化（降低饱和/变灰），比把主角放大更有效。

👉 这一步用到了

用到：第 1 章 视觉平衡 · 对比与层次 · 第 7 章 网格定位 · 第 8 章 相对单位

📚 这段代码用到：第 7 章 网格定位（7fr 5fr 覆盖 12 列）· 第 8 章 相对单位（clamp() 字号）· 第 1 章 视觉平衡（非对称）

.hero {
  padding: var(--space-xl) 0;     /* 松：核心区留白最多 */
}

.hero .grid {
  display: grid;
  grid-template-columns: 7fr 5fr;  /* 非对称平衡 */
  gap: var(--space-xl);
  align-items: center;
}

.hero h1 {
  font-size: clamp(30px, 4vw, 46px);  /* 层次 + 响应式字号 */
  line-height: 1.2;
  margin-bottom: var(--space);      /* 标题与副标题：紧 */
}

.hero .lead {
  font-size: 17px;
  color: var(--c-text-soft);       /* 弱化，衬托标题 */
  margin-bottom: var(--space-lg);
}

.hero .cta {
  background: var(--c-primary);        /* 唯一的高对比元素 */
  color: #fff;
  padding: 12px 24px;
  border-radius: 999px;
}

⭐ 关键点解释：align-items: center 让左右两栏在垂直方向居中对齐； 但要注意——左右两栏内容高度不同时，居中对齐通常比顶对齐更好看， 因为视觉重量更容易平衡。

调整标题字号、留白与左右比例，感受"层次"与"平衡"的变化。

9.5 关于我（双栏）

图文混排：比例比"均分"更重要

"关于我"是典型的图文双栏：一边是头像/名片，一边是文字介绍。

📊 为什么通常不是 1:1？

人像/配图属于视觉信息，文字属于阅读信息。 实践中常见的分法是 4:8 或 5:7—— 让文字栏拿到更多宽度，因为中文单行字数过多会显著降低阅读效率。

⭐ 关键点：不要用 1fr 1fr 做图文双栏。 均分看起来"公平"，但会让文字行过长或图片过大，两边都不舒服。
另一个坑：如果图片在 DOM 中排前面、而你希望文字先被读到（对屏幕阅读器与 SEO 友好）， 应该调整 DOM 顺序或使用 order，而不是靠眼睛"看起来对"就够了。

👉 这一步用到了

用到：第 7 章 网格定位 · 第 5 章 盒模型 · 第 1 章 亲密性与留白

📚 这段代码用到：第 7 章 网格定位（4fr 8fr）· 第 5 章 盒模型（padding 撑出留白）· 第 1 章 亲密性与留白（段内紧、段间松）

.about .grid {
  display: grid;
  grid-template-columns: 4fr 8fr;   /* 图 4 : 文 8 */
  gap: var(--space-xl);
  align-items: start;          /* 顶对齐：长文不被"居中"拉扯 */
}

/* 小屏自动堆叠（第 8 章：响应式） */
@media (max-width: 760px) {
  .about .grid { grid-template-columns: 1fr; }
}

/* 文字段落之间保持"亲密性"：段内紧、段间松 */
.about p { margin-bottom: var(--space); line-height: 1.9; }

⭐ 关键点解释：这里用 align-items: start（顶对齐）， 而不是 Hero 用的 center。 判据是内容长度：短内容配图片用居中更平衡； 长段落配图片用顶对齐，否则文字会偏离读者的目光起点。

切换图文比例与对齐方式，观察阅读舒适度与视觉平衡的变化。

9.6 作品集卡片墙

案例的核心区块：一屏展示多个作品

作品集是整页的说服核心。用卡片墙来承载，一次能展示多个作品，且天然整齐。

🧱 卡片墙用到的原则

重复：每张卡片的圆角、内边距、阴影完全一致（第 1.4 节）——这是"成套感"的来源。
共同区域：卡片背景把内容框成一组（第 1.5 节）。
对齐：auto-fit + minmax 让卡片宽高自动一致（第 3 章）。
亲密性：卡内元素（图/标题/标签）间距 8px（紧），卡片之间 24px（松）。

⭐ 关键点：卡片内部的经典结构是 Flex 纵向 + margin-top: auto—— 它能把"查看详情"推到卡片底部，让高度不一的卡片也保持按钮对齐。
为什么卡片会等高？ 因为 Grid 的默认 align-items: stretch 会拉伸同一行的所有卡片到最高者的高度。这不是巧合，是 Grid 特性。

👉 这一步用到了

用到：第 7 章 自动填充 · 第 6 章 弹性伸缩 · 第 1 章 重复与统一 · 格式塔

📚 这段代码用到：第 7 章 自动填充（auto-fit）· 第 6 章 弹性伸缩（margin-top: auto 把链接贴底）· 第 5 章 盒模型（卡内 padding）· 第 1 章 重复与统一（四张卡同一套值）

/* ① 墙：自适应列数，不需要媒体查询 */
.works .wall {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(260px, 1fr));
  gap: var(--space-lg);         /* 卡片之间：松 */
}

/* ② 卡片：纵向 Flex，让底部链接贴底 */
.work-card {
  display: flex;
  flex-direction: column;
  padding: var(--space);
  background: var(--c-surface);
  border: 1px solid var(--c-border);
  border-radius: var(--radius);
}

.work-card .thumb {
  aspect-ratio: 16 / 10;        /* 统一比例，避免高度参差 */
  border-radius: 8px;
  margin-bottom: var(--space-sm);
}

.work-card .more { margin-top: auto; }   /* ★ 推到最底部 */

⭐ 关键点解释：aspect-ratio: 16 / 10 是让缩略图保持统一比例的关键。如果不加， 图片高度会随原始尺寸变化，整面墙就会"高低不平"。

调整最小卡片宽度与间距，并切换卡片数量，观察整面墙的对齐与呼吸感。

9.7 数据统计区

用数字强化可信度，也考验"信息层级"

这一区要同时放多个小指标和一个大图表——正是第 4 章讲的"仪表盘栅格"场景。

📈 信息层级怎么分？

数字：24～32px 加粗、用主色——它是最重要的。
单位/后缀：14px 常规——次要。
说明文字：12px 灰色——辅助。
三者形成 3 档落差，一眼就能读懂"这个数字是什么"。

⭐ 关键点：数字和它的说明必须"靠得住"（亲密性）—— 垂直间距 4～6px，绝不能和下一个指标一样远， 否则读者会分不清哪个说明属于哪个数字。
跨列思路：容器设 4 列，小指标各占 1 列， 大图表 grid-column: span 4 独占一行（第 4 章）。

👉 这一步用到了

用到：第 4 章 仪表盘栅格 · 第 1 章 对比与层次 · 第 3 章 8pt 间距

📚 这段代码用到：第 4 章 仪表盘栅格（按重要性给格子大小）· 第 1 章 对比与层次（数字/单位/说明三档字号）· 第 3 章 8pt 间距

.stats .grid {
  display: grid;
  grid-template-columns: repeat(4, 1fr);   /* 基准 4 列 */
  gap: var(--space-lg);
}

.stat {
  display: flex;
  flex-direction: column;
  gap: 4px;                    /* 数字与说明：紧 */
  padding: var(--space);
  background: var(--c-surface);
  border-radius: var(--radius);
}

.stat .num { font-size: 28px; font-weight: 700; color: var(--c-primary); }
.stat .lbl { font-size: 12px; color: var(--c-muted); }

/* 大图表独占整行 */
.stats .chart { grid-column: span 4; min-height: 180px; }

/* 小屏降为 2 列，跨列自动收缩 */
@media (max-width: 760px) {
  .stats .grid  { grid-template-columns: repeat(2, 1fr); }
  .stats .chart { grid-column: span 2; }
}

⭐ 关键点解释：小屏把 span 4 改成 span 2 只是一行覆盖，其它指标完全不用动—— 这正是"用 span 而不是写死 1 / 5"的好处（第 4 章）。

切换不同的跨列方案，观察信息层级与大图表的关系。

9.8 响应式与设计自查

让案例在所有屏幕上都成立，并给作品做一次体检

最后一步：让整个案例在手机上也能好好显示，并做一次系统性的自查。

📱 断点怎么定？（第 8 章）

不是"按设备定"，而是"按内容定"——把浏览器拖窄， 直到布局开始"难受"的那一刻，就是你的断点。
本案例只用了两个断点：760px（双栏堆叠）与 1040px（列数减少）。

✅ 布局设计自查清单

检查项对应理论
所有元素都对齐到同一条线了吗？对齐（1.1）
相关的内容靠得更近了吗？（组内 < 组间）亲密性（1.2）
最重要的内容最显眼吗？字号跨度够吗？对比（1.3）
同类元素的圆角/阴影/颜色一致吗？重复（1.4）
分组是否清晰到"不需要文字解释"？格式塔（1.5）
左右视觉重量是否平衡？留白是否有节奏？平衡与节奏（1.6）
间距是否都来自同一套档位？间距体系（3.2）
手机宽度下，内容是否还能顺畅阅读？响应式（第 8 章）

⭐ 关键点：布局做完后，用这份清单逐条过一遍， 比"凭感觉再调调"有效得多。
这套清单本身就是本课程前半部分（设计篇）的浓缩—— 你不需要记住所有 CSS 属性，但应该记住这份清单。

👉 这一步用到了

用到：第 8 章 媒体查询 · 移动优先 · 第 3 章 对齐到栅格

📚 这段代码用到：第 8 章 媒体查询（min-width 逐级增强）· 第 8 章 移动优先（默认单列、向上增强）· 第 3 章 对齐到栅格（窄屏是否还成立）

/* 移动优先：默认单列，再逐级增强（第 8 章） */
.about .grid,
.hero .grid { grid-template-columns: 1fr; }        /* 默认：手机 */

@media (min-width: 760px) {                      /* 平板起：双栏 */
  .hero .grid  { grid-template-columns: 7fr 5fr; }
  .about .grid { grid-template-columns: 4fr 8fr; }
}

@media (min-width: 1040px) {                     /* 桌面起：更大的留白 */
  .hero { padding: calc(var(--space-xl) * 1.6) 0; }
}

⭐ 关键点解释：注意这里的媒体查询用的是 min-width， 默认样式只服务手机——这就是第 8 章讲的移动优先。 整个案例里，小屏样式一次都没被覆盖，只是在被"增强"。
