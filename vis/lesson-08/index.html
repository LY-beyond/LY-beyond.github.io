8.1 position 五种取值

要不要脱离文档流，由它决定

前面学的 Flex 和 Grid 都是在"正常流"里做文章。position 则提供了另一种能力：把元素从正常流里"拎出来"，放到任意位置。

取值参照物是否脱离文档流典型用途
static无（默认）否普通元素
relative自身原位置否（原位置仍保留）微调位置 / 给 absolute 当爹
absolute最近的已定位祖先是角标、下拉菜单、覆盖层
fixed浏览器视口是返回顶部按钮、悬浮条
sticky最近的滚动容器否（滚动到阈值才吸附）吸顶导航、表头

⭐ 关键点："子绝父相"是定位最实用的口诀—— 给父元素设 position: relative，子元素设 position: absolute， 子元素就会相对于父元素定位，而不会满屏乱跑。 忘了给父元素定位，是初学者最常踩的坑。

👉 在案例里看它

导航吸顶用 position: sticky 而不是 fixed，见 9.3 顶部导航栏；实战环节 3 会检查 position 与 top。

/* 子绝父相：经典组合 */
.card {
  position: relative;   /* 父：提供定位参照 */
}
.badge {
  position: absolute;   /* 子：脱离文档流 */
  top: 8px;
  right: 8px;
}

/* 吸顶导航 */
.navbar { position: sticky; top: 0; }

⭐ 关键点解释：absolute 的参照物是 "最近的、position 不为 static 的祖先"； 如果一路上都找不到，就相对于初始包含块（约等于页面左上角）定位。
注意：fixed 不受祖先影响，永远相对视口。

切换 position 取值，注意红色虚线框（原位置）与元素实际位置的关系。

8.2 偏移量

top / right / bottom / left 怎么算

元素一旦有了非 static 的定位，就可以用 top / right / bottom / left 四个属性来"推"它。

📐 两条规则

1. 参照物决定含义：同一个 top: 20px， 在 relative 下表示"相对自己原位置下移 20px"， 在 absolute 下表示"距父容器顶部 20px"。
2. 同时给左右（或上下）会拉伸： 若 left 与 right 都写了且没有固定宽度，元素会被拉宽填满。

  • 取值可以是长度（20px）或百分比（相对父容器尺寸）。
  • 也可以用负值，如 top: -10px，把元素往反方向推。
  • 对 static 元素设置这四个属性完全无效。

⭐ 关键点：top 和 bottom 同时存在时会互相"拉扯"， 只有在元素高度为 auto 时才表现出拉伸效果； 若元素已有固定高度，则以 top 为准。 调试定位问题时，先确认"参照物是谁"。

👉 在案例里看它

案例里 top: 0 就是「吸在视口顶部」这个偏移量的表达，见 9.3 顶部导航栏。

/* relative：相对自己的原位偏移 */
.shift { position: relative; top: 12px; left: 24px; }

/* absolute：相对已定位父容器 */
.tip { position: absolute; bottom: 100%; left: 0; }

/* 左右都写 -> 拉伸填满（无固定宽度时） */
.full { position: absolute; left: 0; right: 0; }

⭐ 关键点解释：bottom: 100% 常用于"小提示泡"—— 它表示"移到父元素顶部的上方"，也就是完全贴在父元素上边缘外面， 这样气泡和触发元素之间不用手动算高度。

拖动 top / left 滑块，观察 relative 与 absolute 下偏移参照物的差异。

8.3 z-index 与层叠

谁在上面，谁在下面

当元素互相重叠时，浏览器需要一个规则来决定谁显示在上面，这就是 z-index（z 轴坐标）。

🧱 三条前提

1. z-index 只对已定位元素（position 非 static）或 flex/grid 子项生效；
2. 值可以是负数，数值大的盖住数值小的；
3. 它会创建层叠上下文，子元素的 z-index 只能在父级内部比较。

⭐ 关键点：最常见的"z-index 不管用"， 原因通常是忘了给元素加 position——对一个 position: static 的元素写 z-index: 9999 是完全无效的。
另一个常见原因是层叠上下文被父元素"锁"住了： 父元素有了 transform / opacity < 1 等属性后， 子元素再大的 z-index 也跳不出父元素的层级。

👉 在案例里看它

导航的 z-index: 50 让它盖住下面滚上来的内容，见 9.3 顶部导航栏。

.box-a { position: absolute; z-index: 1; }
.box-b { position: absolute; z-index: 2; }  /* b 盖住 a */
.box-c { position: absolute; z-index: 3; }  /* c 在最上面 */

/* 想让子元素突破父级层叠，先确保父元素没有创建层叠上下文 */

⭐ 关键点解释：实践中最省事的做法， 不是给所有元素乱设 z-index，而是只给需要浮起的元素 设定少量明确的层级（例如 1 / 10 / 100 / 1000）， 并统一记在项目里，避免出现"9999 满天飞"的失控局面。

拖动三个 z-index 滑块，观察重叠盒子的上下关系如何改变。

8.4 视口与媒体查询

让 CSS 根据屏幕宽度做决定

响应式的第一步，是告诉浏览器"按设备的真实宽度来渲染"——这需要一行 meta 标签：

<meta name="viewport" content="width=device-width, initial-scale=1.0">

有了它，再用 媒体查询（media query），就能在特定宽度下应用不同的样式：

📱 常用断点

< 640px 手机　·　640–1024px 平板　·　> 1024px 桌面

⭐ 关键点：漏写 viewport 的 meta 标签，是"移动端看起来像缩小版桌面页" 的头号原因——iOS/Android 会默认按 980px 宽渲染再整体缩小。 写完这行，媒体查询才会按真实逻辑宽度生效。

👉 在案例里看它

案例只用了两个断点：760px（双栏）与 1040px（留白加大），见 9.8 响应式与自查。

/* 桌面样式（默认） */
.cards { display: grid; grid-template-columns: repeat(3, 1fr); }

/* 屏幕 <= 700px 时改为单列 */
@media (max-width: 700px) {
  .cards { grid-template-columns: 1fr; }
}

⭐ 关键点解释：max-width 表示"不超过该宽度时生效"， min-width 表示"至少该宽度时生效"。 两者可以混用，但推荐统一用 min-width（移动优先），逻辑更清晰。

拖动"屏幕宽度"滑块，观察下方模拟视口里的布局在断点处自动切换。

8.5 移动优先

从小到大写，而不是从大到小

写响应式有两条路线，结果一样但维护成本差别很大：

路线默认样式媒体查询用维护感受
移动优先（推荐）手机单列min-width 逐级增强越写越"加料"，清晰
桌面优先桌面多列max-width 逐级覆盖越写越"打补丁"，易冲突

⭐ 关键点：移动优先的本质是"先保证小屏可用，再给大屏加料"。 因为手机性能与带宽最差，先写小屏样式可以让它只加载最必要的规则， 同时避免"桌面样式写太满，小屏再一条条覆盖"的麻烦。
实践建议：媒体查询里的 min-width 从小到大排列， 且每个断点只写"相比上一档新增了什么"。

👉 在案例里看它

案例最后一步就是把「桌面优先」重构为「移动优先」：默认单列 + min-width 增强，见 9.8 响应式与自查；实战环节 8 要验证 375 单列、1180 两栏。

/* ① 默认 = 移动端：单列 */
.cards { display: grid; gap: 16px; }

/* ② 平板及以上：两列 */
@media (min-width: 640px) {
  .cards { grid-template-columns: repeat(2, 1fr); }
}

/* ③ 桌面及以上：三列 */
@media (min-width: 1024px) {
  .cards { grid-template-columns: repeat(3, 1fr); }
}

⭐ 关键点解释：注意每个媒体查询里只改了列数， 没有重复写 display: grid 和 gap—— 它们继承自移动端的默认样式。这就是"逐级增强"的含义。

切换两种写法，对比同一效果下 CSS 的组织方式差异。

8.6 相对单位

px 之外，还有更"聪明"的长度

响应式不只靠媒体查询，相对单位能让尺寸自动"跟着环境走"，很多时候可以省掉断点。

单位相对于典型用途
px绝对像素边框、阴影等固定细节
rem根元素（html）字号字号、间距——最推荐
em当前元素字号组件内部按比例缩放
%父元素对应尺寸宽度、高度占比
vw / vh视口宽 / 高的 1%满屏区块、超大标题

⭐ 关键点：rem 生效的前提是根字号可被用户调整—— 浏览器默认 html 字号为 16px，所以 1rem = 16px。 用 rem 写字号的好处是：用户改浏览器字号设置时，整个页面会跟着等比放大， 而 px 不会——这是无障碍（a11y）的重要一环。

👉 在案例里看它

案例的相对单位用在两处：首屏字号 clamp(30px, 4vw, 46px)、容器 min(100% - 48px, 1180px)，见 9.4 首屏 Hero。

/* 1rem = 根元素字号（默认 16px） */
.title { font-size: 2rem; }      /* = 32px */
.gap-lg { margin: 1.5rem 0; }  /* = 24px */

/* 字号随视口平滑变化，连断点都省了 */
h1 { font-size: clamp(28px, 5vw, 48px); }

/* 区块最小占满一屏 */
.hero { min-height: 100vh; }

⭐ 关键点解释：clamp(最小值, 理想值, 最大值) 是响应式字号的"神器"——它让字号在视口变宽时平滑增大， 但不会小到看不清、也不会大到失真，本站标题就用了这个写法。

调整"根字号"与"视口宽度"，观察相同数值下 rem / em / % / vw 的实际尺寸差异。
