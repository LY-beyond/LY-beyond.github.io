## 第八轮：修复「选择文件夹」不可用（用户反馈弹出的仍是文件选择框）
- 原因：「选择文件夹」依赖 `<input webkitdirectory>`，部分浏览器（国产兼容模式等）不支持该属性，静默降级成普通文件框
- 修复（case-upload.js）：三级降级策略 ① webkitdirectory（bind 时用 setAttribute 再补一次，防 innerHTML 丢属性）→ ② showDirectoryPicker() 文件夹句柄 API 递归读取（walkDirHandle，补 webkitRelativePath）→ ③ 都没有则明确提示三个替代办法；虚线框副标题加 Ctrl+A 全选提示
- 通用兜底验证：平铺多选文件（无路径）时，CaseDemoHost.findFile 的 basename 回退能把 demo/index.html ↔ index.html 对上，端到端校验 0 错误、整页模式正常
- 测试坑升级：无头 Chrome 测 file:// 页必须加 --allow-file-access-from-files，且测试页要有 <meta charset="UTF-8">，否则 data.js 报 SyntaxError: Invalid or unexpected token（UTF-8 被误解码，中文标识符变非法 token）
- 验证：DIR_ATTR=true PICKDIR_TRIGGERED=true / FILE_COUNT=4 MODE=整页模式 VALIDATION_ERRORS=0；版本号升到 20261022g；指南文档同步补了替代办法
- 追加修复（版本号 h）：用户反馈点「选择文件夹」先弹文件框再弹文件夹框。根因：两个隐藏 input 就在虚线框 #imp-drop 内部，程序化 .click() 派发的合成 click 会冒泡回虚线框监听器，二次调用 fileIn.click() → 双弹窗（「选择文件」按钮同样受累，会弹两次文件框）。双保险修复：输入框上 stopPropagation 截冒泡 + 虚线框只响应 e.isTrusted=true 的真实点击。无头测试（包装原生 click 保留冒泡行为复现）：DIR_BTN dir=1 file=0、FILES_BTN file=1、INPUT_SELF 0/0 全过。测试坑：MouseEvent 的 isTrusted 只读，defineProperty 会抛错
