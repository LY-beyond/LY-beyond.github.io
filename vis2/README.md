# 人工智能 · 新质生产力｜数据可视化

**第二次作业**：用一张**零构建**的长滚动数据看板，讲清「**人工智能是发展新质生产力的核心引擎**」这一主题。

- 纯 HTML + CSS + JavaScript（原生 ES Module 之外的普通 script），**无需 npm / 无需打包，双击 `index.html` 即可运行**；
- **中英双语**（右上角「中 / EN」）、**亮 / 暗主题**（右上角日/月图标，跟随系统并可手动切换）；
- **14 个章节**（00 阅读地图 → 13 关于）、**13 张自绘 SVG 图表** —— 雷达 / 折线 / 双组条形 / 气泡矩阵 / **热力矩阵** / **小倍数图** / 横向排名 / **省级分级填色地图** / 流向 / 力导向图谱 / 时间轴，外加 **1 台生产力模拟器**（含**龙卷风敏感性图**与**蒙特卡洛分布图**两张派生图）；
- 每张图都自带 **图表 ⇄ 数据表**切换与 **PNG / SVG / CSV 导出**（13 张图 × 3 种格式，导出的是同一份数据）；
- 除 `vendor/` 下 5 个 d3 子模块（共约 30 KB）外**没有任何运行时依赖**，不联网、不读 CDN；
  连省级地图的边界都是**构建期**抽稀好的静态几何（`map-china.js`，28 KB），运行时一次网络请求都不发。

> 配套自检：`node selfcheck.mjs` —— 一条命令跑完全部**静态**自检（结构 / 跳转 / 中英对齐 / 无障碍与对比度 / 体积预算 / 数据链路），毫秒级返回；
> 加上 `--full` 会连**真机**自检（`audit.mjs` 11 档视口布局体检 + `smoke.mjs` 124 项交互断言）一起跑。
> 数据不是手写的：`data/*.csv`（可 diff 的数据源）→ `node data/build.mjs` → `data.js`，见 [data/README.md](data/README.md) 数据字典。

## 🛠 技术要点

- **运行时零构建、零依赖**：没有 npm、没有打包器，`index.html` 直接引用相对路径的 `.js` / `.css`；
  唯一的「构建」发生在**开发期的数据侧**（`data/*.csv` → `data.js`），产物就是一个普通静态文件，浏览器不需要任何工具链。
  脚本加载顺序：`d3-dispatch → d3-selection → d3-quadtree → d3-timer → d3-force → i18n → data → map-china → charts → app`。
- **数据与呈现分离，数据本身也是构建产物**：`data/*.csv`（40 个数据集、带类型化表头、可 diff）→ `node data/build.mjs` → `data.js`；
  `charts.js` 只画图，`app.js` 只做「取数据 → 选容器 → 画图 → 挂交互」。改数字不用碰渲染代码，改渲染不用碰数据，
  而且「手改 `data.js` 忘了同步 CSV」会被 `node data/build.mjs --check` 直接拦下（`selfcheck.mjs` 已包含这一步）。
- **颜色一律从令牌取**：`charts.js` 通过 `getComputedStyle` 读 `tokens.css` 的 `--c-* / --d1..--d6`，
  并写成 SVG **表现属性**（而不是 CSS 类）—— 好处是①切主题时颜色自动跟随、②导出 / 截图不掉色。
- **主题切换 = 重画**：`themechange` 事件触发 `renderAll()`，图表按新令牌重绘；`theme.js` 在 `boot()` 之前就把 `data-theme` 写到 `<html>` 上，**首屏不闪白**。
- **语言切换 = 重画**：`i18n.js` 提供 `T(key)` 与 `setLang()`，`langchange` 事件同样触发 `renderAll()`。
  图表内的文字（轴标题、气泡名、图例）都由 `app.js` 用 `P({zh, en})` 传进去，因此英文模式下**不会残留中文**（`parity-check.mjs` 与浏览器实测均为 0）。
- **一份数据、两种语言**：不维护 `zh/` 与 `en/` 两套页面，避免「改了中文忘了英文」；词表键由 `parity-check.mjs` 断言对齐（当前 86 个键）。
- **四种新图型都是「一个数据源、两种看法」**（第二次作业新增）：
  - **分级填色地图**：五档分位数着色（不是线性分档，尾部看得清）；省级边界的几何键与 `data.js` 的行政区划代码**由 `check.mjs` 双向断言**，少一个省就会出现「有轮廓没颜色」，多一个键则永远画不出来；
  - **热力矩阵**：**列内归一化**（同一行里是渗透率 %、市场规模亿元、人才指数 /100，只有列内比较才有意义），格子里照实写原始数值，数据表与 CSV 导出也是原始值；
  - **小倍数图**：三格共用同一套纵轴刻度（这是小倍数图的全部意义），配色跨格一致、产业身份交给标题前的色点；宽屏三列、窄屏竖排，年份刻度只标在最下面一格；
  - **敏感性分析**：龙卷风图一次只把一个因素从 0 扫到 100（回答「先调哪个」），蒙特卡洛四个因素同时 ±15% 扰动抽 500 次（回答「有多不确定」）。随机数用**固定种子的 mulberry32** —— 换语言 / 换主题重绘时必须是同一批样本，否则图会莫名其妙地跳；滑块拖动时重算走 90ms 防抖。
- **无障碍**：跳转链接 `skip-link`、顶栏 `aria-expanded` 折叠、图表容器 `role="img"` + `aria-label`、
  导航当前项 `aria-current`、语言按钮 `aria-pressed`、尊重 `prefers-reduced-motion`（数字不再滚动、动画直接落到终态）。
- **响应式**：移动优先；顶栏在 ≤1160px 折叠成抽屉（13 个导航项在 1024px 时会超出，而 `.topnav` 隐藏了滚动条、用户不知道能横滑）；
  英文标签更长，`i18n.css` 里对 `html[lang="en"]` 的导航单独收过字号与内边距（否则宽屏也会差 40px）；
  卡片墙用 `auto-fit`；图表用 `viewBox`，但画布宽度跟随**容器实际宽度**（上限 = 设计宽度 900/960/700），
  所以字号在宽窄屏上都是 11~13px（1:1），不再出现「宽屏放大到 23px、手机压到 3.5px」。
  容器宽度变化 ≥24px 时 `app.js` 节流重画一次（动画会重播，属于预期）。

- **模拟器状态**：`STATE.sim` 独立于渲染存在，切换语言 / 主题后**旋钮位置与结果保持不变**（不会把用户调好的参数重置）。

## ✅ 自检与验收

```bash
cd vis2
node selfcheck.mjs          # 静态自检全部跑完（不联网、不开浏览器，毫秒级）→ 汇总断言数
node selfcheck.mjs --full   # 连真机自检一起跑（需要本机 Chrome，约 1–2 分钟）
```

### 八个自检脚本，各管一件事

| 脚本 | 类型 | 管什么 |
|---|---|---|
| `selfcheck.mjs` | 汇总 | 按顺序跑下面 6 个静态检查，汇总断言数与失败项；`--full` 时再加两个真机脚本 |
| `check.mjs` | 静态 | 结构一致性：词表键、`data-i18n` 键、挂载点、选择器、数据形状（双语叶子 / 热力 15×5 / 小倍数 3×7 / 地图 34 行 / 图谱 21 节点 36 边…）、vendor 顺序、五个新引擎导出 |
| `link-check.mjs` | 静态 | 站内跳转与资源引用：每个 `#锚点` 都能命中（含由 `data.js` / `app.js` 生成的跳转）、脚本/样式/图标文件都在、外链带 `rel="noopener"` |
| `parity-check.mjs` | 静态 | 中英对齐：两表键一致、英文无中文残留、**占位符与数字同步**、451 个双语文案两侧都在、`index.html` 中文文本必须有 `data-i18n`、含中文的 `aria-label` 必须有 `data-i18n-attr`、脚本里不许出现裸中文 |
| `a11y-check.mjs` | 静态 | 无障碍：**54 组前景/背景对比度实测**（亮暗两档，含 `color-mix` 的预乘混合与 WCAG 公式）、`tokens.css` 注释里写的比值必须与实测一致、id 唯一、ARIA 引用完整、控件可及名、标题层级、landmark、焦点顺序、role 白名单 |
| `budget-check.mjs` | 静态 | 体积与承诺：8 条 gzip 预算（全站 / 各文件 / vendor / CSS）、请求数上限、**零联网**（禁止 `fetch` / `XHR` / 动态 `import` / `@import` / 外链资源）、无 `type="module"`、数据摊销，并核对本 README 的「复杂度清单」数字 |
| `audit.mjs` | 真机 | 11 档视口（360 → 1440px）布局体检：横向溢出与超出的元素、章节高度节奏、网格孤儿行、图表缩放比、< 44px 触控目标、首屏折线、锚点跳转被吸顶栏遮挡、顶栏导航是否被裁切 |
| `smoke.mjs` | 真机 | 124 项交互断言：13 张图工具栏与按钮、气泡→产业/场景跨图联动（含空集兜底）、数据表开合与行数、年份播放器、PNG/SVG/CSV 导出（文件名 + CSV 表头）、地图换指标 / 前五名 / 悬停、热力 15×5、小倍数两种排版、拖动滑块后两张敏感性图重算、英文模式无中文残留、19 个 SVG / 14 章节 / 13 导航项、全程零报错零溢出 |

每个脚本末尾都会打印 `SUMMARY script=… checks=N failed=M`，`selfcheck.mjs` 靠这一行汇总；
**任何一个脚本失败都以非零码退出**，可以放心挂到 CI 或提交钩子上。

## 🚀 部署

> 💡 **额度紧张 / 还没定稿？** 可以先不部署：日常用上面的「🧪 本地预览」看效果，
> 收尾时再一次性部署 —— 完整说明见 [`DEPLOY-NETLIFY.md`](DEPLOY-NETLIFY.md) **§0.5**（含 Netlify 额度计费口径与"开发期间暂停构建"的做法）。

**Netlify（推荐，含"同仓库多站点"的完整指导书）：👉 [`DEPLOY-NETLIFY.md`](DEPLOY-NETLIFY.md)**

要点：本仓库同时托管 `vis/`（第一次作业）与 `vis2/`（第二次作业），
而 Netlify 一个站点只能有一个 Publish directory，**且 `netlify.toml` 会覆盖 UI 设置**，
所以根目录的 `netlify.toml` 里**故意不写 `publish`**，两个站点各自在 Netlify UI 里填：

| 站点 | Publish directory | Build command |
|---|---|---|
| 旧站点（vis） | `vis` | 留空 |
| 新站点（vis2） | `vis2` | 留空 |

日常更新：`git push origin main` → Netlify 自动重新部署（约 10 秒，无构建步骤）。

其他方式（**路径全部相对**，无需额外配置）：

- **预览（不部署）**：见上方「🧪 本地预览」—— 双击 `index.html` / 本地 HTTP 服务器 / GitHub Pages；
- GitHub Pages：仓库 `main` 分支根目录发布，访问 `https://ly-beyond.github.io/vis2/`；
- **应急手动部署**：Netlify Drop 拖拽 `vis2` 文件夹，或 `npx netlify-cli deploy --prod --dir=vis2`。

站点体积很小：**页面只请求 17 个文件 / 磁盘 366 KB / gzip 后 116 KB**（其中 `vendor/` 的 5 个 d3 脚本累计约 30 KB，
抽稀后的省级边界 `map-china.js` 28 KB，生成的 `data.js` 61 KB；其余为页面代码与样式）。
部署目录里另有**不参与页面加载**的东西：8 个自检脚本（147 KB）、`data/` 数据源与构建脚本（139 KB）、
`README.md` / `HIGHLIGHTS.md` / `FEATURES.md` / `DEPLOY-NETLIFY.md` 等文档（40 KB），整个目录 71 个文件 / 691 KB。

## 📊 数据链路（回答「数据哪来的、怎么处理的」）

页面上每一个数字、每一句文案都来自 `data/` 下的 CSV —— 它不是手写进 `data.js` 的：

```text
data/*.csv         40 个数据集 / 269 行，带类型化表头（列名:text|number|boolean|json），UTF-8 带 BOM，Excel 直接能开
data/sim-model.js  模拟器的模型函数（函数进不了 CSV，构建时原样内联）
        │  node data/build.mjs              ← 生成（40 个数据集 → 61 KB 的 data.js）
        ▼
data.js            页面加载的数据模块（构建产物，顶部写着「请勿手改」）
        ▲  node data/build.mjs --extract    ← 反向：把手改同步回 CSV
```

| 想要做什么 | 怎么做 |
|---|---|
| 改一个数字 / 一句话 | 改 `data/` 下对应 CSV 的那一格 → `node data/build.mjs` → `node selfcheck.mjs` |
| 看每个 CSV 有哪些列、什么类型、对应页面哪一节 | [**data/README.md（数据字典）**](data/README.md) —— 由 `node data/build.mjs --docs` 生成 |
| 改模拟器公式 | 改 `data/sim-model.js`（模拟器 / 龙卷风图 / 蒙特卡洛共用它）→ 重新构建 |
| 确认没人偷改 `data.js` | `node data/build.mjs --check`：断言「仓库里的 data.js 就是这些 CSV 生成的」 |
| 重构数据结构后确认没丢东西 | `node data/build.mjs --verify <另一个 data.js>` 逐字段比对（含模型在 3 组输入下的输出） |

数据集的划分不是拍脑袋：`--extract` 会把「元素是对象的数组」「键数 ≥ 5 的嵌套对象」切成各自的表，
并做一次**覆盖度自检** —— `AI_DATA` 里每个叶子都必须落在某个数据集里，否则「有数据没进 CSV」会直接报错（避免静默丢数据）。

两条容易忽略的约定：

1. **类型化表头**：`110000` 这种行政区划代码在 CSV 里是 `id:text`，所以不会被自动变成数字、也不会和地图几何的字符串 id 对不上；
2. **空单元格 ≠ 空字符串**：非文本列留空表示「这一行没有这个字段」（`data.js` 里就不出现这个键），
   与 `false` / `0` 区分得清清楚楚（产业规模里「2025 年是预测」就是靠这个布尔列表达的）。

---

页面中的产业规模、算力规模、渗透率、效率增益、全球指数、省级算力与企业数量等均为**依据公开报告整理/估算的示意性数据**，
用于说明趋势与结构，**不作为投资或政策依据**；来源清单见页面第 13 节与 `data/sources.csv`（构建进 `data.js` 的 `sources` 字段，一行一条）。

省级地图的底图轮廓来自**阿里云 DataV.GeoAtlas**（经抽稀处理），只用于可视化演示、**不是审图号地图**，
不作为行政区划依据；南海诸岛以右下角插图的常规形式呈现。
`_map.mjs` 生成脚本与原始边界不在部署目录内，页面上没有任何运行时网络请求。
