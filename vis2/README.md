# 人工智能 · 新质生产力｜数据可视化

**第二次作业**：用一张**零构建**的长滚动数据看板，讲清「**人工智能是发展新质生产力的核心引擎**」这一主题。

- 纯 HTML + CSS + JavaScript（原生 ES Module 之外的普通 script），**无需 npm / 无需打包，双击 `index.html` 即可运行**；
- **中英双语**（右上角「中 / EN」）、**亮 / 暗主题**（右上角日/月图标，跟随系统并可手动切换）；
- **14 个章节**（00 阅读地图 → 13 关于）、**13 张自绘 SVG 图表** —— 雷达 / 折线 / 双组条形 / 气泡矩阵 / **热力矩阵** / **小倍数图** / 横向排名 / **省级分级填色地图** / 流向 / 力导向图谱 / 时间轴，外加 **1 台生产力模拟器**（含**龙卷风敏感性图**与**蒙特卡洛分布图**两张派生图）；
- 每张图都自带 **图表 ⇄ 数据表**切换与 **PNG / SVG / CSV 导出**（13 张图 × 3 种格式，导出的是同一份数据）；
- 除 `vendor/` 下 5 个 d3 子模块（共约 30 KB）外**没有任何运行时依赖**，不联网、不读 CDN；
  连省级地图的边界都是**构建期**抽稀好的静态几何（`map-china.js`，29 KB），运行时一次网络请求都不发。

> 配套自检：`node check.mjs` —— 零依赖静态体检（词表键对齐 / 挂载点 / 选择器 / 双语字段 / 脚本顺序），毫秒级返回。

## 📂 文件结构

```
vis2/
├── index.html          # 唯一页面：13 个章节的骨架（图表全部由 JS 注入）
├── tokens.css          # 设计令牌：颜色 / 间距 / 圆角 / 阴影 / 字号（亮暗两套）
├── styles.css          # 布局与组件样式（顶栏、首屏、卡片、图表容器、KPI、时间轴、页脚…）
├── theme.css           # 主题按钮样式
├── theme.js            # 主题切换器：在 <head> 提前执行，避免暗色闪白
├── i18n.css            # 语言相关的微调（中英排版差异）
├── i18n.js             # 中英词表 + 切换器（普通 script，file:// 下也能用）
├── data.js             # 全部数据与文案（每个字符串都是 { zh, en }）
├── map-china.js        # 中国省级边界（抽稀后的静态几何，由 D:/Vis/_map.mjs 生成，见下）
├── charts.js           # 14 个自绘 SVG 引擎（13 张图表 + 模拟器仪表盘，无第三方图表库）
├── app.js              # 渲染调度：把 data.js 画进 index.html，并接管交互
├── check.mjs           # 零依赖静态自检（node check.mjs）
├── favicon.svg
└── vendor/             # d3 的 5 个必要子模块，共约 30 KB（见下表）
```

> `map-china.js` 是**构建期产物**：原始省级边界（阿里云 DataV.GeoAtlas，约 570 KB / 1.9 万个点）
> 经「等距圆柱投影（按 35°N 做 cos 纬度校正）→ Douglas–Peucker 抽稀 → 量化」压到 29 KB，运行时直接读这份几何，
> 一次网络请求都不发。需要重新生成时在 `D:/Vis` 下执行 `node _map.mjs`（`--fetch` 会先联网下载原始边界）。
> 生成脚本自带两条自检：几何里出现 `NaN` 会直接失败；每个省最多保留 6 个环、小政区自适应容差（否则澳门会被抽没）。

### vendor 里的 5 个文件

| 文件 | 用途 | 是否需要 |
|---|---|---|
| `d3-dispatch.min.js` | 事件派发（d3-force 依赖） | 力导向图 |
| `d3-quadtree.min.js` | 四叉树（d3-force 防重叠） | 力导向图 |
| `d3-timer.min.js` | 帧循环（d3-force 依赖） | 力导向图 |
| `d3-force.min.js` | 力学仿真（速度 Verlet、多体、碰撞、alpha 衰减） | 力导向图 |
| `d3-selection.min.js` | 选择集（图谱连线/节点绑定） | 关系图谱 |

> **其余图表全部自己写**：坐标换算、轴与网格、渐变、气泡、流线、时间轴、模拟器都是手绘 SVG。
> 用 d3-force 而不是全手写，是因为力导向的物理调参代价高；而它**必须是本地文件**（CDN 断网 / `file://` 打开即失效）。

## 🛠 技术要点

- **零构建、零依赖运行**：没有 npm、没有打包器，`index.html` 直接引用相对路径的 `.js` / `.css`。
  脚本加载顺序：`d3-dispatch → d3-selection → d3-quadtree → d3-timer → d3-force → i18n → data → map-china → charts → app`。
- **数据与呈现分离**：`data.js` 只有数据与文案（全部 `{ zh, en }`），`charts.js` 只画图，`app.js` 只做「取数据 → 选容器 → 画图 → 挂交互」。
  文案改动不会碰图表代码，图表参数改动不会碰数据。
- **颜色一律从令牌取**：`charts.js` 通过 `getComputedStyle` 读 `tokens.css` 的 `--c-* / --d1..--d6`，
  并写成 SVG **表现属性**（而不是 CSS 类）—— 好处是①切主题时颜色自动跟随、②导出 / 截图不掉色。
- **主题切换 = 重画**：`themechange` 事件触发 `renderAll()`，图表按新令牌重绘；`theme.js` 在 `boot()` 之前就把 `data-theme` 写到 `<html>` 上，**首屏不闪白**。
- **语言切换 = 重画**：`i18n.js` 提供 `T(key)` 与 `setLang()`，`langchange` 事件同样触发 `renderAll()`。
  图表内的文字（轴标题、气泡名、图例）都由 `app.js` 用 `P({zh, en})` 传进去，因此英文模式下**不会残留中文**（`check.mjs` 与浏览器实测均为 0）。
- **一份数据、两种语言**：不维护 `zh/` 与 `en/` 两套页面，避免「改了中文忘了英文」；词表键由 `check.mjs` 断言对齐（当前 81 个键）。
- **四种新图型都是「一个数据源、两种看法」**（第二次作业新增）：
  - **分级填色地图**：五档分位数着色（不是线性分档，尾部看得清）；省级边界的几何键与 `data.js` 的行政区划代码**由 `check.mjs` 双向断言**，少一个省就会出现「有轮廓没颜色」，多一个键则永远画不出来；
  - **热力矩阵**：**列内归一化**（同一行里是渗透率 %、市场规模亿元、人才指数 /100，只有列内比较才有意义），格子里照实写原始数值，数据表与 CSV 导出也是原始值；
  - **小倍数图**：三格共用同一套纵轴刻度（这是小倍数图的全部意义），配色跨格一致、产业身份交给标题前的色点；宽屏三列、窄屏竖排，年份刻度只标在最下面一格；
  - **敏感性分析**：龙卷风图一次只把一个因素从 0 扫到 100（回答「先调哪个」），蒙特卡洛四个因素同时 ±15% 扰动抽 500 次（回答「有多不确定」）。随机数用**固定种子的 mulberry32** —— 换语言 / 换主题重绘时必须是同一批样本，否则图会莫名其妙地跳；滑块拖动时重算走 90ms 防抖。
- **无障碍**：跳转链接 `skip-link`、顶栏 `aria-expanded` 折叠、图表容器 `role="img"` + `aria-label`、
  导航当前项 `aria-current`、语言按钮 `aria-pressed`、尊重 `prefers-reduced-motion`（数字不再滚动、动画直接落到终态）。
- **响应式**：移动优先；顶栏在 ≤1160px 折叠成抽屉（13 个导航项在 1024px 时会超出，而 `.topnav` 隐藏了滚动条、用户不知道能横滑）；
  英文标签更长，`i18n.css` 里对 `html[lang="en"]` 的导航单独收过字号与内边距（否则宽屏也会差 40px）；
  卡片墙用 `auto-fit`；图表用 `viewBox`，但画布宽度跟随**容器实际宽度**（上限 = 设计宽度 900/960/700），
  所以字号在宽窄屏上都是 11~13px（1:1），不再出现「宽屏放大到 23px、手机压到 3.5px」。
  容器宽度变化 ≥24px 时 `app.js` 节流重画一次（动画会重播，属于预期）。

- **模拟器状态**：`STATE.sim` 独立于渲染存在，切换语言 / 主题后**旋钮位置与结果保持不变**（不会把用户调好的参数重置）。

> 收尾时再一次性部署 —— 完整说明见 [`DEPLOY-NETLIFY.md`](DEPLOY-NETLIFY.md) **§0.5**（含 Netlify 额度计费口径与"开发期间暂停构建"的做法）。

**Netlify（推荐，含"同仓库多站点"的完整指导书）：👉 [`DEPLOY-NETLIFY.md`](DEPLOY-NETLIFY.md)**

要点：本仓库同时托管 `vis/`（第一次作业）与 `vis2/`（第二次作业），
而 Netlify 一个站点只能有一个 Publish directory，**且 `netlify.toml` 会覆盖 UI 设置**，
所以根目录的 `netlify.toml` 里**故意不写 `publish`**，两个站点各自在 Netlify UI 里填：

| 站点 | Publish directory | Build command |
|---|---|---|
| 旧站点（vis） | `vis` | 留空 |
| 新站点（vis2） | `vis2` | 留空 |

日常更新：`git push origin main` → Netlify 自动重新部署（约 10 秒，无构建步骤）。

其他方式（**路径全部相对**，无需额外配置）：

- **预览（不部署）**：见上方「🧪 本地预览」—— 双击 `index.html` / 本地 HTTP 服务器 / GitHub Pages；
- GitHub Pages：仓库 `main` 分支根目录发布，访问 `https://ly-beyond.github.io/vis2/`；
- **应急手动部署**：Netlify Drop 拖拽 `vis2` 文件夹，或 `npx netlify-cli deploy --prod --dir=vis2`。

站点体积很小：**20 个文件 / 约 401 KB**（其中 `vendor/` 的 5 个 d3 脚本累计约 30 KB，
抽稀后的省级边界 `map-china.js` 29 KB，两份说明文档占 31 KB；其余为页面代码与数据）。
